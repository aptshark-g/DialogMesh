# DialogMesh v5：从检索系统到认知系统

## 状态：设计阶段（2026年7月）
## 作者：APTShark + Agent

---

## 1. 核心洞察

DialogMesh v4 成功构建了 SemanticObject、RelationSubstrate、CognitiveWorkspace 和 Runtime。但系统本质上是**被动的**——LLM 回答，然后等待。

v5 的升级是一个单一的架构转变：

```
被动 LLM  →  主动 LLM
预测      →  模拟
行为图    →  认知轨迹
状态      →  状态变迁
```

## 2. 架构：之前 vs 之后

### v4（当前）
```
对话
  ↓
行为图（外部：Q1→Q2→Q3）
  ↓
概念图
  ↓
知识
  ↓
反思
```

### v5（目标）
```
外部对话
  ↓
对话树（用户可见的历史）
  ↓
语义对象世界（存在什么）
  ↓
认知工作区（活跃的推理空间）
  ↓
内部模拟（LLM 站在用户的心智中反问自己）
  ↓
预测 / 问题生成
  ↓
反思（预测对了吗？）
  ↓
学习（改进模拟策略）
  ↓
知识更新（沉淀所学）
```

### 关键：模拟 替代 预测

| | v4 预测 | v5 模拟 |
|---|---|---|
| 方法 | 话题转移统计 | LLM 构造用户认知态，站在其中推理 |
| 冷启动 | 无用（无历史） | 立即可用（心智理论） |
| 输出 | "用户可能会问 X" | "我会问 X、Y、Z，置信度 0.82" |
| 学习 | 无 | 自监督：匹配→奖励，未匹配→惩罚 |
| 元学习 | 无 | 学习**哪种**模拟策略更有效 |

## 3. 模拟引擎设计

### 3.1 核心循环
```
第 N 轮：LLM 回答用户
    ↓
模拟引擎激活：
  1. 构建用户认知态（用户已知什么，缺口在哪里）
  2. LLM："如果我是这个用户，接下来我最可能问的 3 个问题是什么？"
  3. 生成问题 + 置信度分数
    ↓
第 N+1 轮：用户提出实际问题
    ↓
评估：
  BGE 语义相似度（预测 vs 实际）
  匹配 > 0.6 → 奖励（置信度增量 +0.09 到 +0.15）
  未匹配   → 惩罚（-0.05）
    ↓
策略学习：
  模拟策略权重 += 0.05（匹配）或 -= 0.02（未匹配）
  话题转移策略权重 同理调整
  缺口填补策略权重 同理调整
```

### 3.2 关键设计决策

**为什么用心智理论而不是统计？**
- 统计预测需要历史 → 冷启动失败
- 心智理论从第 1 轮即可工作："用户问了 Runtime。他们大概率不了解 Observation 或 Normalizer。如果我是他们，我会问这些是如何连接的。"

**为什么用 BGE 评估而不是精确匹配？**
- 用户可能用不同措辞问语义等价的问题
- BGE cosine > 0.6 算部分匹配 → 实现梯度学习

**为什么需要策略权重？**
- 不同场景需要不同的模拟方式
- 系统学习对于不同用户哪种方式最有效
- 这是元学习：学习**如何**模拟，而不是模拟**什么**

## 4. 认知轨迹（行为图 → 执行轨迹）

### 4.1 行为图的问题
行为图记录的是：`用户 Q1 → 助手 A1 → 用户 Q2 → 助手 A2`

这是**可见的表面**。它没有捕获：
- 进行了哪些观察
- 形成并拒绝了哪些假设
- 冲突发生在哪里
- 置信度如何演变

### 4.2 认知轨迹
记录**内部执行过程**：
```
Trace {
  视角: "architecture",
  活跃对象: [Runtime, Observation, Normalizer],
  注意力: {Runtime: 0.9, Observation: 0.7},
  检索对象: [EventIR, ConceptGraph],
  假设: [
    "用户需要理解 Runtime→Observation 流程",
    "用户可能对 Normalizer 角色感到困惑"
  ],
  拒绝假设: [],
  推理树: {
    根: "Runtime → Observation → Normalizer → Projector",
    分支: ["为什么需要 Normalizer？", "替代方案：直接解析"]
  },
  反思: {
    置信度增量: +0.12,
    知识提交: ["Normalizer 连接了 EventIR 和 SemanticObject"]
  }
}
```

### 4.3 为什么重要
- **重放**：可以重新运行相同的推理路径
- **半途重放**：可以从 Trace 的任意点重新推理
- **对比**：比较两条 Trace 看哪里发生了变化
- **元学习**：学习哪些推理模式有效

## 5. 关系图作为统一本体

### 5.1 问题
v4 有三套独立的关系系统：
- ConceptGraph 边（共现）
- RelationSubstrate 边（类型化）
- CausalChain 边（因果）

这是三套并行系统，语义不同。

### 5.2 统一关系模型
```
Relation
├── causal（导致）
├── contains（包含）
├── depends_on（依赖）
├── defines（定义）
├── implements（实现）
├── evolves_to（演化到）
├── contradicts（冲突）
├── analogous_to（类比）
└── uses（使用）
```

核心洞察：**因果只是关系的一种，具有方向性和约束性。**

### 5.3 这能实现什么
- SemanticObject 通过关系图连接（单一真相源）
- ReasoningTree 使用关系进行遍历
- CausalChain 是关系图中高置信度的子集
- 认知轨迹记录哪些关系被激活/创建

## 6. 四空间 → 统一认知运行时

### 6.1 当前（四空间）
| 空间 | 用途 | 状态 |
|------|------|------|
| 文档空间 | 原始文本摄入 | 稳定 |
| 概念空间 | 结构化概念（10477 个对象） | 稳定 |
| 知识空间 | 沉淀的知识（持久化） | 部分 |
| 认知空间 | 活跃工作区（瞬态） | 激活 |

### 6.2 目标：认知本体

回答四个问题：
1. **存在什么？** → SemanticObject
2. **它们如何关联？** → RelationGraph（因果是其中一种）
3. **推理时如何激活和演化？** → Workspace + Runtime + Trace
4. **什么被提交为长期知识？** → KnowledgeSpace

## 8. 与外部研究的关系

| 研究 | 共享概念 | DialogMesh 的不同 |
|------|---------|------------------|
| Reflexion | 事后反思 | 我们在用户提问**前**就模拟，不是在失败后 |
| Self-Refine | 生成→批判→修改 | 我们模拟用户，不是自我批评 |
| PreFlect | 执行前风险预测 | 我们模拟认知状态，不是执行风险 |
| Anthropic J-space | 模型内部表征 | 我们构建**围绕 LLM 的外部**认知运行时 |
| MIRROR | 智能体间互省 | 我们通过模拟实现人机共同反思 |
