# 发散→收敛推导压缩 — 元认知启发链

> 2026-07-23 · 修正: 规则归纳 = 过拟合, 正确路径 = 发散→筛选→启发链

---

## 一、为什么规则归纳是过拟合

```
历史数据 → 提取模式 → 规则集
  问题: 等价于 LSTM 窗口拟合——高度匹配训练数据, 零泛化
  如: "if causes_chain && confidence > 0.7 → intent=诊断"
       → 换一个场景: "延迟"由"配置错误"导致 → 规则不匹配
  
  本质: 从有限采样中归纳确定性规则 = 神经网络过拟合的本质
```

## 二、发散→收敛 启发链模型

### Step 1: 发散 (Diverge — LLM guesses without context)

```
输入: 原始推导链 (无上下文)
  "延迟飙升 → 监控缺失 → 告警未触发 → 故障定位失败"

LLM 无约束猜测 (temperature=0.8, no system prompt):
  → 猜测1: "用户可能在生产环境, 没有分布式追踪系统"
  → 猜测2: "可能是运维人手不足, 监控覆盖不完整"
  → 猜测3: "也许是历史遗留系统, 没有现代化可观测性"
  → 猜测4: "延迟可能是业务层而非基础设施问题"
  
关键: 无上下文 → LLM 不得不"猜" → 产生发散性假设
      这些猜测可能错误, 但包含了 LLM 的海量预训练知识
```

### Step 2: 收敛 (Converge — LLM filters with context)

```
输入: 原始推导链 + 发散猜测 + 对话上下文
  [原文]: "这个延迟是哪个模块导致的? 之前没加监控?"
  [推导链]: 延迟→监控缺失→告警→故障定位
  [猜测1-4]: ... (上一步输出)

LLM 受约束筛选 (temperature=0.1, with full context):
  → 验证猜测1: "分布式追踪" — 用户未提及, 驳回 (conf=0.2)
  → 验证猜测2: "监控覆盖" — 与"没加监控"对齐, 保留 (conf=0.85)
  → 验证猜测3: "遗留系统" — 无证据, 驳回
  → 验证猜测4: "业务层" — 提到了"模块", 部分相关 (conf=0.5)
  
输出: 筛选后的假设 + 拒绝理由
```

### Step 3: 启发链 (Heuristic Chain — the compressed artifact)

```
筛选结果 → LLM 生成启发链:

  "用户描述了一个级联故障: 模块延迟→缺少监控→无法定位。
   这与 '监控缺失导致故障链不可见' 的模式一致 (来源: 猜测2, 验证通过)。
   但需要注意: 用户明确提到'哪个模块', 说明延迟有具体边界, 不是全局性的。
   
   启发: 当故障描述包含 '哪个X + 缺少监控' 模式时,
   优先定位X的边界, 而非假设全局故障。
   反例: 若用户说'整个系统都慢了', 则不应限定边界。"

这个启发链:
  ✅ 有包容性: 覆盖了原始案例, 但不限于它
  ✅ 有泛化: 给出了'何时适用'和'反例'
  ✅ 保留了推导: 监控缺失→故障不可见→定位失败
  ✅ 可逆推: 打开启发链 → 可以还原原始推导逻辑
```

## 三、与神经网络的类比

```
神经网络:
  训练 = 在随机状态下发散 (梯度探索)
  推理 = 在约束下收敛 (forward pass)
  过拟合 = 发散不足, 只记住了训练样本

推导压缩:
  发散 = LLM 无上下文猜测 (创造性探索)
  收敛 = LLM 有上下文筛选 (证据约束推理)
  启发链 = 保留推导结构的压缩态
  过拟合 = 只做收敛(归纳规则), 不先发散(生成假设)
```

## 四、压缩质量度量

```
不是 "规则匹配率" (那是在验证过拟合)
而是 "启发覆盖率":

  启发覆盖率 = |新案例中启发链适用的比例|
  
  好的启发: 覆盖率 60-80% (不是100%——100%=过拟合)
  
  启发生命周期:
    → 覆盖率下降 → 触发重新发散 → 新启发链 → 替代旧启发
```

## 五、实现流程

```
每 N 轮对话 (N=5):
  1. 提取最近 N 轮的推导链 (L2实体边 + L2.5信念轨迹)
  2. 发散: LLM(temperature=0.8, no_context) → 生成 K 个猜测 (K=3-5)
  3. 收敛: LLM(temperature=0.1, full_context) → 筛选 + 排序
  4. 启发: LLM 生成启发链 (含: 模式描述 + 适用条件 + 反例 + 推理路径)
  5. 存入启发池, 替换低覆盖率旧启发
```

## 六、与现有组件集成

```
DerivationCompressor:
  输入: L2 edge_history + L2.5 trace + discourse_topics
  diverge(): LLM 无上下文 → K 个猜测
  converge(): LLM 有上下文 → 筛选 + 置信
  heuristic(): LLM → 启发链
  输出: HeuristicChain (入池) + metadata (coverage, freshness)

MetaCognitive:
  监测启发覆盖率
  覆盖率 < 阈值 → 触发重新压缩
  新旧启发冲突 → 元认知裁决
```

## 七、总结

| 维度 | 规则归纳 (旧) | 发散→收敛 (新) |
|------|-------------|---------------|
| 类比 | LSTM 窗口拟合 | 神经网络训练 |
| 发散 | 无 | LLM 无上下文猜测 |
| 收敛 | 从历史提取 | LLM 有上下文筛选 |
| 输出 | 确定性规则 | 启发链 (含反例+边界) |
| 泛化 | 过拟合 | 覆盖率 60-80% |
| 生命周期 | 静态 | 覆盖率下降→重新发散→替换 |
