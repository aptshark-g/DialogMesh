# LLM-3 v6 接入认知层（思考树 = 对内执行预测学习）— 拍板定案（2026-08-04）

> 定位: LLM-3（v6 是否接入认知层 / runtime+cli 零引用 cognitive_tree）正式定案。
> 核心命题（用户）: 思考树不是"思考记录"，是**对内执行预测学习**——
> 预测执行结果（如代码通过/失败）→ 执行 → 结果对照 → 差异学习 → 下次先做提高成功率的事。
> 类比: CPU 分支预测（预测表不消耗执行资源，换来流水线不空转）。

> 状态: ✅ 已拍板（2026-08-04）

## 一、核心命题（用户的认知模型）

```
LLM 真正耗时在工具使用，不在思考 → 预猜测的价值 = 让执行前就有预期

分支预测类比:
  分支预测器    → 预测表（便宜，不消耗执行资源）
  LLM 思考      → 真正的执行（贵）
  思考树        → 预测表 + 结果回写（学习）

对内学习循环（自监督，不需要用户信号）:
  预测执行结果（通过/失败/副作用）→ 执行 → 结果对照
  → 差异学习 → 下次先做提高成功率的事（先编译验证/先查依赖/先建索引）

与行为链的分工:
  行为链 = 对外学习（学用户习惯）
  思考树 = 对内学习（学自己的执行轨迹）
  两者同构: 预测 → 执行 → 差异 → 回写 → 下次更好
```

## 三、拍板内容（正式）

```
LLM-3: v6 接入认知层，思考树 = 对内执行预测学习

① 接入范围:
   runtime/engine + cli/engine 挂 cognitive_tree（v3_0 思考树为唯一实现）
   规划阶段（用户点名: "尤其是在规划的时候"）优先接入:
     执行前 → 思考树写入预测（预期结果 + 置信度）
     执行后 → 结果对照 → 差异回写 → 学习
   工具使用轨迹（长耗时部分）为预测主战场

② 对内学习闭环（预测-执行-对照-学习）:
   PERDICT  → 执行前预测（规则/历史/小模型优先，LLM 可选——A16 快慢）
   EXECUTE  → 真实执行（工具/代码）
   COMPARE  → 结果对照（预测 vs 实际，BGE/结构化）
   LEARN    → 差异回写思考树 + 策略权重更新（自监督，A6）
   → 失败多 → 自动学会执行前先做提高成功率的事

③ 输出吸收（用户点名）:
   工程链: 执行前检查项（先编译/先查依赖）来自预测学习
   元认知: 反思输入（为何预测失败）
   Skill: 高成功率执行序列 → 沉淀为 skill（与学习层联动）

④ 与 LLM-1/B1-8 联动:
   B1-8-P4: Workspace reasoning_tree/hypotheses → cognitive_tree 写入
   LLM-1:   6 LLM 思考记录 → compiler → cognitive_tree（共享树通信）
   LLM-3:   v6 主路径消费 cognitive_tree（本项）
   → 三者合并为"认知层完整接线"施工包

⑤ simulation_engine 扩展:
   从"用户问题预测"扩展为"系统执行结果预测"（新增预测域）
   保留用户预测能力（对外），新增执行预测（对内）
   同一自监督框架（权重更新机制复用）
```
