# DialogMesh UI 细节差距诊断 —— "结构对了,为什么还是不好看"

> 2026-08-15 · 基于 `screenshots/chat.png`、`sessions.png` 实拍,对标 Linear / Notion / Raycast / Things / YouMind
> 用户原话诊断:"模块之间的分离无设计直接就算切开的,没有审美感;滑动的栏显得不太好看"
> 结论先行:**骨架(三栏)和方向 4 是同构的,差距 100% 在表层处理(surface treatment)。**
> 另注:`kimi-design-skill` 在索引中但未实际安装,本诊断人工完成。

---

## 0. 一句话病因

我们把"分隔"当成**画线**,顶级产品把"分隔"当成**排布**。
现在整个窗口是用 1px 亮灰线把近黑底色切成网格——视觉上像老式 IDE 的分割条,不像被设计过的表面。

---

## 1. 分隔:三种手段的优先级被我们搞反了

顶级产品的分隔优先级:**色调阶梯 > 负空间 > 发丝线(最后手段)**。

| 手段 | 顶级做法 | 我们的现状 |
|---|---|---|
| 色调阶梯 | 背景/侧栏/卡片三级明度差(深色下如 #0B0D10 → #10141A → #161B22),无边界线也能分区 | 所有面板几乎同一个近黑色,只能靠线 |
| 负空间 | 栏间距 8–16px 留缝,线到 padding 处就停 | 分割线**通顶通底**,横竖交叉成网格 |
| 发丝线 | 1px、透明度 5–8%(深色下 ≈ rgba(255,255,255,.06)),只用于真正需要的地方(表头下、输入区上) | 线偏亮、处处都有:侧栏右缘、顶栏下缘、右栏左缘、卡片四周一圈 |

**具体证据**(chat.png):侧栏|顶栏|内容|右栏四条全长线交叉;右栏"认知画像"标题出现两次且上下各带一条线;卡片自身还有一圈描边——同一个 300px 宽的右栏里有 5 条竖线 + 3 条横线。

**处方**:
- 砍掉所有通长分割线,改为:背景三级明度阶梯 + 栏间 12px 缝隙
- 必须保留的线(输入框上缘、表头下缘)降到 6% 透明度,且两端缩进 16px 不到边
- 卡片去描边,用比背景亮一级的底色区分(深色 UI 的"卡片"应该是"更亮",不是"有框")

## 2. 色彩:琥珀橙一个颜色干了六份活

现在琥珀橙同时是:品牌色、导航激活态、主按钮、数字强调、状态色(成功进度条)、FAB、发送键。
**一个色相承担 6 个职责 = 没有职责**。满屏橙色让界面处于"持续提醒"状态,看久了燥。

顶级做法(Linear/Raycast 都是深色,证明深色没问题):
- 强调色只出现在两处:**主行动按钮 + 当前位置指示**
- 数字用前景色(白/近黑)+ tabular-nums,不用彩色
- 状态用语义色且降饱和(成功绿/警告黄/危险红,明度压低)
- 其余全部是中性灰阶梯

**处方**:琥珀橙可以留(品牌资产),但职责砍到 2 个:主按钮 + 导航激活点(小圆点或 4px 左侧条,不是整片药丸)。"63/52/50"这种大数字改回前景色,语义交给小字标签。

## 3. 滑动的栏:滚动条与侧栏两个问题

**滚动条**:目前应为系统默认/未深度定制——深色界面里灰白滚动条非常扎眼。
处方(全平台一致做法):
- 宽 4–6px,全圆角,轨道透明,滑块 rgba(255,255,255,.14)
- 默认隐藏,hover/滚动时 150ms 淡入,停止滚动 1s 后淡出(overlay 式,不占布局宽度)
- 实现:`::-webkit-scrollbar` + `scrollbar-width: thin`,Vite preview 下 Chrome 表现即可达标

**侧栏**("滑动的栏"如果指它):12 个导航项等距平铺 + 底部还挤着"悬浮/嵌入/Backend Online/收起"四块 chrome。
处方:
- **分组**:主导航(总览/聊天/会话) | 洞察(图谱/画像/元认知/行为) | 工程(工程/网关/管道/深层链) | 系统(设置),组间 16px 间距 + 10px 灰色大写组标
- 激活态:8px 圆角浅色底(亮 8% 的 tonal fill),左侧 3px 橙色小条,**不是整片橙药丸**
- 图标统一 16px、1.5px 描边粗细(现在粗细不一)
- "悬浮/嵌入"是窗口模式开关,收进标题栏右侧或设置页,不该常驻侧栏底部;"Backend Online"缩成 6px 状态点 + hover tooltip

## 4. 顶栏:搜索框霸占了不属于它的位置

现在顶栏 = 重复的产品名下拉 + 居中大搜索框 + 右侧图标群。搜索不是每页的主任务,却占了视觉 C 位。
处方:
- 顶栏压到 48–52px,左侧放**当前位置**(面包屑/页面标题),右侧放**本页上下文的动作**
- 全局搜索收进 ⌘K 命令面板(Linear/Notion/Raycast 全部如此),顶栏最多留一个小的"搜索或命令…"触发器
- 去掉与左上角 logo 重复的产品名下拉

## 5. 右栏:常驻 + 标题重复 + 字段陈列

- "认知画像"标题上下出现两次(dock 标题 + section 标题)——去掉一层
- 聊天页和会话页右栏**内容完全一样**——它应该是上下文感知的:聊天页=当前会话画像,会话页=选中 session 摘要,图谱页=选中节点详情
- "C / O / NC"密码式缩写 + 巨大橙数字:改成中文标签 + 常规字号数字,或干脆翻译成一句洞察(画像页重做时一并解决)

## 6. 圆角 / 字阶 / 间距:没有系统,各自为政

| Token | 现状 | 处方 |
|---|---|---|
| 圆角 | 4/8/10/12/16/全圆 混用 | 只留两档:卡片/面板 8px,按钮/输入框/pill 全圆角 |
| 字阶 | 12/13/14/16/20/28+ 自由发挥 | 五级:11(辅助)/13(正文)/15(强调正文)/20(页标题)/28(大数字,tabular-nums) |
| 间距 | 全局 12–16px 均匀抹平 | 4px 网格;组内 8–12,组间 24–32——**用间距表达亲疏**,现在所有东西等距所以看不出分组 |
| 层级 | 靠彩色制造 | 靠字重 + 灰度:主文字 100%,次级 60%,辅助 40% |

## 7. 内容的人性化(最便宜的质感提升)

sessions.png 里会话列表显示 `b84e1b45-4f5` + `0.0 KB`——这是数据库行,不是界面。
顶级做法:人类可读标题(首条消息摘要)+ 相对时间(3 小时前)+ 一行预览。同样的数据,零成本,质感天差地别。

## 8. 小东西清单

- FAB(右下橙色聊天钮)在聊天页自己也显示,冗余且压内容——只有非聊天页需要,或干脆去掉
- 空态"开始对话":橙菱形图标 + 两行字,可以加一句引导示例(可点击的示例问题)
- "成功状态 82% / 风险状态 18%" 进度条配大红大橙,像告警面板;降饱和,加一句人话结论

---

## 9. 改动的量级与顺序(全是"表层",不动结构)

| 优先级 | 项 | 性质 |
|---|---|---|
| P0 | 分隔重做(色调阶梯 + 砍通长线) | 纯 CSS/token |
| P0 | 滚动条 overlay 化 | 纯 CSS |
| P0 | 右栏标题去重 + 上下文化(每页不同内容) | 小组件改动 |
| P1 | 琥珀橙职责砍到 2 个 | token + 少量组件 |
| P1 | 侧栏分组 + 激活态改 tonal | 侧栏组件 |
| P1 | 顶栏瘦身 + ⌘K 搜索 | 顶栏组件 + 新命令面板 |
| P2 | 圆角/字阶/间距 token 收敛 | token |
| P2 | 会话列表人性化 | 数据映射 |
| P3 | FAB 去留、空态引导 | 小组件 |

**关键判断:以上全部不需要动信息架构,也不需要换深浅主题。** 深色一样可以顶级(Linear/Raycast 即证);方向 4(浅色纸张)是审美偏好选择,细节规则在两种主题下通用。
