# 任务页: 完成度/执行轨迹视图（大工程, 2026-08-17 立项）

> 状态: 需求记录 + 方向设计（未开工）
> 触发: 用户「任务页不错但太匮乏——能画简单画布, 但任务完成情况看不了」

## 一、现状

- `TaskPlanningPage.tsx` + `FlowchartCanvas`: 只做**静态规划画布**
  （节点 + 依赖边, 后端 `/v6/task-graph` 存取版本化快照）。
- 节点 `status`/`progress` 字段已存在（canvas 序列化里写死 `pending`/`0`）,
  但没有执行侧写入, 也没有完成度视图。
- 执行层（executor / ExecutionTree）已落树（2026-08-15 P0 接线）:
  create_task → 每步 spawn → complete_node, 行为链/元认知可消费——
  但**前端没有消费 ExecutionTree 的视图**。

## 二、目标（用户原话要点）

1. 任务**完成情况**能看: 总进度、每节点状态（pending/running/done/failed/skipped）、
   失败原因、耗时。
2. 与执行轨迹（ExecutionTree）打通: 规划画布 ↔ 真实执行结果双向对照
   （规划是"预期", 执行是"实际", 差异即诊断信号）。
3. 后续可量化: Agent 任务成功率 / 平均步数 / 平均耗时 / 失败分布
   （对齐 README 宣称的"任务成功率"指标, 评测不能只测召回）。

## 三、方向设计（草案）

- **数据源**: 新增只读端点聚合执行轨迹（如 `/v6/tasks` + `/v6/tasks/{id}/runs`）,
  由 ExecutionTree 落盘反推（不要前端拼凑）。
- **画布增强**: 节点状态着色 + 点击节点看该步执行明细（工具调用/输入输出/耗时/错误）;
  失败节点支持一键"诊断"（复用 AsyncDiagnoser / probe）。
- **列表视图**: 画布之外加任务列表（名称/状态/进度/时间/所属项目）, 支持按项目过滤。
- **回放**: 淘宝 PES 式"全链路可回放"——每步独立记录已有基础, 前端做时间轴回放。

## 四、调研待办（用户: 去 GitHub 找类似方案）

- 任务画布/执行视图: 主流思路 = DAG 可视化 + 执行状态叠加。
  候选参考: `flyte` / `prefect` UI（任务 DAG + 运行状态）; `dify`/`coze` 工作流画布;
  `n8n`（节点执行状态/重试/日志）; `flowise`; `langgraph studio`。
- 关注点: 画布渲染性能（大图虚拟化）、状态实时推送（SSE/WS）、
  失败诊断入口、与 LLM 任务（规划→执行→审查）的语义对齐。

## 五、落地节奏

- P0: ExecutionTree → 只读聚合端点 + 任务列表 + 画布状态着色（一轮内可做）。
- P1: 节点明细抽屉 + 失败诊断入口 + 按项目过滤。
- P2: 时间轴回放 + 任务成功率等量化统计。
