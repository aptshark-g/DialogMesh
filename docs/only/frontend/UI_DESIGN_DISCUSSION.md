# DialogMesh GUI — 美术风格与 UI 设计讨论稿

> 版本: v1 | 日期: 2026-08-11 | 状态: 讨论中(未定稿,不改代码)
> 素材: `screenshots/` 目录下 14 张全页面实拍截图(2026-08-11,1440×900 + 1 张移动端)
> 前置阅读: `../GUI_API.md` (v10)

---

## 0. 一句话结论

当前 UI 的问题不是"丑",而是**没有产品视角**:它是 82 个后端端点的逐点陈列室,把系统内部架构(管道、底物、子图、元认知)直接当成了用户界面。美术风格只是表象,信息架构(IA)才是病根。建议先定"产品定位",再定"美术方向",最后谈"设计系统"。

## 1. 现状诊断(基于实拍截图)

### 1.1 视觉层 —— "能看的模板,没有气质"

现状是通用的深紫黑(`#0C0A0F`)+ 琥珀橙(`#D97706`)暗色方案,方向本身没问题(Linear/Vercel/Raycast 都是暗色系),但执行粗糙:

| 问题 | 证据 | 影响 |
|---|---|---|
| 主色滥用、无色彩层级 | 主按钮、激活 tab、图标底、徽章、进度条、数字高亮全是橙;同时橙色又兼任 `status.warning`(见 `gateway.png` 健康点 vs 警告条) | 橙色失去"引导视线"的作用,且语义冲突(品牌色=警告色) |
| 紫底 + 橙点显"脏" | `dashboard.png` 大面积紫黑卡片上的橙色图标底 | 暗色系的高级感来自克制的对比度,现在对比关系混乱 |
| 信息密度极低 | `meta.png` 5 张 0 值大卡片占满首屏;`tasks.png` 近乎全空 | 工程控制台定位 vs 营销页式的低密度,自相矛盾 |
| 字体层级弱 | 页面标题/卡标题/正文几乎同字号,数字一律大号橙色 | 视线没有落点,重要与次要信息平级 |
| 无品牌记忆点 | 圆角卡 + 细边框是任何一个 Tailwind 模板的默认长相 | 做完之后用户记不住这是 DialogMesh |

### 1.2 布局层 —— 三栏都在,但栏栏有问题

- **右侧面板(常驻)**:所有页面挂同一个"认知画像"面板,而且标题重复出现两次(联动条 + 面板头,见任意截图右上)。它占 ~22% 屏宽,内容却是固定的 63/52/50 + 成功/风险两条——**与当前页面零关联**。在网关页填 Key 时它是噪声,在图谱页它是占位。
- **顶栏**:搜索框无实际功能(搜什么?)、右上三个图标语义不明。
- **Sidebar**:13 个导航项**平铺无分组**。更要命的是命名直接把内部架构名词抛给用户:「管道」「深层链」「元认知」是系统实现概念,不是用户任务语言。用户的心智是"我要聊天/看系统懂了什么/调配置",不是"我要看 pipeline 层级统计"。

### 1.3 功能展现层 —— "奇怪"的具体证据(逐页)

| 页面 | 截图 | 问题 |
|---|---|---|
| 总览 | `dashboard.png` | 主体三张空态大卡("暂无数据"),右栏却显示 63/52/50 的"有数据"——空态与数据态自相矛盾 |
| 聊天 | `chat.png` | 空态尚可,但模型选择器孤零零悬在顶部;FAB 聊天按钮与聊天页功能重复(所有页面常驻) |
| 图谱 | `graph.png` | 意图过滤器 chips 是「扫描记忆/读取记忆/写入记忆/修改值」——**这是 MemoryGraph 逆向工程的遗留词汇!** 对话记忆产品里出现"扫描内存"意图完全违和(色板 `intent.scan-memory` 等源自 legacy) |
| 画像 | `profile.png` | 全站信息组织最好的一页,但 8 张"0 分"指标卡把雷达图淹没了 |
| 任务 | `tasks.png` | **最灾难的一页**:一个巨大空画布 + 一个 "+",没有引导、没有示例、没有说明,用户进来完全不知道能做什么 |
| 网关 | `gateway.png` | 功能最完整,但 4 个 tab(Provider/用量/配置/运维)+ 9 个 Provider 卡片列表,配置任务和监控任务混在一页 |
| 管道 | `pipeline.png` | **把后端 JSON 原样键值陈列**(`running: true`、`confidence: 0.5`、`chain_results: {}`)——这是调试面板,不是产品界面 |
| 深层链 | `deepchain.png` | 裸 JSON 树/键值卡,`patterns: 5条` 这类原始计数对用户无意义 |
| 工程 | `engineering.png` | 42 个模块表格全是 "已加载" 绿灯——状态列没有信息量 |
| 会话 | `sessions.png` | 142 个会话全是 `b84e1b45-4f5` 哈希名 + `0.0 KB`,**没有标题/时间/摘要** —— 不可浏览即不可用 |
| 元认知/行为 | `meta.png` `behavior.png` | 结构正确的骨架,但首屏被 0 值统计卡占满,真正的内容(审核队列、模式列表)在下方 |
| 设置 | `settings.png` | **数据持久化卡片直接渲染出 `[object Object]`**——bug 级的呈现事故 |

### 1.4 病根总结

> 现在的 UI = 后端 API 的逐端点陈列。每个端点一个页面,每个字段一个卡片。
> 这是 developer-console 思维;而 DialogMesh 的卖点(白盒认知可视化)需要**产品化转译**:把内部状态翻译成用户能行动的洞察。

## 2. 第一个要讨论的问题:产品定位

美术风格取决于定位。三条路,气质完全不同:

### 选项 A — 认知开发者控制台(White-box Cognitive Console)
- **类比**:LangSmith、Weights & Biases、Grafana、Datadog × Linear 的视觉完成度
- **用户**:开发者/研究者(你自己、合作者、未来的开源用户)
- **IA**:观测优先,会话/图/管道/元认知都是平级"数据源视图"
- **视觉**:高密度、等宽字体、精确对齐、克制的状态色
- **优势**:与 82 个端点的现状最近,改造成本最低

### 选项 B — 对话优先,认知作为差异化层(Chat-first + X-ray)
- **类比**:ChatGPT/Claude 的对话界面 + 一个可展开的"X 光片"侧层
- **用户**:把 DialogMesh 当 AI 助手用的人,白盒是"哇塞时刻"(demo 利器)
- **IA**:L0 对话(主表面)→ L1 洞察(画像/行为/元认知,"系统懂了我什么")→ L2 控制台(管道/工程/网关,收进开发者模式)
- **视觉**:对话区呼吸感 + 洞察区数据感,两种节奏
- **优势**:叙事最完整——"别的 AI 黑盒,我的能给你看它在想什么"

### 选项 C — 认知地图实验室(Node-graph Lab)
- **类比**:Obsidian Graph View、Blender/虚幻的节点编辑器、Figma 画布
- **IA**:图谱是唯一主角,其余全是图的筛选/下钻面板
- **优势**:最有"颠覆性产品"相;风险是可用性和实现成本最高

**我的倾向:B 为体,A 为用。** 即产品形态走 B(对话是主表面,观测是分层揭示),视觉语言走 A 的完成度标准(Linear 级的细节)。C 的节点美学可以局部借用到图谱页。
理由:你的论文叙事和 README 都是"对话记忆引擎",B 的对话主表面与之匹配;而 82 个端点的工程深度需要一个不打折的控制台,A 的密度规范正好用在 L2。

**→ 待你拍板:定位选 A / B / C,还是其他?**

## 3. 美术风格方向(三个提案,待选一个深化)

> 三个方向都是"暗色优先",但气质完全不同。截图均为现状,下表是走向。

### 方向 1:「精密仪器」— Precision Instrument
- **一句话**:像一台校准过的测量仪器——数据可信、操作精确
- **色板**:近黑的石墨底(`#0E1116` 系,去紫),单一强调色改为**电青/钛蓝**(`#5EEAD4` 或 `#7DD3FC`),橙色仅留警告;状态色严格语义化
- **字体**:Inter/JetBrains Mono 为主,数字统一 tabular-nums,指标用等宽大字
- **材质**:1px 发丝边框、无阴影或极浅阴影、微圆角(6px)、细微网格/刻度纹理
- **参考**:Linear、Vercel Dashboard、Raycast
- **适合**:定位 A/B;改动小,风险最低

### 方向 2:「暗夜实验室」— Cognitive Lab
- **一句话**:深夜实验室里的认知显微镜,有一点"科幻仪器"的戏剧性
- **色板**:深墨蓝黑 + **荧光生物色**(cyan/品红/荧光绿)用于图节点温度、信号流;琥珀仅用于"人类标注/用户行为"
- **材质**:发光边缘(克制的外发光)、玻璃拟态面板、信号流动画、图谱页全屏画布
- **参考**:Obsidian 图谱、虚幻引擎节点编辑器、《钢铁侠》JARVIS 的克制版
- **适合**:定位 B/C;品牌辨识度最高,但动效和性能成本大,做砸了就变"杀马特监控大屏"

### 方向 3:「纸面工程图」— Blueprint / Technical Drawing
- **一句话**:工程蓝图 + 钢笔标注——白盒概念的视觉直译(内部结构被"画出来")
- **色板**:深蓝图纸底(`#1B2A4A` 系)+ 白色/浅蓝线稿 + 红色批注色;或反向的米色纸面亮色模式
- **字体**:标题衬线/手写标注体点缀 + 正文无衬线
- **材质**:细网格底纹、虚线引线、角标刻度、蓝图式图框
- **参考**:建筑蓝图、Notion 技术博客插画、Tldraw 美学
- **适合**:差异化最强、与"白盒/可编辑"理念最契合;但读屏舒适度需要精细调校,工程图表类页面(Graph/工程链)收益最大

**我的倾向:方向 1 打底 + 方向 3 的图纸语言注入图谱/工程类页面。** 方向 2 发光美学风险收益比最差,除非你非常想要"科幻感"。
**→ 待你拍板:1 / 2 / 3,或组合?**

## 4. 信息架构重构提案(与美术方向正交)

无论选哪个方向,IA 都建议重构——这是"功能展现奇怪"的直接解药:

### 4.1 导航:13 项平铺 → 3 层收敛

```
L0 对话(默认着陆)          L1 洞察                L2 控制台(开发者)
├─ 聊天 / 会话列表         ├─ 认知画像            ├─ 管道与调度
└─ 图谱(对话的可视化)     ├─ 行为发现            ├─ 工程链
                          ├─ 元认知中心          ├─ 网关 & Provider
                          └─ 会话档案            ├─ 参数与规则
                                                └─ 系统设置
```
- L2 整组收进"开发者模式"开关(默认隐藏或折叠为一项「控制台」)
- 移动端底部导航只保留 L0 + 画像
- 「任务」页当前无真实功能(原 mock + 空画布),**建议下线或重做**为"规划任务可视化"(接 /v6/perspectives 与 planning),否则是第一个该砍的导航项

### 4.2 右侧常驻面板:按需出现
- 撤掉全站常驻的"认知画像"右栏(或改为**上下文感知**:聊天页显示当前会话画像,图谱页显示选中节点详情,网关页不显示)
- 修正"认知画像"标题重复渲染的 bug

### 4.3 数据翻译原则(每个页面自检清单)
1. 这页的**用户问题**是什么?("系统现在健康吗" 而不是 "stats 接口返回什么")
2. 首屏第一屏必须回答它;0 值/空态必须给引导(学习的例子:`chat.png` 的空态是全站最好的)
3. 原始 JSON/内部字段名(chain_results、edge_count、`[object Object]`)永远不出现在界面上——设置页的 `[object Object]` 属于必须修的呈现 bug
4. 状态列必须有信息含量(42 个"已加载"绿灯 = 没有状态)

### 4.4 文案与词汇清理
- 清除 MemoryGraph legacy 词汇:意图分类「扫描记忆/读取记忆/写入记忆/修改值」→ 对话域词汇(提问/请求代码/解释/闲聊...)
- 统一术语表(中英):Subgraph=编译子图 vs 子图缓存;Discourse Tree=对话树;Meta=元认知……全站一张表,GUI 文案与文档对齐

## 5. 设计系统落地清单(定方向后的施工图)

1. **Design Tokens 收敛**:品牌色与警告色分离;补全字阶(11/12/13/14/16/20/28 七级足够)、间距 4px 网格、圆角(现在 4/8/12/16 混用无规则)
2. **组件清单重制**:Button(4 变体)、Card(密度 3 档)、Badge、Tab、Drawer、Modal、Toast、EmptyState(现在每页各写各的)、MetricTile(统一数字格式 tabular-nums)
3. **页面模板**:列表页 / 详情页 / 画布页 / 表单页 四种模板,页面不再自由发挥
4. **空态规范**:图标 + 一句话 + 一个行动按钮(取代"暂无数据"四个字)
5. **动效规范**:只在状态变化处动(framer-motion 已有),禁止常驻动画;150–300ms 两档
6. **暗色/亮色**:tokens 已预留双套,但亮色从未验收过——定方向后同步验收
7. **验收标准**:以 Linear/Vercel 截图级细节为 bar(对齐、留白、hover 态、焦点环)

## 8. 参考产品拆解: YouMind(2026-08-11 追加,用户点名)

> 用户反馈:方向 1/2/3 概念稿"还不如现在的,太丑了",点名 YouMind 的设计"还不错"。
> 参考截图存 `uiTest/ym_*.png`(官网本机网络不可达,截图取自公开测评文章)。

### 8.1 YouMind 是什么

玉伯(语雀创始人)创业的 AI Creation Studio,核心是 IPO 三栏:**资料(Input)/ 作品(Output)/ 对话(Process)**。语雀血统 = 内容优先、克制、温暖。

### 8.2 视觉语言提取(从截图实测)

| 维度 | YouMind 做法 |
|---|---|
| 底色 | 暖白纸张感(≈#FAFAF8),卡片纯白,靠 1px 发丝边框分区而非深色块 |
| 主按钮 | 纯黑 pill(全圆角),全站几乎唯一重色块 |
| 强调色 | 极少,只出现在小图标/标签上;大面积保持中性 |
| 圆角 | 卡片 8–12px,按钮/输入框全圆角 |
| 阴影 | 极轻弥散阴影,只用于浮层和卡片悬浮 |
| 图标 | 线性小图标 + emoji 点缀(项目列表用 emoji 当头像,亲切感来源) |
| 留白 | 奢侈。卡片内边距大,栏间距大,字行高松 |
| 温度 | 手绘插画(Pro 弹窗)、emoji、口语化文案——"工具"感被刻意藏起 |

### 8.3 为什么我的方向 1/2/3 全错了

三个概念稿都默认了"深色开发工具"审美(Linear/Vercel/科幻实验室/蓝图)。但 DialogMesh 的内核是**认知、记忆、写作**——和 YouMind/Notion/语雀同属"内容工具"血脉。用户对"好看"的校准样例是**浅色、纸张感、内容优先**,不是精密仪器。这是我方向判断的失误,记录备查。

### 8.4 方向 4 · 纸上工作室(Paper Studio)

概念稿:`uiTest/direction4_paper_studio.png`(提示词已入 `uiTest/prompts.md`)。

- 暖白底 + 黑发丝文字 + 黑色 pill 主按钮 + 一个克制的强调色
- 三栏映射:左导航(图标+中文)/ 中对话流(几乎无边框,排版驱动)/ 右上下文卡片(相关记忆片段 + 迷你图谱)
- 与 DialogMesh 现有页面的映射:
  - 聊天/会话/总览 → 完全适用,浅色纸张感直接提升
  - 画像/行为/元认知 → 白底卡片 + 图表,比现在深色底好做得多
  - 图谱/瀑布/工程链(画布页)→ 白底画布(类 Obsidian 白板),节点用浅色描边卡片
  - 管道/工程/网关(硬核页)→ 保持浅色但提升密度(等宽数字、紧凑表格),或作为唯一例外保留深色"机房"模式——**待决**

### 8.5 修订后的推荐

**方向 4(纸上工作室)为全局主基调**,取代原"1 打底 + 3 局部"。
- 图纸语言(方向 3)降级为可选彩蛋:仅工程链/瀑布页可用细网格纹理致敬,不再作为独立方向
- 深色模式: tokens 已有双套,纸上工作室反相即可,但优先级排到最后
- 最大挑战不是美术而是**密度管理**:82 个端点的信息量在 YouMind 式留白里放不下,答案只能是渐进披露(默认隐藏工程细节,按需展开),不是缩小留白
