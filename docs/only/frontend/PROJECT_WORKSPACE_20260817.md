# 项目=工作区: 文件夹/子对话/分支管理（2026-08-17 方向设计）

> 状态: 方向已定, P0（文件夹关联）已实现, 子对话/分支为待办
> 触发: 用户「项目创建后应选择文件夹; 项目下对应子对话; 学 codex 的分支/git 管理」

## 一、已实现（本轮 P0）

- 项目模型加 `path`（工作区文件夹）: 后端 `projects_api.py`
  （create/patch 支持 path + create_dir; `GET /v6/projects/browse` 只读目录浏览,
  默认根 `data/projects`, 仅列直接子目录, 不创建不删除——A21 权限只减不增）。
- 前端: 侧栏创建项目后弹「选择工作区文件夹」（新建/已有）;
  projectStore 加 `setProjectPath`; 会话归入沿用 B15/B1/B16。

## 二、用户方向（记录）

1. **创建项目 → 选文件夹**: 新建（自动建 `data/projects/{slug}`）或已有
   （浏览选择/手动路径）。✅ P0 已实现。
2. **项目 = 子对话容器**（对齐 codex/claude-code）: 一个项目下是其专属的
   一组子会话, 而不是"全局会话 + 标签过滤"。即项目页打开 = 该项目的对话树,
   新建会话默认挂该项目（B16 已有 project_id 携带, 前端缺项目内会话入口）。
3. **历史数据插入/经验总结**: 通过"会话归入", 可选择把过去的数据插入该项目,
   或交给元认知以项目为单位总结经验（项目范围的经验 RAG / 凝练）。
4. **分支 + git 式管理**: 会话可 fork（分支）, 项目内会话/图/规则可回滚到
   历史版本, 类似 codex 的 checkpoint 与 git 分支; 蓝图（blueprint）作为
   "分支策略"复用的载体。

## 三、设计要点（草案）

- 工作区目录的语义: `data/projects/{slug}/` 存该项目专属的
  会话快照/图导出/规则/经验（不是把全局 data 拆散, 而是"导出 + 引用"）。
- 会话树: 会话已有 discourse_tree/对话树概念, "项目内子会话" =
  以项目为根的对话树第二层; fork = 树的复制分支（复用任务图版本机制）。
- 权限: 浏览/选择文件夹只读; 新建目录仅限 `data/projects/` 根下
  （手动路径仅记录引用, 不越权创建外部目录）。
