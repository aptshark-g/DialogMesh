## 一、背景与触发

前端深审发现: Layout 右侧是**硬编码的 RightPanel（认知画像）**，虽可收展
（uiStore.sidePanel: isOpen/width=340/title）但:
1. 宽度不可拖拽调整
2. 内容不可更换（Layout 写死 `<RightPanel/>`）
3. 常驻画像在多数页面（工程/任务/管道等）无上下文价值 → 浪费屏幕

用户提出: 右侧做成**可调整大小 + 可放其他页面内容**的三屏结构（左导航 + 中主
内容 + 右上下文坞，参考 youmind 产品）。

---

## 二、讨论过程与要点

### 2.1 用户关键补充（第二次讨论）

> "直接在左侧页面加入选择，是在中间呈现还是右边？对话+上下文、对话+工程链、
> 对话+任务规划这种联动应该很不错。"

→ 用户实际要的是: **右侧内容跟随主页面联动 + 用户可选**，而非固定三栏。

### 2.2 拆解（两件事）

```
1. 联动（自动）: 主页面决定右侧默认内容
   对话页 → 默认上下文/画像 | 工程页 → 默认工程链/约束 | 任务页 → 默认执行面板
2. 可选（白盒）: 右侧是内容坞（Dock），用户可切换内容
   = 右栏内容选择器（放侧栏/工具栏/右栏头部均可）
```

### 2.3 为什么"左侧/页面级选择"合理

- 左侧导航全局常驻，"右栏联动模式"（跟随页面/固定某内容/全白手选）描述的是
  工作区结构，不是某页面的内容 → 放侧栏是自然位置。
- 用户举的三例 = 右栏内容的三种典型（上下文/工程链/任务规划），都是
  "主对话 + 领域侧栏"配对。

## 三、设计方向（讨论达成）

### 3.1 uiStore 扩展
```
sidePanel: {
  isOpen, title, width（默认 340，可拖拽 280–560）,
  mode: 'auto' | 'fixed',        // 联动模式
  dockContent: 'profile'|'context'|'engineering'|'tasks'|'legend'|'thinking'|...
}
```

### 3.2 RightDock 组件（取代硬编码 RightPanel）
```
按 mode 决定内容:
  auto  = 按当前路由映射（对话→上下文/画像、工程→工程链、任务→任务面板…）
  fixed = 用户指定 dockContent
```

### 3.3 交互
- 右栏头部: dock 内容切换（tab 式，like youmind）
- 侧栏: "联动模式"开关（auto/fixed）
- 宽度: 拖拽 handle（onPointerDown + move/up），clamp 280–560，持久化

### 3.4 候选右栏内容（待拍板清单）
```
画像 profile        （现状 RightPanel: 雷达图+指标+进度）
上下文 context      （对话的上下文/子图视图）
工程链 engineering  （约束/检查项/工程链状态）
任务 tasks          （执行面板/任务规划）
图例 legend         （图谱页节点/边图例 + 选中节点详情）
思考流 thinking     （LLM 思考过程流）
```

## 四、与设计哲学对齐

```
A19 白盒:   系统给默认联动（auto），用户可覆盖（fixed）→ 工作区结构白盒化
A16 快反馈: 默认窄坞（280）+ 按需展开，不占主任务空间
行为链学习: "用户选择 dock 内容/拖拽宽度" 是行为事件 → 可被行为链学习
            （与 B5-3 用户编辑行为回流同通道）
上下文工程: 右栏 = 上下文/子图在前端的投影（主任务 + 辅助上下文同屏）
```
