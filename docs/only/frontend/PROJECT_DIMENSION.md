# 缺失的维度:项目(Project)— DialogMesh 的中间层

> 2026-08-15 · 用户观察:"现在的前端更多是系统和用户之间的,而缺失了项目的"
> 后端事实核查(2026-08-15,grep GUI_API.md v10):**无任何组织容器** —— 无 project / workspace / tags / group / label 字段。最接近的只有 `GET /v6/mind/full`(心智空间),与项目无关。

---

## 1. 问题确认:现在的 IA 只有两层,缺了中间层

| 层 | 内容 | 现状 |
|---|---|---|
| 系统层 | 引擎、网关、管道、深层链、设置 | ✅ 有,而且占了导航一半 |
| **项目层** | **用户的工作组织:毕设 / 论文投稿 / memorygraph / …** | ❌ **完全没有** |
| 对话层 | 聊天、会话 | ✅ 有,但是一锅烩(142 个会话平铺,无前缀无分组) |

结果就是:用户在"毕设"和"memorygraph"之间切换时,UI 没有任何东西跟着变——会话列表、图谱、记忆、任务全是全局混在一起的。**用户的心智模型是"我在做某个项目",UI 的心智模型是"系统在跑一些会话",两者对不上。**

## 2. 业界对照

- **YouMind**:项目即知识库容器,侧边栏第一级就是项目列表(实拍 ym_project.png)
- **ChatGPT Projects**:项目 = 一组对话 + 文件 + 专属指令 + 独立记忆
- **Cursor/VS Code**:项目 = 打开的文件夹,一切操作的隐含范围
- **Obsidian**:vault,切换 vault = 一切切换

共同点:**项目是"默认范围"——选中了它,检索、列表、图谱、上下文全部自动收窄。**

## 3. 项目在 DialogMesh 语境里的定义(提议)

**项目 = 认知边界(cognitive boundary)**,包含:

- 一组会话(session 归属项目)
- **记忆检索的默认范围**(ContextCompiler 召回时项目内语料优先——这是对回答质量的真实提升,不只是分组)
- 图谱切片(图谱页默认只渲染当前项目的子图)
- 任务与产物(任务图、生成文件按项目归档)
- 可选的项目级指令/画像切面

## 4. UI 落点

1. **侧栏「项目组」**(2026-08-15 已按用户意见从"顶部切换卡片"改为导航内项目组):位置在**主导航之下、洞察之上**;每个项目一行(15px 色块头像 + 名称),点击即切换范围;**当前项目用右侧 5px 琥珀圆点标记**,与页面导航的左侧橙条区分开(一个是"范围",一个是"位置");组标右侧常驻 `+` 新建项目。参考 YouMind 侧栏项目列表。顶部不再放切换卡片(装饰感、且 mockup 阶段被指出"不能切换很奇怪")。
2. **项目主页**(新页面,点项目名进入):项目内会话列表 + 项目图谱预览 + 最近产物 + 一句话项目洞察("本周新增 23 条记忆,主题集中在次级通道辨识")
3. **新建会话默认归属当前项目**;会话列表按项目分组或加项目过滤器
4. **图谱/记忆/任务页**:顶栏加项目范围 chip(可临时切到"全部")

## 5. 落地路径(后端没有,分阶段)

| 阶段 | 内容 | 依赖 |
|---|---|---|
| P0 前端-only | 本地映射表 session_id → project(存 localStorage/本地文件),先跑出切换器 + 项目页骨架 | 无后端改动 |
| P1 后端实体 | session/task/graph-node 加 `project_id`;ContextCompiler 检索加 `project` 范围参数 | 后端排期 |
| P2 项目级智能 | 项目图谱切片、项目级画像/洞察、跨项目记忆分层(全局知识 vs 项目知识) | P1 完成 |
