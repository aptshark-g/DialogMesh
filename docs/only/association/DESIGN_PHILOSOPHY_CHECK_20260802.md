## 2. 公理一致性矩阵（A1-A25 全量对照）

### A1 视角是模块属性，颗粒度是内部递归 — ✅ 强符合

- 关联链一级视角 = 关系/因果（PARADIGM §8 明确）。
- L3 四视角投票（discourse+profile+association+pcr）正是"多个一级视角汇聚到关联链"的实例——不是标签切换，是模块职责汇聚。
- 二级视角（结构/语义/时序/反例）隐含在 L2 语义本体（结构）、L2.5 时序先验（时序）、L4（时序）中。
- **判定**: 设计符合；实现缺"关联链如何暴露自己的视角/颗粒度接口"（§9 开放点也提了）。

### A2 颗粒度哲学：地图式递归图 — ⚠️ 部分符合

- 符合面: StateGraph（对话树+关联链=统一网状结构）体现递归图；L5 层级（伪因果→实因果）是不同颗粒度。
- 缺口: L2 substrate 查询固定 1-2 hop，不是"任意节点可缩放"——递归缩放未在关联链设计显式化。
- **判定**: 设计方向对，但关联链没有"颗粒度缩放"的第一类接口（放大到子图/缩小到摘要）。

### A3 关系第一公民 — ✅✅ 强符合（关联链的根本哲学）

- RelationEdge/Evidence/mechanism 全部 first-class、可审计、可查询（RELATION_SUBSTRATE v2.0）。
- chapter2 全文就是"A3 关系>提示词"的展开。
- **判定**: 这是关联链存在的理由；实现 `compiler/relation_substrate.py` 存在但无产出路径（审计 D 系列）。

### A4 信念是竞争出来的（7 维）— ✅ 强符合（含一处实现张力）

- 7D BeliefState（support/conflict/stability/coverage/recency/novelty/entropy）与 PARADIGM 定义一字不差。
- Hypothesis Engine"竞争→冻结"机制 = A4 的"维护一群互相竞争的解释，等待共识自然形成"。
- **实现张力**: `l2_5_belief.py` 把 7D 做成说明性字段，真正驱动决策的是贝叶斯概率；`hypothesis/` 包才是离散投票。A4 要求"决策看 7 维不看单一 confidence"，当前实现不完全满足。

### A5 树是推理工作台 — ✅ 符合

- 关联链 L3 意图标签 → 对话树 topic/action 标注（双向），不替代对话树。
- **判定**: 符合"树管推理焦点、关联链管关系"的分工。

### A6 认知必须自我纠错 — ✅ 设计符合 / ❌ 实现断链

- 设计: 用户改 L1.5 补全 / L2 语义 / L5 因果标注 → 元认知审核 → 画像更新 → 行为链记录（BUSINESS_CHAIN_06 §4 权限表）。
- 实现: 负向反馈路径全部断（D4 冷路径从未运行、D7 subscribers 无依赖、API 无暴露）。
- **判定**: 这是"设计有、实现无"的最大哲学违背——A6 是本项目核心，关联链的修正回流是整个认知负向链路的一部分。

### A7 信息论根：方差与熵 — ✅ 符合

- L2.5 的 entropy>0.5 → LLM 触发 = "低概率高价值定位"实例。
- 7D 中 entropy 维度直接来自 A7。
- **判定**: 符合；且 L2.5 的"5 轮强制结晶"= A7 的"有限轮不收敛则最大熵默认域"。

### A8 表达形式哲学 — ✅ 通过子图/编译快照体现

- 关联链产出的关系天然结构化（JSON 表达），通过子图/Context 编译快照（A8 的工程化）呈现给 LLM。
- **判定**: 关联链自身不需要选表达形式（那是子图的职责），但 RelationSubstrate 的 LOD 4 级（名称→结构→全部→+mechanism）与 A8 形式光谱（XML/JSON/NL）可对应。

### A9 行为是一等公民 — ✅ 强符合

- BUSINESS_CHAIN_05_SUPPLEMENT: "关联链双重角色：既是被查询的知识源，也是被更新的学习目标（双向）"。
- L4 三方交汇：行为链提供 A→B 行为序列，关联链更新边权重。
- **判定**: 行为发现→元认知审核→关联链吸收的三阶段闭环是 A9 的完整实例。

### A10 元认知 = 第二大脑 — ✅ 设计符合

- L5 伪因果送审元认知；元认知审核子图关联（BUSINESS_CHAIN_06 §3 双向图）。
- **判定**: 设计符合；实现待审计（元认知与关联链的审核通道）。

### A11 执行层哲学 — ⚠️ 边缘相关

- 前置富化器（切分前消解）符合"可回溯可修正"精神——切分后的 chunk 可独立回溯。
- **判定**: 关联链不直接涉及执行层，但前置富化器是 A11 在"上下文准备"侧的呼应。

### A12 对象之下是约束空间与转换 — ✅✅ 强符合（因果哲学的地基）

- "因果=约束空间内稳定投射"（洗车店例子）→ structural_prior ≤0.7 = A12 的工程落点。
- do-calculus 后门准则验证 HARD_BLOCK = "约束空间内验证因果"。
- **判定**: 关联链 L5 是 A12 在因果域的完整载体；实现断链（D1/D2/D5）是工程欠账不是哲学违背。

### A13 长证明后验 — ✅✅ 强符合（并解决信念哲学张力）

- L2.5 贝叶斯序贯 `P = prior + (1-prior)×likelihood` 是 A13 的原型公式。
- **关键发现**: A13 明确说"与 Hypothesis 竞争互补——单步可解时用证据投票（可解释），单步不可解/需跨轮收敛时用贝叶斯序贯（数学严谨）——两者是同一处理哲学的两种力度"。
- **这直接裁决了 DESIGN_DEEP_READ §6 张力 1**: 两套信念哲学不是矛盾，是按"单步可解/不可解"分场景选择。设计文档缺的是"何时用哪个"的决策规则（可在 L3 前加选择器）。

### A14 工程链哲学 — ✅ 强符合

- A14 明确引用 BUSINESS_CHAIN_06 §2.6（L4 三方交汇）。
- 约束=事实间的隐含结构；L4 时序是关联链×行为链×工程链的交汇点。
- **判定**: 关联链 L4 是 A14 的指定汇合点；工程链接线状态待审计（COMPLETENESS 说工程链部分完成）。

### A15 温度系统哲学 — ⚠️ 边缘

- L5 伪因果降级（元认知发现矛盾→降级 L4 重新验证）与温度"降温换表示"呼应。
- **判定**: 关联链非温度系统主场（记忆/持久化才是）；无违背。

### A16 多层编排冷热哲学 — ✅✅ 强符合

- 关联链快慢双通道：Fast（L1-L2 <5ms）/ Async（L1.5 LLM）/ Slow（L5 因果晋升）= A16 冷热分层的直接实例。
- DESIGN_HYBRID_ARCHITECTURE（Event Sourcing 冷路径隔离）= A16 "先给体验再给准确"的架构实现。
- **判定**: 关联链是 A16 的样板模块；实现未接线（D4）是工程欠账。

### A17 git 式记录 — ✅ 强符合

- 关联链冷路径 = EventLog append-only + last_seq 增量拉取 + 崩溃重放（HYBRID_ARCHITECTURE §六）。
- **判定**: 设计完整符合 A17；实现 EventLog 在（`event/storage.py`），关联链订阅未接。

### A18 参数自适应 — ⚠️ 部分

- 符合面: 置信度融合阈值、骨架匹配阈值、belief 锁定阈值在 config（l2_config.json）。
- 缺口: 阈值未全部进 ParameterRegistry（A18 要求参数注册表 + 三重调节）；骨架库 5/20 且匹配阈值硬编码。

### A19 白盒化 — ⚠️ 设计符合 / ❌ 实现违反

- 设计: 用户可查看/修改 L1.5/L2/L5（BUSINESS_CHAIN_06 §4 权限表）——白盒承诺完整。

### A20 竞争吸收 — ✅ 强符合

- **判定**: 关联链是 A20 的最大受益模块（5 项目 8 吸收点中 4 点落在关联链）。

### A22 因果哲学（发现型三层）— ✅✅ 强符合 / ❌ 实现 stub

## 4. 核心发现：哲学对设计张力的裁决

### 裁决 1: 两套信念哲学 = 同一哲学两种力度（A13）

DESIGN_DEEP_READ §6 张力 1（离散投票 vs 连续贝叶斯）被 A13 直接裁决：
- **单步可解** → 证据投票（Hypothesis Engine，可解释）；
- **单步不可解/需跨轮收敛** → 贝叶斯序贯（L2.5，数学严谨）。
- 两者不是二选一，是"同一处理哲学的两种力度"。
- **设计缺口**: 缺"何时用哪个"的选择器（可在 L3 前根据 ambiguity/entropy 决定）。

### 裁决 2: 关联链是 A16 的样板模块

快慢双通道 + 冷路径 Event Sourcing = A16"快反馈 + 后补修正"的完整实例。这印证了 DESIGN_HYBRID_ARCHITECTURE 的正确性，也意味着关联链施工必须保持冷热分层的骨架。

### 裁决 3: A19 白盒化是关联链实现的最大欠账

设计给了用户修改权限（L1.5/L2/L5），实现零暴露。按 P22"CLI 数量是白盒的度量"，关联链施工 P0 应包含 `dm assoc` 系列 CRUD 命令。

### 裁决 4: A18"验证必须真实"否定现有测试

当前关联链测试全是 `>0` 浅断言——直接违背 A18。施工时必须重写为黄金样例集 + 真实断言（用户已多次强调"绿了不代表对"）。

### 裁决 5: A22 哲学正确、工程欠账

L5 因果三层设计完整符合哲学，但实现 stub。修复方向不是改哲学，是补实现（D1/D2/D5 根修：models 非 stub + 三步映射复活）。

## 6. 对实现审计的哲学指导（后续施工红线）

1. **冷热分层不可丢**: 关联链实现必须保留 Fast/Async/Slow 路径骨架（A16）。
2. **关系必须可查询**: RelationSubstrate 必须有产出路径（A3）——当前无调用方是最大哲学违背。
3. **修正回流必须有**: 用户改 L1.5/L2/L5 必须回流（A6）——先补 API 再谈模型。
4. **测试必须真实**: 黄金样例集 + 对抗性断言，拒绝浅断言（A18）。
5. **白盒通道必须建**: `dm assoc` 系列命令（A19/P22）。
6. **因果克制**: prior≤0.7 + do-calculus 负向验证，绝不输出 1.0（A22/P25）。
7. **信念按场景选**: 单步可解投票、跨轮贝叶斯（A13）。
