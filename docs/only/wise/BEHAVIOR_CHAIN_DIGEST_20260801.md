## 二、行为链的完整机制图景（已读部分）

### 2.1 定位

**行为链不是被动记录器——是预测引擎**（BC05 §1）。回答四个问题：用户下一步可能做什么？行为是否异常？系统应建议什么？预测对错如何更新？

管线: 编译器 → 行为嵌入层 → BehaviorGraph(存储/权重) → BehaviorPredictor(预测) → FusionEngine
                              ↑                                        ↓
                        BehaviorRewarder(奖励/反思)              Cognitive Tree(ABL 反思)

### 2.2 前瞻机制（核心——为讨论 2）

**显式预测（四层决策树，BC05 §3）**:
```
① 成本底线(token 超支) → 纯统计
② 风险劫持(delete/pay/权限) → 无条件 LLM
③ 冷启动(turns≤3) → LLM + ε=0.6 探索（构建初始先验）
④ CI 宽度: 收敛(conf>0.85)→贝叶斯; 混沌(0.4-0.85)→LLM 黄金区; 发散(conf<0.4)→主动询问
```

**动态 ε-greedy（BC05 §4）**: 冷启动 ε=0.6 → 指数衰减 → 稳定期 0.05 → 锚点>50 时 0.02

**多源协同权重（BC05 §5）**: 历史锚点(0.10→0.45) / 对话树(0.30→0.25) / 画像(0.25→0.15) / LLM(0.30→0.05) / 关联链(0.05→0.10) —— 冷启动 vs 稳定期权重切换

**强化学习信号（BC05 §6）**: R = 0.7×accuracy + 0.3×info_gain；Q-table(state={action, recent3, phase, cluster}, action)
- accuracy: +1.0 命中 / -0.5 错误 / +0.2 部分正确
- info_gain: +0.3 新模式 / 0 无新信息 / -0.1 幻觉（锚点验证失败）

**LLM 协同（7/24）**: Layer2 行为漂移解释 + 异常模式发现 + 阈值自适应；Layer3 DPO（接受=正对/拒绝=负对/修正=偏好修正版/无反应=0.3 弱信号）

**纠错即训练（THOUGHT_IMPRINT 哲学 4）**: 纠正惩罚是预测命中的两倍（+0.10 / -0.20）；连续纠正 2 次跳过 EMA 硬覆盖

**冷启动种子（GRAPH）**: ColdStartSeeds + 稀疏处理链（语义邻居→LLM→种子→均匀分布）；种子自动废弃

### 2.4 发现→审核→吸收 三阶段（BC05_SUPPLEMENT）

```
阶段一 统计发现（零 LLM）: P(B|A)≥0.75 + 关联度≥0.3 + 重复≥3次
阶段二 前端展示（审核前即可消费）: 用户自己就是最好的验证者
  ✓ 接受→verified_by_user; ✗ 拒绝→送元认知分析原因; ⏰ 10s超时→pending_review
阶段三 元认知审核 + 关联链吸收: 通过→A↔B strength+0.05; 拒绝→-0.02
```

- **关联链双重角色**：既是被查询的知识源，也是被更新的学习目标（双向）
- **画像驱动阈值差异**：高C→min_repeat=2；高NC→=4；低A→conf=0.85；高O→min_assoc=0.2
- **与预测的关系**：预测对了→加速发现（跳过重复要求）；发现被审核通过→注入历史锚点→提高预测准确率

### 2.5 三层参数范式（DESIGN_V3_3_ALGORITHM §0）

算法参数的统一设计规则（每个模块的阈值/权重均遵循）：
1. **文献锚点**：从公开基准/论文查参数参考值（“合理起点”不是“最优值”）
2. **安全区间**：下界=功能退化，上界=能力浪费；区间内系统不崩溃
3. **语义对齐自适应**：调整信号必须与参数语义作用对象对齐（不用全局信号）——这就是 A18 “参数编码 + 对齐信号”的算法级定义，也是 PCR 参数自适应的工程基础

### 2.6 关键 ADR（DESIGN_V3_1_BEHAVIOR_SUMMARY §9）

| ADR | 决策 | 理由 |
|-----|---------|---------|
| 011 | 扩展 TopicTree 而不新建行为树 | 避免跨树查询复杂化 |
| 012 | L1Summary 用 LLM 生成 + 规则兜底 | 规则模板信息丢失 60-70%，三链需语义理解 |
| 013 | 预测不参与当前轮决策 | 预测=猜用户要做什么，当前轮=理解用户说了什么；错误预测参与决策会误解当前意图 |
| 014 | 行为权重不直接 fine-tune LLM | 在线 fine-tune 灾难性遗忘；行为权重是用户级、LLM 参数是跨用户 |

### 2.7 思想源头（LITERATURE_CORTEX_CONVERSATION）

这份 7/4-7/5 对话是行为链/因果设计的起点，关键原则均在此诞生：
- **“对话树的核心不是分类，是建模行为因果”**：从后验切分器→预测性行为图（输入→预测→验证→更新权重）
- **“错误推测是黄金训练信号”**：用户下一步行为本身就是训练，LLM 做猜测成功加分失败修正
- **“因果是约束的投射”**：洗车店 5 米例子（要洗车→车到店→开过去）——事实上不存在因果，只有约束，约束让关联变成因果
- **“二合一架构”**：LLM 粗切分 + 规则选择性深挖（避开组合爆炸与 LLM 注意力竞争）
- **“并行跟踪的问题与方案”**：复杂度可控调/因果映射鸿沟/性能/噪声=画像问题

### 2.8 完整行为链生命周期图景（合并所有文档）

```
行为发现(2.4 统计) → 前端标签 → 用户反馈(✓/✗/超时) → 元认知审核 → 关联链吸收
行为预浌(2.2 四层决策树) → 前端建议 → 用户接受/修正 → 奖励(REWARDER) → 权重更新(GRAPH) → 回流
两条路互补: 预测对了加速发现; 发现被审核通过注入锚点提高预测

### 2.3 工程细节（已读部分）

## 三、与 openclaw standing intents 的对照（讨论 2 核心）

| 维度 | 行为链（我们） | standing intents（openclaw） |
|------|--------------|------------------------------|
| 性质 | **隐式预测**（学用户行为模式） | **显式声明**（用户主动说"当X提醒Y"） |
| 来源 | 行为序列统计 + LLM 候选 + 画像 | 用户指令（intent 工具） |
| 冷启动 | ε=0.6 LLM 探索 + 种子库 | 无（直接用户声明） |
| 匹配 | 四层决策树（成本/风险/冷启动/CI） | 确定性 FTS 预筛（零模型调用） |
| 学习 | DPO + Q-table + 信息增益 | 无（纯状态机） |
| 生命周期 | 边权重演化 + 种子废弃 | 显式状态机(pending/armed/fired/done/cancelled/expired) |
| 取消 | 用户行为修正自然改变模式 | 持久状态非模型判断（ProEvent 证据） |

**结论**：
1. **隐式前瞻（行为预测）我们比 openclaw 深得多**——四层决策树 + 冷启动 + DPO + 共塑造式，这是我们的强项。
2. **显式前瞻（用户声明的未来事件）我们没有专门承接机制**——用户说"以后提到 X 提醒我 Y"，目前大概率进对话树/记忆靠上下文召回，而 openclaw 用 TriggerBench 证据证明这种方式会失效（前瞻回忆随上下文衰减，漂移到"总是提醒"）。
3. **待拍板**：是否需要轻量"显式承诺"子层（挂在行为链下：关键词/scope/expiry/fire budget，匹配走确定性 FTS，生命周期显式状态）？

## 五、讨论 2 拍板：行为链 = 行为认知系统（显式+隐式一体）（2026-08-01）

### 5.1 拍板结论

**显式承诺属于行为链的内系统模块，显式与隐式一体，双向可逆。**

- 不是独立子系统（否定了我先前"轻量独立子层"的建议）
- 依据：A1（一个事实多视角）+ A24（可逆推性）——显式声明是隐式模式的编译产物，隐式模式是显式声明的学习沉淀
- 定时等内容也纳入行为链（时间触发是行为条件的一种）

### 5.2 设计形态

```
行为链 = 行为认知系统（显式+隐式一体）
├── 隐式层: BehaviorGraph 权重（学出来的行为模式）
│     └── 四层决策树预测（ADR-013: 预测不参与当前轮决策）
├── 显式层: 用户声明承诺（编译出来的未来动作）
│     ├── 事件触发（"当X提醒Y"）→ 确定性 FTS 匹配
│     └── 时间触发（"周五提醒"）→ 定时条件
└── 双向转换（A24 可逆推性）
      ├── 显式→隐式: 每次承诺的创建/触发/完成/取消 都是行为事件 → 进行为图学习
      └── 隐式→显式: 行为图稳定模式 + 元认知审核通过 → 编译为显式建议（前端标签）
```

### 5.3 三个实现边界（已确认）

1. **存储形态**：行为图节点/边加 `explicit: true` 标记 + 独立生命周期字段（pending/armed/fired/done/cancelled/expired），共享同一图结构——不新建子系统，只加形态标记
2. **调度边界**：显式承诺命中 → 确定性匹配（零 LLM）→ 注入隐藏上下文块（每轮≤3，对齐 openclaw trigger injection），不参与隐式预测的权重竞争
3. **学习回流边界**：承诺完成/取消回流行为图学习（显式→隐式），但**触发本身不算学习信号**——只有"触发后用户实际行为"才算（防自我强化：承诺触发≠用户真会做）

### 5.4 下一步

- 审计 `core/agent/behavior/` 代码现状（哪些落地/空壳）
- 决定改造策略（统一审计后改造 vs 一个一个来）
- 再深入讨论改造
