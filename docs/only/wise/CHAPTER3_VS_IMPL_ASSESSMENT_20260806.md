## 一、结论先行

**不是同一水平线。验证端到位, 提炼端差半截。**

- 现有实现 = **统计蒸馏（一阶抽象）**: 行为序列"完全相同 ×N"→ 聚类 → 模板,
  然后 A24 coverage 验证。本质是 Skill 式"从数据里提取动作序列"。
- 博客设计 = **二阶抽象**: LLM 在"掩盖（无上下文, temperature=0.8 发散猜）"
  与"暴露（全上下文, temperature=0.1 收敛筛）"两种信息状态下反复碰撞,
  反事实扩展, 产出**启发链（判断准则）**而非动作模板。
- 区别正是博客 §九 说的: Skill 回答"怎么做", 二阶抽象回答"该不该做、用什么道理判断"。
  现有实现产出的是 Skill（动作模板）, 不是启发（判断准则）。

## 三、为什么"统计聚类"不等于"掩盖/发散"

博客 §六.5 的核心: **掩盖 = 剥夺证据 → LLM 被迫调取预训练先验**,
产生"合理但未被验证的、甚至错的"假设——这些假设是候选"道理",
且能暴露两个相反哲学（卡尔曼 vs 信息论）在统一判据（可解释性）下的碰撞。

统计聚类做不到这点:
- 只发现"已发生的相同序列", 无法产生"可能正确的其他做法"（发散空间 = 0）
- 无法表达知识边界（"什么被拒、为什么被拒"——博客 §六 明确这是知识本身）
- 反例/推理路径完全缺失 → 启发不可审计、不可迁移

## 四、补充清单（按优先级）

### P0 — 二阶抽象提炼管道（对齐博客 §六.5）
新模块 `core/agent/blueprint/heuristic_distiller.py`（或扩展 learning_bridge）:
1. **发散**: 从 trace_store 样本构造"决策场景摘要"（掩盖实体名/数值）→
   LLM(temp=0.8) 生成 K=3-5 候选启发（含反例式候选）
2. **收敛**: 暴露完整上下文 → LLM(temp=0.1) 逐候选筛选 →
   保留 + 拒绝理由（拒绝理由进 knowledge boundary）
3. **反事实**: 对低覆盖高价值候选 → "如果该启发为真 → 哪些行为应被改变" →
   在历史轨迹中找支持/反驳证据 → 命中升级 / 未命中降级（拒绝理由保留）
4. **可逆推验证复用**: 通过的发散启发走 `_a24_verify`（60-80%）

### P1 — 启发链结构化
`SkillCandidate` 扩展: `pattern_desc`（模式描述）/ `conditions`（适用条件）/
`counterexample`（反例）/ `reasoning_path`（推理路径）。LLM 生成四元组。

### P1 — 元认知监测
周期审计启发库存: coverage 低于阈值 → 标记 stale 并触发重新发散;
新旧启发冲突 → 冲突记录进元认知队列（M5 通道已通, 补输入源）。

### P2 — 冷启动种子 + 可递归
- 内置 3-5 条种子启发（手写过渡, 经验积累后退役）
- 启发冲突 → 元规则凝练（复用同一发散/收敛机制, 对象=裁决）

## 六、建议顺序

1. **先补 P0 二阶抽象提炼管道**（这是"设计水平线"的核心差距, 博客 §九 的灵魂）
2. 再 P1 启发链结构化 + 元认知监测
3. GAP-3/GAP-4（工具批次介入/压缩反馈）为外围 P2, 可并行/随后

> 缺口优先于外围交互机制。GAP-3/4 是执行体验优化, 二阶抽象是认知能力本体。
