## 0. 为什么需要这份公约

200+ 设计文档不是吃素的。但我们最近的 PCR 讨论暴露了一个问题：**模块化讨论让我们丢失了整体范式**。

- 我们纠结"坐标 vs 标签"、"算法 vs LLM 谁裁决"、"切分先后"——这些大多是**范式缺失导致的伪问题**；
- 我们假设某个算法"无敌"，假设维度可以孤立计算，假设判断可以没有参照、没有先验、没有后验——这都违背了项目自己的哲学；
- 项目已经有成熟范式（v4 认知流水线 376 测试、v5 信息论分治），只是没有写成一份**公约**供所有讨论引用。

本公约的目的：把范式显式化，让每个模块设计都能回答三个问题：
1. 我在这条认知流水线的哪一层？我的初始视角是什么？
2. 我产出的是 Observation 还是结论？我在哪个颗粒度级别工作？
3. 我的判断用了哪些参照、先验，错误后如何回流？

## 1. 核心范式：认知流水线（一条链，五层）

```
Event ──多域投影──▶ Observation ──证据竞争──▶ Hypothesis ──冻结──▶ Knowledge ──蒸馏──▶ Skill
 (事实)              (候选解释)        (竞争中的信念)    (稳定认知)         (可复用能力)

      ▲                                                                          │
      └─────────────────────── 负向反馈 · 修正回流 ←───────────────────────────────┘
```

**每一层都在减少信息量、增加确定性。** 这是整个项目的骨架，任何模块都能在这条链上找到自己的位置。

| 层 | 定义 | 关键机制 |
|----|------|---------|
| Event | 原始事实（用户输入/执行结果/代码变化） | 无加工 |
| Observation | 一个事件在多个认知域里**同时成立**的候选解释 | 多域投影（模块初始视角） |
| Hypothesis | 跨域竞争中的信念，维护 7 维信念状态 | 证据竞争/投票/时间衰减 |
| Knowledge | 冻结后的稳定认知，不再参与竞争 | 共识冻结 |
| Skill | 从 Knowledge 蒸馏的可执行能力蓝图 | 能力蒸馏 |

**负向反馈（v4 已知缺失，v5+ 设计空间）**：
- 错误修正：用户明确说"不对/错了"的信号应天然最高权重（UserCorrectionVote）；
- 过时淘汰：长期未用的知识/技能应自动降级；
- 修正回流：一次纠正应回流到 Hypothesis/Knowledge 层，而非只影响本次执行。

## 2. 公理

### A1. 视角是模块属性，颗粒度是内部递归（一级视角 vs 二级视角）

**来源**: v4 Observation Compiler（5 认知域）+ L5 §4.1 多视角调整（结构/语义/时序/反例）+ 颗粒度哲学讨论

**含义**: 视角不是"给同一事件贴不同标签"，而是**模块职责的自然投影**——每个模块因为职责固定，天然有一个初始视角：

```
行为链  → 行为内容视角（学习/记录/修正/行为）
对话树  → 对话结构视角（话题/深度/焦点）
PCR     → 意图/认知视角（期望/噪声/复杂度）
画像    → 用户认知视角（惯性/情绪熵/期望偏差）
子图    → 知识关系视角（锚点/扩散/因果）
```

这些一级视角**浮于表面、由模块固定决定**，它们之间的差异是"看什么"，不是"怎么抽象"。

而**深层次的抽象发生在更细的颗粒度**——每个模块内部还有自己的二级视角（验证视角）：
结构 / 语义 / 时序 / 反例。这四个不是模块间的视角差异，而是**单一模块内部的更细颗粒度视角**。

**推论**:
- 一级视角不可互替：行为链和对话树天生干不同的活，这不是设计缺陷，是职责划分；
- 二级视角（结构/语义/时序/反例）是所有模块**共享的抽象质量判据**；
- "多视角"的真义是颗粒度递归，不是标签切换。

### A2. 颗粒度哲学：地图式递归图（不是分层图）

**来源**: 持久化/图结构讨论（2026-08-01）+ L5 四区存储 + 视角摘要化

**含义**: 系统的图结构不是"分层图"（严格父子、部分-整体），而是**地图式递归图**——就像地图：

```
缩放级别 1 → 看到国家（盘根错节，但只有国家级摘要）
放大       → 看到省份（更细的信息出现）
再放大     → 看到城市、街道（细节展开）
```

- 同一片区域，在不同缩放级别呈现**不同的摘要**——这不是"子集包含"，是"颗粒度决定可见信息"；
- 信息盘根错节（跨级引用、隐线），但**在放大颗粒度之前，你只看到当前级别该看的**；
- 缩小 = 摘要化（视角压缩）；放大 = 细化（颗粒度展开）。

**与视角摘要化的关系**: 两者相辅相成——**每一级缩放都是一种视角摘要**。颗粒度决定"看多细"，视角决定"从哪看"。一级视角 + 颗粒度缩放 = 完整的多视角抽象。

**推论**:
- 图/持久化应该支持**递归缩放**（任意节点可放大到子图、可缩小到摘要），而不是固定层级；
- 摘要不是"丢掉细节"，是"换一个缩放级别呈现"——细节仍在，只是不可见；
- 抽象质量由"放大了能否还原"（可逆推）定义——回到 A5。

### A3. 关系第一公民（关系 > 提示词）

**来源**: chapter2 全文 · v4 Semantic World Model

**含义**: 提示词只能告诉 Agent 一条规则，无法告诉它"这条规则和谁相关、从哪来、什么时候会变"。关系是比文本更难传递、更稀缺的上下文资源。

**推论**:
- 上下文是**编译出来的局部知识快照**（子图），不是 prompt 里的一句话；
- 关系是 first-class、可审计、可查询的实体（graph.backbone / communities / edge_type）；
- 工程上：给 LLM 一个局部世界子图，而不是一条 system prompt。

### A4. 信念是竞争出来的（7 维，非单一 confidence）

**来源**: chapter2 §四·五 Hypothesis Engine · 7 维 BeliefState

**含义**: 信念状态不是单个 confidence 数值，而是 7 维向量：
support / conflict / stability / coverage / recency / novelty / entropy。

**推论**:
- 决策不能只看"概率多高"，要看**支持与冲突的张力**、稳定性、覆盖率、新颖度、熵；
- 低置信 ≠ 需要问用户：要先看熵、看冲突，再看是否需要澄清。

### A5. 树是推理工作台（推理 > 记忆）

**来源**: chapter1 全文 · 编译器 AST 教训

**含义**: 对话树首先是**推理树**，其次才是记忆树。它不是用来记住一切的，是用来**管理推导的焦点**的——每一层只关注当前该关注的东西。

**推论**:
- 树给每个节点一个**位置信号**（你在哪、怎么走到这里的）；
- 记忆（持久化图）在磁盘上，对话树在内存里，每次只搬运当前思考所需的信息；
- "够用就行，贪多是病"；遗忘用激活计数取代时间衰减（零算力）；
- 需要跨跳时用指针（Tree-Graph Hybrid），主干走树、旁路走图。

### A6. 认知必须自我纠错（负向反馈 + 后验学习）

**来源**: chapter2 §十 已知局限 · DESIGN_LEARNING_INGESTION.md · Profile ExecutionTrace

**含义**: 正向链路（Event→...→Skill）只是半个认知系统。真实的认知系统必须有负向链路：错误修正、过时淘汰、修正回流。

**推论**:
- 用户纠正信号（REJECT/否定词）应天然最高权重；
- 模块的判断（zone/标签/切分/期望）**必须**被用户反馈训练，而不是一次算完；
- 学习摄入（ChromaDB 聚类 → LLM 凝练规则 → EventLog）是后验学习的工程形态；
- 画像（Profile）通过 ExecutionTrace 的 STRENGTHEN/WEAKEN/REJECT 持续更新。

### A7. 信息论根：方差与熵是同一枚硬币（低概率事件的两种态度）

**来源**: DESIGN_INFO_THEORETIC_COMPRESSION.md + DESIGN_L5_LONG_TERM_MEMORY.md + 卡尔曼滤波讨论（2026-08-01）

**含义**: 确定性与信息价值有两个度量，深层次统一：

```
方差（高斯/正态分布）: 度量"偏离中心的代价"——准确性
熵（log）:            度量"罕见本身的价值"——信息量 I = -log₂ P
```

- 低概率事件有两个态度：
  1. **低权重抹平**：当作噪声/异常，平滑掉（高精度场景下的传感器噪声）；
  2. **高价值定位**：罕见 = 高信息量，指向背后的不同机制（新状态、新意图）。
- 判断依据：**能否被现有模型解释**——能解释 = 噪声（抹平）；不能解释 = 新信息（定位）。
- 卡尔曼滤波的镜像：当对象精确性提高（预测误差→0）时，观测误差大的点反而主导状态更新——因为高精度下大偏差只可能来自"传感器误差区间估计"或"真实状态突变"，两者都极具信息量。

**推论**:
- 分治是必然选择，不是权衡：高概率低价值 → 聚类凝练；低概率高价值 → RAG 原样保留；
- "罕见 ≠ 无关，罕见恰恰是信息价值的来源"（Shannon）——这是 L5 存储决策的数学根；
- 聚类处理高频平庸（压缩成规则），RAG 处理低频高价值（定位参照），二者互补不互斥。

### A8. 表达形式哲学：语义决定形式，不依赖自然语言

**来源**: 表达形式哲学讨论（2026-08-01）

**含义**: 不是所有内容都必须用自然语言呈现给 LLM。**表达形式是语义的编码决策**——语言受制于语义语法，自然语言只是形式光谱中的一种，不是默认值。子图/Context 编译的一大职责就是为每类内容选择最合适的表达形式。

```
内容类型                    最佳表达形式
复杂且需清晰描述            XML（层级/属性/命名空间/可验证）
关系/结构化数据             JSON（键值/映射/无歧义/机器友好）
复合或含模糊性              自然语言（保留模糊空间/语义丰富/意图容忍）
```

**推论**:
- 机器对机器（组件间、给 LLM 的结构化上下文）不必经过自然语言的语法瓶颈——语法是信息瓶颈，能绕开就绕开；
- 结构化形式消除歧义、保持结构完整、减少描述性冗余（token 效率）；
- 模糊性本身是信息：用户意图不明时，自然语言保留模糊空间，不要过早结构化；
- 子图的职责不仅是“选哪些内容”，还包括“每种内容用什么形式表达”——表达形式是编译决策。

### A9. 行为是一等公民（对话只是行为的一部分）

**来源**: 行为链哲学讨论（2026-08-01）+ BUSINESS_CHAIN_05_BEHAVIOR.md + 05_SUPPLEMENT_DISCOVERY.md + DESIGN_COGNITIVE_DYNAMICS_V6

**含义**: 系统的观察对象不是“对话”，是**行为**——对话、工具调用、文件编辑、前端点击都是行为事件的一种，对话只是行为序列里的一种。行为链把行为流当作**强化学习的在线数据源**：预测引擎（P(B|A) 统计先验 + Q(state,action)）、动态 ε-greedy（冷启动探索→稳定收敛）、奖励函数（预测对 +1.0 / 错 -0.5 / 方向对 +0.2）持续回流更新先验。

**推论**:
- 所有用户交互归一为行为事件（统一观察面）；
- 行为发现三阶段：统计发现（零 LLM）→ 前端消费 → 元认知审核 → 关联链吸收；
- 行为 = 可观测的 Transition 序列；“变化”比“状态”更根本（v6 Transition 一等公民）；
- 行为的信任升级必须经过元认知裁决（候选 → 验证 → 吸收/降级）。

### A10. 元认知 = 第二大脑（思考的思考）

**来源**: BUSINESS_CHAIN_09_METACOGNITION.md + DESIGN_METACOGNITION_RUNTIME.md

**含义**: 第一大脑是算法+业务（各链干活）；第二大脑是反思、审核、回溯。元认知四职责：**协同**（跨树查询驱动、子 Agent 协调）、**学习**（Transition → L5 Memory → 所有模块学习）、**裁决**（跨树冲突、审核队列、归约）、**复盘**（Git 式版本控制 + 对比修改前后）。

**推论**:
- 双环结构：小环（节点内 Think→Act→SelfChk→Correct→Retry）+ 大环（冷路径审计 → 回档修正 → 重新执行）；
- User-In-Loop：任一步骤可暂停干预（LLM 低置信自触发 / 用户主动 / 规则触发）；
- 所有可修改数据 Git 式版本化（可回滚/可追溯/可审计）；
- 元认知自身的决策也版本化（审核通过/拒绝+原因）。

### A11. 执行层哲学：可回溯可修正，可自我批判

**来源**: DESIGN_EXECUTION_LAYER.md + 执行层哲学讨论（2026-08-01）

**含义**: 执行不是一路向下。树图（Tree-Graph Hybrid）是执行层的结构形态：树承载推导方向性（焦点管理），图承载联想（跨分支/跨树），七棵树并行构成森林，跨树查询驱动。思考允许**回退插入**（回到决策节点插新分支）与**任意位置插入**（元认知判断“执行前应先验证”）。

**推论**:
- 可回溯只是基础，**可自我批判**才是核心：修正深度必须匹配错误深度——浅错误回退一步，根定义错了要回到根节点注入新内容，或启动独立树图再合并森林；
- ReAct 重试闭环（MetaTree 质量评估，Max 3）：明确错误自动修正 / 模糊降温度 / 信息不足派生检测 Agent；
- 归约按重要性倒置（高价值 LLM 直接归约，低价值摘要丢弃）；
- 修正的深度 = 错误的深度（根节点修正 / 森林合并）。

### A12. 对象之下：约束空间与状态关联转换（视角的基石、元认知的元信息）

**来源**: THOUGHT_IMPRINT.md（约束空间哲学）+ DESIGN_COGNITIVE_DYNAMICS_V6.md（Transition 一等公民）+ BUSINESS_CHAIN_STATE_MACHINE.md（Command→Event→State）+ ENGINEERING_V3_3_DO_CALCULUS.md + DESIGN_GUARD_SYSTEM.md

**含义**: 
- **因果不是世界的固有属性，而是认知主体在约束空间中做出的投射**。当一组约束的稳定性超过观测者的参考框架时，这组约束定义的关系就是“足够好的因果”（THOUGHT_IMPRINT 转折 1，洗车店例子：要洗车→车到店→怎么到→开过去，约束连起来 5 米也需要开）；
- 对象（Object）只是表象。**对象之下是约束空间**（什么合法/什么可达/什么被禁止）**与状态关联转换**（状态为什么从 A 变成 B、转换的原因/证据/影响）；
- 发展史：Memory→Knowledge→Object→State→Transition→Dynamics。**真正的分水岭在 Object→State 之间**——一旦系统以 State 为中心组织自己，Transition 和 Dynamics 就是自然的下一步（v6 Transition 是一等公民，v7 Dynamics 是远景）。

**推论**: 
- **视角/模块的差异 = 约束空间的不同 + 转换模式的差异**：对话树、行为链、画像不是“看的内容不同”，而是“工作在哪个约束空间、处理哪些转换”不同——这是 A1 视角哲学的基石；
- **元认知的元信息 = 约束空间（可达/合法/禁止）+ 转换模式（Transition 类型分布）**：元认知分析的是转换模式（“为什么连续 3 次 REJECT？”、“为什么一直 INFER 没有 OBSERVE？”），而非静态状态（v6 §6.3 MetaReport）；
- 工程落点：Command→Event→State 事件溯源（防广播风暴，每 tick 只产 1 个 Event）、do-calculus 后门准则验证 HARD_BLOCK（约束空间内验证因果）、Guard System 背压/断路/级联检测（约束的运行时形态）；
- `structural_prior` 永远说“在当前约束空间里的稳定性”，不说“因果必然性”（永远 1.0）——哲学判断落到工程参数（约束稳定性取代因果必然性）。

### A13. 处理哲学：长证明后验（单步不可解时，贝叶斯序贯范式起作用）

**来源**: 处理哲学讨论（2026-08-01）+ BUSINESS_CHAIN_06 §2.4（L2.5 信念凝聚器：贝叶斯序贯更新）+ chapter2_relation_over_prompt.md（与贝叶斯更新的对照）+ DESIGN_ASSOCIATION_CHAIN_L1_L4.md（BLF / T-BN 时序贝叶斯）

**含义**: 处理不是一步到位的“回答”，是**跨步骤的证据累积与收敛**。当问题无法被单步骤解决时，贝叶斯范式起作用：

```
T1: 模块延迟飙升 → vote {诊断:0.3, 吐槽:0.4}
T2: 之前没加监控是吗 → vote {诊断:0.85}
    P(诊断|T1+T2) = 0.3 + (1-0.3)×0.85 = 0.895 → 超过阈值 0.85 → 锁定
LLM 回复草稿回传 → 自洽性增强 → P(诊断) = 0.97
5 轮未达 0.85 → 输出最大熵默认域 + 主动提问
```

**推论**: 
- **后验成为下一步的先验**：每轮投票更新信念池，后验喂回先验（L2.5 prior → L3 下一轮先验；T-BN 时序贝叶斯预测 P(intent_{t+1} | intent_t)）；
- **增量公式即长证明**：P = prior + (1-prior)×likelihood，每一步只加不确定部分的收敛量，多步累积达阈值才结晶；
- **与 Hypothesis 竞争互补**：chapter2 指出 v4 问“多少证据支持”、贝叶斯问“世界的不确定性”——单步可解时用证据投票（可解释），单步不可解/需跨轮收敛时用贝叶斯序贯（数学严谨）——两者是同一处理哲学的两种力度；
- **强制结晶防发散**：有限轮内不收敛→ 最大熵默认域 + 主动询问（不无限累积，防资源空耗）。

### A14. 工程链哲学：约束在事实之中天然存在（不变量是派生物，不是声明物）

**来源**: 工程链讨论（2026-08-01）+ chapter2_relation_over_prompt.md（RateLimiter 案例）+ chapter1_design_thinking.md（“平铺文本天然以时序为约束，大脑天然以关联为约束”）+ BUSINESS_CHAIN_07_ENGINEERING.md + DESIGN_ENGINEERING_CHAIN.md（RFC 七类节点）+ BUSINESS_CHAIN_06 §2.6（L4 三方交汇）

**含义**: 约束不是被“声明”出来的规则，而是从事实中**浮现**的不变量。事实天然携带约束关系（时序、依赖、类型兼容、行为继承）；工程链的工作是把这些潜在约束显式化为可推理的知识。最典型的证明是 blog 的 RateLimiter 案例：**“链路中间的新节点应继承两端的行为约束”——这条规则不在代码里、不在文档里、不在 prompt 里，它在 Auth 与 Logger 之间那条关系里。**（已有雏形：A3 关系第一公民、A12 约束空间、A2 递归地图、A13 证据累积——工程链是它们在工程域的汇聚点）

**要点**:
- **约束 = 事实间的隐含结构**：Auth 有 /metrics、Logger 有 /metrics、两者都是链路中间件 → 归纳出不变量“所有中间件必须暴露监控”。先有事实，后有约束；约束是事实的压缩概括。
- **约束是归纳不是声明**：Constraint 带 evidence 列表（candidate→verified），从多个事实实例归纳出普遍不变量，成立与否由**事实覆盖率**验证——与逆向动力系统同构（规则必须能反推回事实，coverage 60-80%）。
- **工程链 = 不变量链**：对话树描述“发生了什么”、行为链描述“做了什么”、因果链描述“为什么”，工程链描述**“什么必须成立”**。约束 ≠ 因果：约束满足是因果候选的必要条件，不是因果本身（L5 用约束满足做伪因果晋升的候选筛选）。
- **与关联链 L4 强绑定**：L4（时序模式）是关联链 × 行为链 × 工程链的三方交汇点。工程链提供约束条件（A 的实现依赖 B）→ 注入关联强度作为先验；行为模式确认后反向验证约束有效性 → 更新约束 evidence。
- **反模式是最高价值知识**：知道“什么绝对不能做”（负边 violates）比知道“怎么做”更有约束力；AntiPattern 核心禁止 LLM 自动创建（人工标注），是对 LLM 权力边界的显式约束，也是元认知审核的输入。
- **是 A12 的工程实例**：A12 说对象之下是约束空间（合法/可达/禁止）；工程链节点（Constraint/Rule/AntiPattern）就是工程域的约束空间表示，工程边（requires/depends_on/implements）就是状态转换规则。

**推论**:
- **约束继承**：新节点进入链路时沿约束边继承两端不变量（RateLimiter 案例），不必重新推理；
- **约束验证 = 自我纠错**：candidate→verified 是 A6 在工程域的实例化；违反检测（AntiPattern）是负向反馈的工程通道；
- **约束是子图骨架**：编译快照中约束边决定“哪些必须一起变”，是上下文压缩的信息论依据（强相关 = 强制保留）。

### A15. 温度系统哲学：记忆是热的（多因子复合温度场 × 价值轴）

**来源**: BUSINESS_CHAIN_04_META_PERSIST §3.3.1（HCWA ↔ 4 态温度映射）+ DESIGN_INFO_THEORETIC_COMPRESSION（温度×价值二维矩阵）+ 温度系统讨论（2026-08-01）

**含义**: 记忆不是均匀存储的，是有“温度”的——温度不是单一时间轴，而是**多因子复合场**：时间（最近 ≠ 重要）、访问次数（LRU 频率维度）、主题管理（主题簇活跃度）、时空局限性（物理分层），以及更深的行为惯性（长期行为模式固化记忆）等共同决定；信息价值是另一条正交轴（稀缺轴：罕见 ≠ 无关）。温度系统 = 模拟人（遗忘曲线/粘合度/语义唤醒）× LRU（访问频率驱动降级）× 时空局限性（内存→持久化→归档的物理分层）的复合考量：

```
active  → H (Hot):    当前 Session, 全量在内存
paused  → C (Warm):   近期 Session, 已持久化, 可按需加载
cold    → W (Cold):   历史 Session, 带衰减权重
frozen  → A (Archive): 压缩, metadata + 摘要

迁移: 粘合度阈值 (≥0.7 合并 / <0.4 切换) + 访问频率 (10 轮→cold, 50 轮→frozen)
唤醒: BGE 匹配 > 0.8 → 直接回到 Hot（语义相关打破时间衰减）
```

**要点**:
- **降温不是删除，是换表示**：Frozen 不是丢弃——高价值内容以 V3 里程碑+索引保留（检索可用），低价值压缩为摘要；温度决定的是“注入上下文的颗粒度”，不是“是否存在”。呼应 A2（颗粒度缩放）与 A8（表达形式服从语义）。
- **纯 LRU 不够，人不是按时间遗忘的**：LRU 只认“最近访问”，人脑按“关联强度/语义相关”遗忘与唤醒——CohesionScorer 粘合度（相关会话合并）与 BGE 语义匹配 > 0.8（唤醒）就是“人”的那部分，时间衰减只是其中一维。
- **温度 × 价值 → 保留策略（二维，不是一维）**：单独温度维会损失“罕见但冷”的高价值信息——Frozen 高价值仍保留里程碑摘要+索引；与 A7 信息论互补：温度管时间轴，价值管稀缺轴。
- **时空局限性是物理底座**：Hot 全量在内存、Warm 持久化可加载、Cold 带衰减权重、Archive 压缩——温度层级映射存储物理层与推理成本层（越热成本越高、粒度越细），是 A2 颗粒度哲学在记忆域的实例。
- **与 A5 互补**：A5 树是推理工作台——树的“激活计数”管推理焦点（当下该想什么）；温度系统管记忆驻留（该以什么粒度存在）。一个在内存推理侧，一个在持久化存储侧。

**推论**:
- **唤醒是语义的，不是时间的**：旧但相关的记忆应能跳过温度层级直接回 Hot（BGE > 0.8）——记忆的价值由关联强度决定，不由年龄决定；
- **温度是动态场不是静态标签**：每次访问/合并/唤醒都改变温度，温度是记忆的元状态（与 A12 约束空间呼应：合法迁移边由粘合度与访问频率约束）；
- **压缩即降维表示**：Cold→Frozen 的 V4 压缩与 A7 的 P(高)+I(低)→压缩同构——温度下降时换表达形式，信息不丢只换颗粒度。

### A16. 多层编排冷热哲学：快反馈 + 准后补 + 不阻断

**来源**: DESIGN_COLD_HOT_FEEDBACK.md（三层回写）+ BUSINESS_CHAIN_02_LLM_RESPONSE_SIDE.md（快慢双通道）+ DESIGN_EXECUTION_LAYER.md + 冷热编排讨论（2026-08-01）

**含义**: 传统 React 是“请求→尝试→判断对错→重来→对了才给”（阻断当前回答）；本系统的编排是“请求→多视角竞争→给最优回答→Meta 异步审视→修正未来”——**用户立即得到回答（不阻断），准确性由后补修正承载**。

**要点**:
- **快速算法先反馈**：第一层快速路径（算法/启发式/PCR 快通道）先给用户即时反馈，不等待深度分析；
- **准确性内容后补修正**：三层回写——Layer 1 确定信号→同步修正（CorrectionMark 附加不覆盖）；Layer 2 证据累积→异步裁决（Belief Accumulator 跨 Tick 收敛）；Layer 3 模式漂移→参数调整（下次 Tick 生效）；
- **不阻断 = 体验哲学**：修正不覆盖已给回答，只影响未来 Tick；“不二值”——不是对/错，是置信度区间；
- **git 式记录保证一致性**：所有修改走 Command→Event→State 事件溯源（每 Tick 只产 1 个 Event，防广播风暴）；NodeEditRecord 类比 Git diff（记录 action/original/new_nodes，超阈值快照）——可回滚、可追溯、可审计；
- **与 A15 呼应**：A15 是记忆存储的温度分层，A16 是编排执行的冷热分层（快通道=热、慢通道=冷）——同构：越热越即时、越冷越准确。

**推论**:
- **先给体验，再给准确**：用户体验由快速路径保证，系统准确性由后补修正保证，两者不互斥；
- **一致性靠记录不靠锁**：事件溯源 + diff 记录 = 任何状态可重建、任何修改可回滚；
- **修正深度匹配错误深度**（A11 延伸）：Layer1 表面修正 / Layer2 证据级修正 / Layer3 参数级修正。
- **不阻断 vs 准确性 = 分工，不是冲突**：后补修正就是专门消化“先给不够准”的通道——快速路径先给结果（如对话树的初步主题划分），后补改的是底层结构（树变动、执行层状态变动），而不是覆盖已给回答——与 A11 执行层可回溯可修正是同一机制在“回答之后”的延续。

### A17. git 式记录哲学：一致性是记录出来的，不是锁出来的

**来源**: BUSINESS_CHAIN_STATE_MACHINE.md（Command→Event→State）+ BUSINESS_CHAIN_03_USER_EDIT_TREE.md（NodeEditRecord ≈ Git diff）+ DESIGN_GLOBAL_STATE_MACHINE.md + git 式记录讨论（2026-08-01）

**含义**: 系统的一致性不靠“禁止修改”或“全局锁”保证，而靠**完整记录 + 可重建**保证——每个状态变化都是显式 Event，每次修改都有 diff 记录，任何时刻都能回到任意历史状态。这直接解决“多层编排中快慢通道并发修改”的一致性问题。

**要点**:
- **事件溯源**：Command → Event → State 三阶段，每 Tick 只产 1 个 Event（防广播风暴）；状态 = 事件序列的纯函数；
- **diff 记录**：NodeEditRecord 类比 Git diff（action: split/merge/move + original_node + new_nodes）；超阈值（>10 条或 diff_ratio>0.6）→ 快照存储当前版本；
- **可回滚可追溯**：任何修改可回退、任何决策可审计（谁改的、为什么改、影响什么）；
- **与元认知的接口**：修改记录 → Event Log → Observation Pool → 学习管线（A6 修正回流、A10 元认知审核都消费记录）；
- **与 A11 呼应**：执行层可回溯可修正，底层机制就是 git 式记录。

**推论**:
- **记录即资产，是学习溯源的地基**：git 式记录不是开销，是“逆向动力系统”的原料（从修改历史归纳模式），也是所有学习与溯源的统一入口——事件链记录了“为什么这样改”，没有它，后验学习和行为归纳就没有地基；
- **一致性 = 可重建性**：不追求“从不冲突”，追求“任何冲突可回滚重建”；
- **用户修改也是 Event**：用户的每次编辑都进入版本历史，成为行为链/画像的学习数据（A9）。

### A18. 参数自适应哲学：自动化调参（编码 + 测试 + 反馈闭环）

**来源**: BUSINESS_CHAIN_09_METACOGNITION.md（参数注册表 per-param change log + ε 自适应）+ DESIGN_METACOGNITION_RUNTIME.md（ParameterRegistry + 用户批准/调整）+ DESIGN_COLD_HOT_FEEDBACK.md Layer 3（OCEAN 权重/ε/蓝图偏置微调）+ 参数自适应讨论（2026-08-01）

**含义**: 系统参数不靠“拍脑袋定死”，也不靠“人工大量实验扫参”，而靠**参数编码 + 自适应闭环**：参数是显式编码的（注册表），需要大量测试建立基线；自适应提供**反馈 + 步长变动 + 最值范围**；搭配**用户感知调节 + 元认知调节 + 行为记录学习**，把人工实验量降到最低。

**要点**:
- **参数编码是前提**：参数注册表（per-param change log：slow_path.threshold 5→3→7）——参数不是散落的魔法数，是可追踪、可审计、可回滚的第一公民；
- **测试建立基线**：参数编码需要大量测试建立“什么值在什么场景下合理”的基线（黄金示例集）；
- **自适应 = 反馈 + 步长 + 最值范围**：自适应不盲目搜索，按反馈方向调整步长，受最值范围约束（合法域）；参数注册表记录每次变化（ε: 0.6→0.45）；
- **三重调节回路**：① 用户感知调节（用户直接改参数/批准调整）；② 元认知调节（参数注册表变化 → 复盘 → 参数自适应）；③ 行为记录学习（行为链记录 → RL 在线学习 → 反馈回参数）；
- **减少实验的本质**：把“人工网格搜索”变成“闭环自动收敛”——每次调节都是可评估的实验，评估结果回流决定下一步步长（A13 长证明后验在参数空间的实例：逐步收敛，不是一次到位）。

**推论**:
- **参数是可学习的约束**：参数的变化记录本身就是行为数据（per-param change log 供元认知复盘）；
- **自适应边界 = 最值范围**：不是无限调，是约束空间内调（A12 约束空间在参数域的实例）；
- **自适应 vs 稳定 = 步长问题，不是冲突**：参数收敛了自然就稳定，不需要额外稳定机制；变化剧烈是步长未设好（过大振荡 / 过小迟钉）；背后是数据规律性质（非平稳/周期/突变），待后续挖掘。
- **验证必须真实（核心）**：**不存在真正的完美量化标准**——意图/认知/对话质量没有客观完美的度量，任何指标都会失真（指标成为目标就不再是好指标）。因此自适应效果只能靠真实断言验证：黄金示例集 + 用户反馈 + 行为结果，不能靠“感觉调好了”（之前测试作假的教训）。
- **量化标准分层：用户反馈 > 成熟方案 > 自造指标**：用户反馈是**最终真相**（真实、直接，但不学术、不系统、难规模化）；学术与成熟企业实践的量化方案是**可信的代理指标**——吸收其成熟内容（评估方法论、指标组合、采集流程），补足用户反馈的不系统性；自造指标是最后手段，必须用真实断言验证（防 Goodhart 失真）。

### A19. 白盒化哲学：内容可操作，行为必记录（查改增删是承诺，不是功能）

**来源**: DESIGN_CLI.md（白盒化完整设计：每模块均可查看/修改/回溯）+ DESIGN_TRACEABILITY.md（设计点追踪）+ BUSINESS_CHAIN_03_USER_EDIT_TREE.md（用户编辑树）+ DESIGN_METACOGNITION_RUNTIME.md（元认知操作）+ 白盒化讨论（2026-08-01）

**含义**: 系统的几乎所有内容都是**可操作**的——可查看、可修改、可添加、可删除，且操作都会被记录。这不是额外功能，是产品承诺：**系统对用户、执行层、元认知三方都是白盒**。这就是为什么有那么多 CLI（dm discourse topic add、dm graph node edit、dm meta correction add...）——每个模块都暴露 CRUD 通道。

**要点**:
- **白盒是默认，黑盒是例外**：每模块均可查看/修改/回溯（DESIGN_CLI 第一行）；CRUD = show/get/add/edit/delete 是所有模块的统一约定；
- **三方操作者，同一套可操作性**：用户（dm ... edit）、执行层（执行中修正）、元认知（审核/建议/自动修正）都能操作同一内容——区别在权限与记录（A6 用户纠正权重最高）；
- **操作必记录**：每个修改都是 Event/NodeEditRecord（A17 git 式记录）——白盒的可操作性和记录性一体，操作即数据（A9 行为学习、A6 修正回流都消费它）；
- **可追溯是白盒的另一半**：DESIGN_TRACEABILITY 追踪每个设计点从“首次出现→设计→代码”——不只运行态白盒，设计态也白盒；
- **为什么必须白盒**：对齐 A3（关系第一公民）——关系在图上可查可改可泛化，而非埋在 prompt 里的黑盒；对齐 A10（元认知治理一切可修改）。

**推论**:
- **可操作性 = 可学习性**：用户/元认知的每次操作都是 RL 数据源（A9），白盒把“纠错”变成“训练”；
- **白盒不牺牲一致性**：A17 记录 + A16 不阻断 = 任何操作可回滚可追溯，白盒与一致性不冲突；
- **CLI 数量是白盒的度量**：模块的 CLI 通道数 = 白盒开放度；新增模块必须同步提供 CRUD 通道（否则违背公约）。

### A20. 竞争吸收哲学：不闭门造车，成熟设计点按“来源→映射→代价→优先级”吸收

**来源**: DESIGN_COMPETITOR_ABSORPTION.md（MemWalker / Hermes-Agent / M-FLOW / MRAgent / VeritasGraph 五项目深度阅读，每个吸收点标注来源/映射/代价/优先级）+ 竞争吸收讨论（2026-08-01）

**含义**: 系统的设计不闭门造车——主动深读主流/竞品/开源项目，把成熟设计点以**工程形式**吸收：每个吸收点必须标注“来源→映射模块→实现代价→优先级（P0-P2）”，进入设计管线。这与 A18 的“成熟方案 > 自造指标”是同一原则在架构维度的对应：先学成熟的，再自造缺口。

**要点**:
- **吸收是工程动作，不是理念口号**：已有五项目深读（MemWalker/Hermes-Agent/M-FLOW/MRAgent/VeritasGraph），产出吸收清单（来源追溯独立层、指代消解前置、冲突检测+版本追踪、技能自动创建、Pipeline Trace 结构化输出等）；
- **吸收 ≠ 复制**：每个吸收点必须映射到 DialogMesh 模块并评估代价（极低/中低/中）——增强而非原样搬运（如来源追溯提升为 Context 编译器的独立子模块，约 30 行代码）；
- **优先级 P0/P1/P2 分类**：先补缺口（P0：来源追溯、指代消解前置），再增强现有（P1/P2：冲突检测、Cone Graph 动态检索、因果发现自动化管线）；
- **与省度管控的平衡**：每个吸收点带代价评估，避免为了吸收而胀胀——吸收的是“设计模式”，不是“代码量”；
- **吸收点必须真实验证**：对齐 A18——吸收不是“看起来好”就算，要用真实断言验证吸收后的效果；勾连此前“去查一下学习一下主流设计”的讨论。

**推论**:
- **持续吸收是公约义务**：每次深入阅读竞品/开源，产出“来源→映射→代价→优先级”清单，进入设计管线；
- **吸收计划与实现分层**：设计存在但未独立的先独立，新能力按代价排序实现；
- **与 A19 白盒化对齐**：来源追溯吸收于 VeritasGraph/M-FLOW，本质是把“回答来源可追溯”变成生成阶段就嵌入的信息（[ref:Event_id]）——白盒的另一个落地形式。

### A21. 安全/护栏/权限哲学：约束空间的强制执行（背压/级联/断路 + 权限单调递减 + 沙箱原子性）

**来源**: DESIGN_GUARD_SYSTEM.md（背压控制/级联检测/断路保护）+ DESIGN_PERMISSIONS.md（pledge+unveil+seccomp 权限分级）+ DESIGN_FILESANDBOX.md（Git-staging+OverlayFS+WAL 三模式融合）+ 安全/护栏讨论（2026-08-01）

**含义**: A12 说对象之下是约束空间（合法/可达/禁止）——A21 说约束空间必须在运行时**强制执行**：背压（TokenBucket 每阶段独立限流）、级联检测（根因定位）、断路（保护管线不过载）；权限 pledge promise reduction（can only decrease, never increase）；文件操作走沙箱（snapshot→临时层 COW→diff→review→commit/discard）。约束不是文档里的规则，是运行时的物理力。

**要点**:
- **护栏是约束空间的运行时形态**：A12 定义合法/可达/禁止，A21 执行它——违反约束 → 拒绝/断路/沙箱隔离（Guard 管线钩子：guard.enter/exit 每阶段）；
- **权限单调递减**：promise reduction 只能收敛不能扩张（can only decrease, never increase）——防止权限胀胀的安全第一原则；
- **破坏性操作必须沙箱化**：文件编辑走 snapshot→临时层 COW→diff→review→commit/discard——原始文件永不修改，与 A17 git 式记录同构（快照+diff+可回滚），对象是文件系统；
- **用户审计回调**：review 阶段用户审计（与 A19 白盒化对齐：用户可干预任何破坏性操作）；
- **级联检测定位根因**：5 级健康状态（OK→SLOW→DEGRADED→FAILING→CRITICAL），按连续失败排序找根因，输出级联链——与 A6 自我纠错的运行时对应。

**推论**:
- **安全不是功能，是约束空间的物理强制力**：每个模块设计时要问“违反约束会发生什么”——没有运行时后果的约束是假约束；
- **权限只减不增**：promise reduction 保证安全第一，需要新权限时通过审计流程而非自动扩张；
- **破坏性操作 = 可回滚操作**：任何 write/edit/delete 都必须可 diff 可回滚（git 式 + 沙箱叠加），与 A19 白盒化共同构成“可操作可回退”的完整闭环。

### A22. 因果哲学：因果是约束空间里的稳定投射，不是世界的固有属性（三层递进：粗发现→负向验证→深度确认）

**来源**: BUSINESS_CHAIN_06 §2.7（L5 因果链：伪因果/实因果/晋升路径）+ DESIGN_ASSOCIATION_CHAIN_L1_L4（因果被吸收进关联链顶层 L5）+ ENGINEERING_V3_3_CAUSAL_SUBSTRATE（8 元角色 + structural_prior ≤0.7）+ ENGINEERING_V3_3_DO_CALCULUS（后门准则 HARD_BLOCK）+ THOUGHT_IMPRINT（约束空间投射）+ A12（对象之下约束空间）

**含义**: 因果不是世界的固有属性，而是认知主体在约束空间中做出的投射——当一组约束的稳定性超过观测者的参考框架时，这组约束定义的关系就是“足够好的因果”。因果链经历了演变：最早是独立链（BUSINESS_CHAIN_06 L5：伪因果自发现 conf≥0.7 + 实因果人工标注、键合图/Petri网），后被吸收进关联链（L1-L4 累积证据，L5 因果封顶），再发展出三层递进设计。

**三层递进**:
- **粗发现——CausalSubstrate 因果基地元角色**：8 元角色（SOURCE/SINK/STORE/DISSIPATE/TRANSFORM/JUNCTION）+ 三步映射（约束→候选骨架→匹配度→structural_prior），~20 骨架库，离线预计算 + 在线只读缓存，行为链 >10 步触发；**structural_prior 上限 0.7——永远不说是确定性因果**（第三知识来源，不是第一）；
- **负向验证——do-calculus 后门准则**：只用于验证 HARD_BLOCK（负向排除），不用于发现因果；路径分析 + 混杂因子检查，P(do(x))≥0.95 → HARD_BLOCK，否则 WARN 降级——因果只能用于“排除”，不能用于“断言”；
- **深度确认——键合图/Petri网/系统动力学**：实因果离线深度分析，人工标注确认；晋升路径：伪因果→用户确认→实因果；降级：伪因果→元认知发现矛盾→降级 L4 重新验证。

**推论**:
- **因果是负向工具**：do-calculus 只验证 HARD_BLOCK，不用来发现——因果断言必须克制，宁愿不说是因果也不说错因果（structural_prior ≤0.7 的工程表达）；
- **约束稳定性取代因果必然性**：永远说“在当前约束空间里的稳定性”，不说“因果必然性”（永远 1.0）——哲学判断落到工程参数；
- **因果是证据累积的封顶**：因果是关联链五层漏斗的顶层——从 L1 句法到 L4 时序逐层累积证据，因果是证据链的结晶，不是独立发现；
- **与工程链约束的边界**：约束 ≠ 因果——约束满足是因果候选的必要条件，不是因果本身（L5 用约束满足做伪因果晋升的候选筛选，呼应 A14）。

### A23. 因果检验哲学（学术三层）：溯源置信 → 反事实推导 → 仿真检验

**来源**: 反事实因果讨论（2026-08-01，Pearl 因果阶梯/反事实推理方向）+ THOUGHT_IMPRINT（键合图 0.95 vs LLM 0.3-0.5 的来源可信度差异）+ A20 竞争吸收 P0（来源追溯独立层）+ A22（发现型三层）+ 未实现（设计空白）

**含义**: A22 是因果的“发现型”三层（粗发现→负向验证→深度确认）；真正深层的学术因果是**检验型三层**，目前未实现：

1. **溯源信息层**：对因果断言的来历做置信度评估——来源决定可信度（键合图/Petri 0.95、人工标注 0.9、LLM 推断 0.3-0.5、规则归纳更低），每个断言必须携带来源链；
2. **形式化证明 + 反事实推导层**：对 a→b→c 因果链做完整反事实空间推导——为什么需要 b（中间变量必要性）、a→c 直接如何（省略中间环节）、c→a 是否可行（可逆性）、b→c 单独如何（部分干预）；对应 Pearl 因果阶梯第三层：如果当初没有 X 会怎样；
3. **仿真检验层**：用 matlab 等仿真工具做动态行为检验——把因果链放进仿真环境，验证预测与行为一致（键合图/系统动力学的动态版本）。

**推论**:
- **检验型三层是“未来”，发现型三层是“现在”**：A22 已落 CausalSubstrate + do-calculus，检验型三层是设计空白，需在§9 追加开放点；
- **反事实推导是因果的完备性检验**：不只问“X 导致 Y 吗”，还问“没有 X 会怎样”“反向可行吗”“中间环节必要吗”——因果断言从“一条链”变成“一个结构”；
- **溯源置信是检验的入口**：没有来源链的因果断言不可检验——先验置信度决定值不值得进入反事实/仿真（呼应 A20 来源追溯吸收点 + A18 验证必须真实）；
- **仿真检验是 A18 “验证必须真实”在因果域的实例**：模型推演 ≠ 动态验证，仿真是最接近真实的断言（呼应 A13 长证明后验：多步验证累积）。

### A24. 逆向动力系统哲学：抽象的质量是可逆推性（聚类凝练→规则化→反向推导验证）

**来源**: DESIGN_DERIVATION_COMPRESSION_V2.md（发散→收敛启发链：规则归纳 = 过拟合）+ DESIGN_L5_LONG_TERM_MEMORY.md §4（聚类→归纳规则→逆推验证→多视角调整）+ THOUGHT_IMPRINT.md + 逆向动力系统讨论（2026-08-01）

**含义**: 真正的抽象不是“提取”，是**逆向动力**：把内容聚类凝练成规则（正向压缩），再用规则**反向推出原内容**，验证覆盖率（coverage 60-80%；100% = 过拟合，0% = 没学到）。简单规则归纳从有限采样中提取确定性规则 = LSTM 窗口拟合（高度匹配训练数据、零泛化）——得到的是“感觉对”的规则，不是“对”的规则。

**核心机制**:
- **反向推导验证（可逆推性）**：规则必须能反推回原内容，coverage 60-80%；失败则多视角调整（结构/语义/时序/反例四视角：规则覆盖所有正例吗、解释合理吗、时间稳定吗、排除所有反例吗）；
- **伪二阶抽象（DMN 发散 → ECN 收敛 → 启发链）**：恶盖上下文让 LLM 无约束猜测（发散，产生海量假设），再带上下文筛选（收敛，保留与对齐的假设 + 拒绝理由），最后凝练成可迁移的启发链；
- **远迁移的二级抽象**：卡尔曼/信息论深层统一（方差 vs 深是同一枚硬币）——启发链是可迁移的最小单元；高概率低价值聚类凝练，高价值低概率 RAG 原样保留（呼应 A7 信息论分治）；
- **与 A18 验证必须真实的闭环**：逆推是“真实断言”的抽象版——规则能反推出原内容 = 学到了，反之 = 没学到；与 A17 记录联动：逆推验证的输入是事件链记录。

**推论**:
- **抽象质量 = 可逆推性（P10 升级为公理级）**：压缩产物必须能反演还原，coverage 60-80%（不是 100%，100% = 过拟合）；
- **“猜得到 = 学到”是训练机制：DMN 发散的海量假设 + ECN 收敛的筛选与拒绝理由，本身就是知识边界的学习（什么被拒绝、为什么被拒绝）；
- **聚类凝练与 RAG 保留是分治不是二选一**：高概率低价值聚类凝练，高价值低概率原样保留；逆向动力系统做的是“可压缩部分的可靠压缩”；
- **呼应 A23 溯源置信**：启发链必须携带“来源: 猜测2, 验证通过”的追溯信息，不是无根据的答案。

### A25. 检索召回哲学：召回是重建上下文，不是搜相似（嵌套证据组装）

**来源**: chapter1_conversation_tree.md（HyperMem 超图 + RRF 融合 + waterwave_activate）+ DESIGN_L5_LONG_TERM_MEMORY.md §3（图+RAG 两层检索）+ MEMORY_LANDSCAPE_VS_MAINSTREAM.md（L1-L3 记忆地图）+ DESIGN_TOPIC_TREE_GRANULARITY.md + 检索召回讨论（2026-08-01）

**含义**: 召回不是“搜相似”，是**重建上下文**：检索是嵌套证据组装，不是单点命中。实现形式：waterwave_activate 语义级联检索（粗到细遍历 Topic→Episode→Fact）+ RRF（Reciprocal Rank Fusion）融合 BM25 和稠密向量嵌入 + BGE+token 混合相似度；图+RAG 两层：embedding → 锚点实体 → 图扩散（water-wave）→ 召回“实际发生过关系”的实体，而不是“语义近似”的实体。

**要点**:
- **级联而非单步**：检索是“粗定位→图扩散→组装”的多步过程（Topic→Episode→Fact 粗到细），呼应 A2 颗粒度缩放；高维空间相似 ≠ 因果相关（纯 RAG 的问题）；
- **RRF 融合 = 多信号交叉**：BM25（确定性共现）+ 稠密嵌入（语义相似）+ 图扩散（实际关联）三个信号汇聚——单信号召回都是偏见；
- **回答“BM25 是不是不先进”**：BM25 是召回的第一级粗筛（确定性、可解释、零成本），不是终极方案——它与稠密检索、图扩散是补互层级而非替代关系（呼应 P2：算法与 LLM 是不同颗粒度的投影）——这个问题本身是单维比较的伪问题；
- **召回必须可追源**：EntityNode 自带 evidence_chain，LLM 可回溯来源（呼应 A23 溯源置信 + A19 白盒化）；
- **与 A15 温度联动**：召回是“寒的记忆被语义唤醒回 Hot”的执行机制（BGE > 0.8 直接回 Hot）。

**推论**:
- **召回即证据组装**：上下文编译是把召回的证据按关系组装成快照（A3 关系 > 提示词），不是拼接证据串；
- **召回质量由验证定义，不由指标定义**：呼应 A18——召回的好坏靠“召回的东西能不能推导出答案”验证，不靠 recall@k 指标；
- **算法召回与 LLM 召回分工**：算法召回负责确定性粗筛与图扩散（快、可解释），LLM 召回负责语义完备性与缺失补全（慢、象征性），不互相替代（呼应 P2）。

| P21 | **参数自适应闭环**：参数编码 + 测试基线 + 反馈步长/最值范围 + 用户/元认知/行为三重调节 | A18 |
| P22 | **白盒化**：所有模块内容对用户/执行层/元认知可查可改可增可删，操作必记录；新增模块必须提供 CRUD 通道 | A19 |
| P23 | **竞争吸收**：主动深读竞品/开源/主流项目，每个吸收点按“来源→映射→代价→优先级”进入设计管线，吸收≠复制，必须真实验证 | A20 |
| P24 | **护栏与权限是约束空间的强制执行**：背压/级联/断路运行时保护；权限只减不增；破坏性操作必须沙箱化（可 diff 可回滚） | A21 |
| P25 | **因果克制**：因果是约束空间里的稳定投射，永远说“稳定性”不说“必然性”；structural_prior ≤0.7；do-calculus 只做负向 HARD_BLOCK 验证不做因果发现 | A22 |
| P26 | **因果检验（学术三层）**：因果断言必须过三层检验——溯源置信评估（来源链决定可信度）→ 反事实推导（必要性/可逆性/部分干预）→ 仿真检验（matlab 等动态验证）；未实现前不宣称深层因果 | A23 |
| P27 | **抽象质量 = 可逆推性**：聚类凝练→规则化→反向推导验证（coverage 60-80%，100% = 过拟合）；DMN 发散→ECN 收敛→启发链；抽象必须携带溯源 | A24 |
| P28 | **召回是重建上下文不是搜相似**：嵌套证据组装（级联检索 + RRF 融合 + 图扩散）；召回必须可追源；算法召回与 LLM 召回分工不替代 | A25 |

## 4. 信息论根：Shannon × 卡尔曼 × DMN-ECN

### 4.1 Shannon 自信息 → 分治

```
I(x) = -log₂ P(x)

"又日常写代码了"      出现100次 → P≈1.0 → I≈0   → 压缩
"服务器崩了找不到根因" 出现1次   → P≈0.01 → I≈6.6 → 保留
"忘记查SQL执行计划"    出现2次   → P≈0.02 → I≈5.6 → 保留
```

存储决策（L5 §2.2）:
```
P(高) + I(高) → RAG 原样保留（密码/罕见 bug）
P(高) + I(低) → DerivationCompressor 压缩成规则
P(低) + I(高) → RAG（关键：罕见≠无关）
P(低) + I(低) → indexed only, no content
```

### 4.2 卡尔曼滤波 → 低概率事件的判断

```
K = 预测误差 / (预测误差 + 观测误差)

对象精确性高（预测误差→0）时：
  大偏差观测 → 两种来源：
    a. 传感器误差区间估计（决定该传感器的 R）→ 低权重抹平
    b. 真实状态突变（新信息）→ 高价值定位
  判断依据: 能否被现有模型解释
```

### 4.3 DMN 发散 / ECN 收束 → 伪二阶抽象

```
发散（DMN）: LLM 无上下文猜测 (temperature=0.8) → K 个假设
  → 掩盖上下文, 迫使 LLM 调取预训练知识, 产生发散性假设
收敛（ECN）: LLM 带上下文筛选 (temperature=0.1) → 验证/驳回
  → 证据约束推理, 保留对齐的假设, 给出拒绝理由
启发链: 模式 + 适用条件 + 反例 + 推理路径 → 可逆推的压缩产物
```

**为什么叫"伪二阶抽象"**: 不是"再抽象一次"，而是**通过逆推验证（规则能否反演还原内容）来检验抽象质量**——抽象的定义从"概括程度"变成"反演能力"。直接规则归纳 = 过拟合（LSTM 窗口拟合）；发散→收敛→启发链 = 可逆推的泛化。

## 5. 公理冲突裁决元规则（真冲突时谁优先）

大部分“冲突”是伪问题（§6：分工/步长/多因子），但真冲突时按以下元规则裁决：

1. **体验不阻断 > 单次准确**：用户立即得回答是先于单次答案精度（A16）；
2. **真实验证 > 指标好看**：不存在完美量化标准，自适应效果以真实断言为准（A18）；
3. **安全约束不可协商**：护栏/权限/沙箱的限制不因功能需求而松动（A21）；
4. **记录永不可删**：事件链/修改记录不因“干净”而清理（A17）；
5. **兑底：回到约束空间**：裁决看哪个选择违反更少的约束（A12），而不是看哪个“更好听”。

## 5.1 范式应用示例：PCR 重新定位

> 详细重设计在 PCR 相关文档进行，此处只示范"范式如何改变模块定位"。

### 5.1 旧定位（范式缺失）

```
用户输入 → PCR(5阶段统计特征) → 一个坐标点 + zone → 下游路由
```

- 单颗粒度：X/Y/Z 在**一个缩放级别**里算统计特征（词数/实体数/情感词）；
- 无参照：从零猜（形态学启发式），不用 RAG 相似确切参照；
- 无先验：画像反哺链路断（BUSINESS_CHAIN_08: "PCR 信号 ❌ 未接入"）；
- 无后验：判断完就完了，没有用户反馈回流。

### 5.2 新定位（范式内）

```
用户输入 = Event
  │
  ├─ 一级视角: PCR 的意图/认知视角（模块固定职责）
  ├─ 信息论分治:
  │    P(高)      → 聚类凝练的规则快路径（启发链检索, 可逆推验证）
  │    P(低)+I(高) → RAG 定位相似确切参照（锚点 → 图扩散 2 跳）
  ├─ 二级视角验证: 结构/语义/时序/反例 → 失败 → 多视角调整
  ├─ 画像先验（Profile TrackA 反哺）→ 认知偏置
  └─ 产出 Observation 集合（不是结论）→ 下游 Hypothesis 竞争
  ▼
负向反馈：用户纠正/执行结果 → 修正回流 → PCR 后验学习
```

**关键转变**:
- 从"一个坐标点" → "一级视角 + 颗粒度递归（规则快路径 / RAG 精定位）"；
- 从"算法 vs LLM" → "信息论分治：高频走规则，低频走 RAG+LLM"；
- 从"维度孤立" → "每个维度挂在一级视角下，用二级视角（结构/语义/时序/反例）验证"；
- 从"零猜测" → "RAG 相似参照 + 画像先验 + 可逆推启发链"；
- 从"一次算完" → "后验学习，修正回流"。

## 5.2 公约自验证（公约如何验证自己）

公约也是一份“感觉上不错”的设计，需要过 A18 自己的关：

- **黄金样例：用公约重判历史设计错误**（PCR 三个实质问题：阈值一致性、子图接口、route 签名鸡生蛋）——公约能指出这些问题，才算过关；
- **模块范式对齐检查表（§8 索引的扩展）**：每个新模块设计先回答三个问题：我在哪一层？我产出 Observation 还是结论？我的判断用了哪些参照/先验，错误后如何回流？（§0 三个问题的强制应用）；
- **反例验证：每条公理找一个违背案例**：做不到的公理要么修正、要么标注“理想状态”。
