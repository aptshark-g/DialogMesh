## 一、核心概念（用户确认后的修正理解）

1. **启发 = 决策依据, 与约束同构** — 不是动作模板（skill 回答"怎么做"）,
   而是判断准则（"该不该做、用什么道理判断"）。像 engineering 约束一样
   **注入上下文**, 出现在所有决策处（规划/工具选择/压缩/元认知）。
2. **二阶抽象 = 把我们已依赖的模式形式化** — "决策时去 wise/ 查哲学公理"
   本身就是启发库存调用（wise = 手写种子启发）。管道是把这个模式自动化:
   从行为长出新公理, 与手写公理同路注入。
3. **掩盖/发散 = 部分信息猜测家族（远迁移思想）** — 不是"隐藏实体名",
   而是主动在信息缺失处构造假设（前向/反向/共性找底/远迁移类比）。
4. **触发 = 变化驱动** — 决策不合理 / 失败 / 公理冲突 / 缺公理感 /
   启发过时 → 触发再抽象; 定时蒸馏仅兜底。
5. **反推验证原料 = 全模块** — 行为链 / 对话树 / 意图 / 执行轨迹 /
   wise 哲学都是资料; 验证 = "启发能否解释历史决策"。
6. **LLM 必须** — 发散/收敛/反推都是 LLM 调用（temperature 切换先验/后验）;
   规则聚类仅冷启动兜底（无 LLM 时）。

## 二、远迁移文献基础（发散变体的理论依据）

| 文献 | 核心 | 对本设计的启示 |
|---|---|---|
| Gentner (1983) 结构映射 | 类比 = 关系系统对齐, 不依赖表面相似 | 远迁移发散 = 结构对齐: 找"关系同构"而非表面相似; 掩盖应针对**关系维度** |
| Gick & Holyoak (1980/83) | 类比问题解决: 源情境→目标情境映射; 显式提示显著提升迁移 | 收敛时**暴露结构线索**（提示"AB 经验与 C 的关系结构"）可大幅提升迁移率 |
| Barnett & Ceci (2002) | 远迁移分类学: 知识类型 × 情境维度（内容/物理/时间/功能/社会/形态） | 掩盖变体家族 = 沿不同情境维度部分掩盖（时序/功能/形态…） |
| Holyoak & Thagard (1989) | 约束满意类比: 结构/语义/实用三约束 | 收敛筛选用三约束: 结构一致 + 语义相关 + 实用可行 |

**发散变体家族（操作化）**:
```
前向掩盖  给 B,C 猜 A        （缺前置机制）
反向掩盖  给 A,B 猜 C        （缺后果/应用）
共性找底  给 A,B（表面不同）找共同机制   （结构对齐, Gentner）
远迁移    带 A,B 经验尝试对应 C          （跨情境映射, Gick & Holyoak;
          收敛时暴露结构线索提升迁移率, Barnett & Ceci 维度）
```

## 三、机制设计

### 3.1 HeuristicInventory（启发库存）
- 启发单元 = **四元组**: `pattern_desc`（模式描述）/ `conditions`（适用条件）/
  `counterexample`（反例）/ `reasoning_path`（推理路径）
  + belief: `coverage / support / insight_score / ts / source / active`
- 存储: 独立库存（内存 + JSON 持久化 data/heuristics.json）
- **注入**: 决策点（executor 节点执行前 / llm_reply 上下文构建时）检索 top-K
  相关启发 → 与 engineering 约束并列注入 system prompt
- **种子 ≠ 公理清单**（用户修正 2026-08-07）:
  - wise 公理 A1-A25 是**项目内提炼产物**（目标形态）, 不是种子 —
    当种子会自我印证闭环（公理→种子→从行为提炼→印证公理）
  - 种子 = **认知结构模板 + 示范种子（few-shot）+ 质量判据**
  - 结构模板: **现象 → 起源（机制） → 边界条件 → 操作化** —
    用结构驱动抽象化, 而非"一拍脑袋编公理"
  - 示范种子: 不是当公理注入, 而是给 LLM 看"启发该长什么样"
    （生成规范样板）

### 3.1.1 种子理论（2026-08-07 用户深化）

**质量判据: 锚定形式科学约束空间**
```
启发是否锚定形式科学（逻辑/集合/映射/图/概率公理）?
  锚定越深 → 约束空间有限且完备 → 可迁移性越高, 过时风险越低
  工程格言（YAGNI）锚定领域经验 → 会过时
  排中律 / 映射形态（多对一·一对一·一对多·多对多）→ 不会过时
```

**示范种子（few-shot 样板, source="seed"）**:
```
① 差异即信息（完整链）:
  现象:   差异即信息
  起源:   差异源自比较 — 孤岛（无参照）时关系从比较中产生;
          没有参照, 差异无意义
  边界:   哪怕内禀视角本身也是一种参照（没有绝对, 只有参照系）
  操作化: 统一化相对化 — 把绝对断言转成相对断言（相对参照系）,
          看似矛盾即可统一（例: 卡尔曼 vs 信息论统一于"能否被
          现有模型解释"）
② 共性边界即分类（完整链）:
  现象:   分析共性边界 = 分类
  起源:   共性是某参考维度下的性质, 边界也在此维度下探讨
  边界:   分类可追溯到排中律（A 或非 A）— 完备互斥是准确性源头
  揭示:   底层性来自锚定形式科学约束空间 — 映射关系（多对一/
          一对一/一对多/多对多）就这么几种可能; 对形式模型的
          研究再研究（自指）= 递归抽象, 使内容深且抽象
```

**结构模板 = 提炼管道的输出规范**: 发散/收敛产出的启发必须符合
"现象→起源→边界→操作化"完整链（自带 reasoning_path）。

### 3.2 HeuristicDistiller（变化驱动的提炼管道）

**触发（事件驱动, 定时兜底）**:
```
决策失败/异常   （executor error_pattern / T6 归因）
公理冲突         （决策事件冲突）
用户纠正         （行为链 user_correction）
启发活性检查     （stale / coverage 跌破阈值）
缺公理感         （元认知建议 / 决策后"不合理"反馈）
定时兜底         （沿用蒸馏间隔, 阈值提高 trace≥10）
```

**管道（掩盖/暴露/反事实/验证）**:
```
1. 取材:    全模块决策样本（执行轨迹/行为链/对话树/意图/wise 公理）
2. 发散:    部分信息猜测家族（前向/反向/共性/远迁移, temp=0.8, K=3-5）
            → 候选启发（含反例式候选）
3. 收敛:    暴露全上下文（temp=0.1, 结构线索提示）→ 筛选 + 拒绝理由
            （拒绝理由 = 知识边界）+ insight_score
4. 反事实:  低 coverage 高 insight → 构造"若启发为真→哪些行为该变"
            → 全模块找证据连接 → 命中升级 / 未命中降级（拒绝理由保留）
5. 反推验证: LLM 采样 20-30 条历史决策 → 判断启发能否解释 → coverage
            60-80% 合格; 100% = 过拟合拒绝; 0% = 幻觉拒绝
6. 沉淀:    合格启发 → HeuristicInventory（注入通道就绪）
7. 监测:    活性/冲突 → 再触发（元认知通道, M5 已通）
```

**无 LLM 降级**: 规则聚类兜底（现有 DistillationEngine 路径保留, 标记
source="rule"）— 仅冷启动。

## 四.5 P×I 路由修正（2026-08-07 用户深化, 施工前定案）

**质疑**: "低概率只靠出现次数是不是太粗糙了？" — 只出现 1 次的垃圾与
只出现 1 次的根因分析, 统计频率相同但价值天差地别。

**修正**: P×I 中的 I（信息价值）由 **LLM 语义评估**, 不是统计频率。
且与冷热系统互补（正是 ColdIndexer importance 三信号的用意）:

```
冷热系统（tiered_storage / G2 EventBus 温减枝）:
  activation_count（频率加权） + recency（近期性） + semantic_value（语义价值）

信息论路由（本管道, 修正后）:
  P = activation_count（统计频率, 冷系统维度）
  I = semantic_value（LLM 评估: 新颖性/可迁移性/是否揭示机制）
  recency 可作辅助（近期出现的高价值更值得保留）
```

**路由规则（修正后）**:
```
P(高)             → aggregate（高频凝练, 规则/模板）
P(低) + I(高)     → preserve（低频高价值, 深路径保留）
P(低) + I(低)     → filter（低频低价值, 过滤 — 不因稀有而保留）
P(中)             → filter
```

**实施落点**:
- LLM 路径: 收敛步骤（_converge）让 LLM 对候选显式评 `information_value`
  （语义价值, 0-1）→ 参与保留/沉淀决策
- 规则兜底（无 LLM）: 意图熵 + 序列新颖度作 I 的代理（非纯计数）
- `_info_route(frequency, semantic_value, intent_count)` 三参数路由

## 五、验收

- 无 LLM: 管道降级规则聚类, 不破坏现有蒸馏
- mock LLM: 发散产出四元组候选; 收敛保留+拒绝理由; 反推验证 60-80% 判定;
  合格启发进库存; 注入格式化含公理+启发
- 生产: 变化触发（失败/纠正）调用管道; 库存持久化
