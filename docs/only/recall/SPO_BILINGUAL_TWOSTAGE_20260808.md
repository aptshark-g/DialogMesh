## 〇、背景（实测驱动）

- 黄金集: SPO 单路 top1 22.5% 最弱; 词典归一无增益 → 需要语义归一
- GLiNER multi-v2.1 实测:
  - SPO 角色标签（subject/predicate/object）中英都无效
  - 泛化标签（concept/method/person）**英文远优于中文**（英文结构严谨,
    实体边界清晰; 中文长句整句框错）
  - 谓词（动词）两种语言都抽不出（GLiNER 只抽名词短语）
- HyDE/LLM 挑选受限于粗召回天花板 → 提升源头在 SPO 提取/对齐

## 一、方案（用户拍板: 两阶段, 加映射层）

```
阶段1 语法拆解（现成工具, 不用训练）:
  英文: GLiNER(concept/method/person) 抽主宾 + 规则/依存抽动词
  中文: Stanza 依存树 → S/V/O（现有）
       ↓
阶段2 抽象关系映射（轻量, 可训练）:
  谓词归一: 开放动词 → 抽象关系类型（约束空间投影）
  主宾对齐: 语法角色 → 规范 SPO
```

## 二、为什么两阶段优于端到端蒸馏

1. 阶段1 是通用能力（语法拆解现成模型强, 尤其英文）, 不浪费
2. 阶段2 是领域能力但**数据需求极小**: 映射是"结构→结构"
   （动词类别 → 关系类型）, 不是"文本→结构"生成; 可规则词典先行
3. **可解释、白盒（A19）**: 哪个动词归哪类可审计, 非黑盒
4. **补 GLiNER 的洞**: GLiNER 抽名词短语, 映射层输入 = 动词 + 主宾, 分工干净
5. **A12 约束空间的工程形态**: 开放谓词收敛到约束空间关系类型,
   "对象之间关系 = 转化投影"的落地

## 三、抽象关系类型集（草案, 15-20 类, 待细化）

| 类型 | 中文动词例 | 英文动词例 |

| 转化(transform) | 变成/转为/升为 | become/turn into |

| 允许(allow) | 允许/可以/可 | allow/can/permit |

| 对立(oppose) | 对立/矛盾/相反 | oppose/contradict |

## 六、与 SPO-C 蒸馏的关系

## 七、软编码 + LLM 泛化（2026-08-08 用户拍板）

> 用户: "为什么不做软编码? 可拓展; 带映射内容给 LLM, 让 LLM 帮挑未覆盖范围"

### 问题: 硬编码谓词表永远补不完（开放谓词无限）

### 设计: 种子缓存 + LLM 泛化 + 反馈闭环（A18）

```
map_predicate(pred):
  1. 查硬编码种子表 → 命中返回（快路径, 白盒）
  2. 查会话内 LLM 判定缓存 → 命中返回
  3. 未命中 → LLM 判定（网关, 慢路径）→ 返回 + 记录未覆盖谓词
  4. 未覆盖谓词池 → 离线补表原料
```

### 两种 LLM 用法

**离线补表（便宜, 定期）**:
- 收集未命中谓词池 → 一批给 LLM 审阅 → "这些动词归哪类? 新增哪几类?"
- 建议并入映射表（人工/自动确认后落表, 白盒可审计 A19）

**在线判定（未命中时, 慢路径）**:
- 单个谓词未命中 → LLM 判 "调节" → regulate → 会话内缓存
- 命中率反馈回流（A6）

### 与 A18/A6 对齐
- 映射表 = 可增长的学习参数（越用越全）
- 词典 = 缓存, LLM = 泛化, 反馈 = 增长动力
