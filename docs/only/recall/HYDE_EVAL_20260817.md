# 真 HyDE 进评测 — 泛化性设计 + 全量实测 + 研究对照（2026-08-17）

> 触发: 交接 P0 "真 HyDE 进评测"; 用户问 "如果这是手动标准是不是无泛化？
> 需要设计对应算法？有类似的研究吧？"
> 结论先行: ①HyDE 的 prompt 是通用零样本模板（非评测集特调, 与论文
> 一致）— 泛化性问题不在 prompt, 而在**语料特性**; ②全量实测（同语料
> 对照）: K=3 RAG-Fusion 形态 doc +3.3pp 但 dialogue -7.7pp（净负）,
> K=1 生产形态全负 — 假设文档无法复现本项目自指语料的内部精确词汇;
> ③研究指向正解: HyDE 生成文档应做 **BM25 稀疏词项扩展**（Rocchio,
> Revisiting Feedback Models for HyDE, arXiv 2511.19349）— 本语料
> bm25 是强信号（B 类命中全来自 bm25）, 而非替换/叠加向量。
> 方法: A18 消融驱动; eval_100 新增 --hyde 模式（真网关 LLM）; 每项
> 结论带同语料数据。

## 一、泛化性回答（用户问题）

**"手动标准无泛化"的担忧不成立于 prompt, 成立于是语料**:

1. HyDE 原论文（2212.10496）就是**一个固定通用 prompt 跨所有 BEIR 数据集**
   （"Write a hypothetical passage that answers the question"）, 零样本,
   不做任何评测集调参。我们实现的 `HYDE_PROMPT` 同样固定、只含 query、
   不接触语料与评测标注 — 这是泛化算法, 不是手写标准。
2. domain-aware 指令（"像项目内部设计文档片段"）是**按语料域给指令**
   （论文对 Wikipedia 语料也用 Wikipedia 风格指令）, 属于通用技术。
3. 真正的泛化失败发生在**自指语料**: 本项目 ~625 篇设计文档是自指的
   （术语内部化: TaskRunner / statemachine / params.agentic / zone→intent
   等）, LLM 从 query 生成的假设文档**无法复现这些内部词汇**, 假设向量
   只能命中"主题相邻"的通用文档 → 漂移。这不是 prompt 能修的问题。

## 二、类似研究（2026-08-17 检索, 有原文依据）

| 研究 | 核心 | 对我们的意义 |
|---|---|---|
| HyDE（2212.10496） | query→LLM 假设文档→编码→检索; BEIR 零样本提升 Contriever | 基线方法; 我们已按此实现 |
| **Revisiting Feedback Models for HyDE（2511.19349）** | HyDE 文档 + **Rocchio/RM3 反馈模型**做 BM25 稀疏词项扩展, 显著优于"简单字符串拼接" | **正解方向**: 本语料 bm25 是强信号; 用假设文档提取/加权扩展词喂 BM25, 而非动向量 |
| RAG-Fusion（多查询 + RRF） | 生成多查询各自检索, RRF 融合 | 我们 K=3 形态即此; 实测 doc 有效、dialogue 负 |
| Query2Doc（Jagerman 2023） | few-shot 伪文档拼接原 query（稀疏/稠密策略不同） | 稀疏侧拼接可作 BM25 扩展的参照 |
| HyPE | 生成假设 prompt 而非文档 | 假设形式可替换（备选实验） |
| AutoMIR / SL-HyDE | 用检索反馈自学习迭代 HyDE | 有反馈数据后可做 |
| SAGE / Adaptive Hybrid（RECALL_MAINSTREAM_GAP 已引） | 按查询难度动态选 k/融合 | 门控的理论依据（我们已实现 DM_HYDE_GATE） |

## 三、实现（评估工具 + 算法 + 3 个真 bug 修复）

### 3.1 eval_100 --hyde 模式
- `scripts/eval_100.py --hyde`: 注入 `_EvalGatewayAdapter`（直连 8080
  网关 deepseek-v4-flash, thinking 关闭, 失败快速降级）; `use_hyde=True`;
  环境变量 `DM_HYDE_K`（1=单假设 / 3=多假设）/ `DM_HYDE_GATE`（向量
  置信门控）/ `DM_HYDE_DECOMPOSE`（隔离旧查询分解路径）。
- 评测适配器与生产 `_GatewayLLMAdapter` 差异: 不依赖 ExecutionGovernor
  熔断状态（评测不被生产断路器影响）、失败返回 ""（HyDE 降级如实记录）。
  **算法同源**: prompt/多假设/RRF/门控全在 recall_service, 生产与评测
  共用同一份代码。

### 3.2 recall_service 算法（泛化设计）
- `HYDE_PROMPT`: 固定通用 + 域导向（设计文档片段）。
- `_hyde_hypotheses(query, k)`: 温度梯度 [0.0, 0.5, 0.9] 采样 K 个假设。
- `_vector_multi_anchors`: 原 query + K 假设向量各自检索 + RRF 合并,
  产出为 vector 源命中（RAG-Fusion 形态, 不被当独立 "hyde" 源埋掉）。
- `DM_HYDE_GATE`: 向量 top-1 ≥ 0.70 时跳过 HyDE（防漂移破坏高置信 query）。

### 3.3 顺带修的真 bug（生产硬化）
1. **SemanticEncoder._init 联网挂起**（`local_files_only=True`）: 评测
   触发首次 HyDE 时 from_pretrained 对本地快照仍发 HF HEAD 检查, 受限
   网络无超时挂起（交接经验 #3 的纪律此前未应用到编码器本体）。
2. **SPO 谓词 LLM 判定爆炸**（`spo_relation_map` 加 50 次进程级预算）:
   `_spo_anchors` 对每个未覆盖谓词调 LLM（max_tokens=16）, 评测注入 LLM
   后单 query 触发上千次网关往返（实测挂起 10 分钟+）。语义归一只是
   加分项, 预算耗尽回退字面兜底（A16 不阻断）。
3. **generate 返回约定兼容**（`_chat_once`/`_expand_questions*`）:
   适配器返回纯字符串 vs GenerateResult.text 两种约定现在都支持。

## 四、全量实测（同语料对照, eval_100, 2026-08-17）

| 配置 | doc top1 | doc MRR | doc nDCG | dialogue top1 | dialogue MRR |
|---|---|---|---|---|---|
| **baseline（当前默认）** | **50.8%** | 0.618 | 0.653 | **76.9%** | 0.833 |
| HyDE K=1 + gate（生产形态） | 41.0% | 0.507 | 0.530 | 69.2% | 0.751 |
| HyDE K=3 + gate（早期, 无隔离） | 45.9~54.1%（跨轮方差 ±4pp） | — | — | 69.2~76.9% | — |
| **HyDE K=3 + gate + 域门控 + SPO 隔离（干净对照）** | **50.8%** | 0.604 | 0.627 | **76.9%** | 0.833 |

**两个测量混淆（早期数据不可信, 已修复）**:
1. **SPO 谓词 LLM 判定**: 注入 svc._llm 供 HyDE 后, `_spo_anchors` 的
   `set_llm` 让 SPO 也走 LLM 谓词归一 → dialogue SPO 打分改变 → 假
   "dialogue 回归"。修复: `DM_SPO_LLM_JUDGE=0` 隔离（评测与静态基线对齐）。
2. **会话 query 被 cold 文档池 HyDE 污染**: goldset（会话）服务的 cold
   池是全局文档池（doc 占比 1.0）, 会话 query 也被注入 hyde 文档命中 →
   非确定 dialogue 波动。修复: 域门控提升到 query 级（`_hot_is_doc` —
   hot 池是会话域则完全禁用 HyDE, 含 cold 注入）。

**解读（干净对照）**:
- K=1（假设文档替换原 query 向量）: 全负 — 假设漂移污染整个 vector 路。
- K=3 干净对照: **doc top1 = 基线（50.8%）, MRR -0.014; dialogue =
  基线（76.9%, MRR/nDCG 完全一致）** — 无增益。早期 +3.3pp 是
  假设生成方差（temperature 0.5/0.9 采样跨轮 ±4pp）内的运气, 非稳定
  效果。
- **结论: HyDE（向量侧, 单/多假设）在本自指语料上无可靠增益** —
  `DM_HYDE` 默认 0 维持; 域门控 + SPO 隔离保留（让任何未来 hyde 实验
  不会被混淆/污染）。

## 四.5 HyDE→BM25 词项扩展（论文正解方向, 实测负）

实现 `_bm25_hyde_anchors`: 假设文档提取 tf×idf 加权扩展词（停用词 +
df>25% 过滤）→ 独立 BM25 检索 → 与原 BM25 RRF 融合（近似论文
2511.19349 的 Rocchio 反馈; Rust kernel 不支持词项权重, 用 rank 融合）。
**冒烟+消融: 负** — 假设文档的通用脚手架词（Tool/进行/结果/机制…,
过滤后仍）检索到通用工具设计文档, 挤掉多向量的弱增益（q002: BM25 off
rank13 → on None）。根因同向量侧: 假设文档无法复现语料内部词汇。
`DM_HYDE_BM25` 默认 0, 开关保留（换 Query2Doc 拼接 / 微调生成方式可
重测）。

## 五、附带发现: 评测语料自污染（重要）

上一轮新增的 RECALL_FUSION_ABLATION / 交接文档进入了 doc 语料
（docs/ 递归收录）— 这两篇恰好讨论"评测/基线/复跑/PCR zone/召回策略",
压过原期望块, 导致基线 doc top1 从 54.1%（语料变更前）漂到 50.8%
（语料变更后）。提交版代码跑同一现状语料也是 50.8% — **不是代码回归,
是语料漂移**。这正是评测集内置"文档漂移检测"要抓的现象; 基线必须
锚定当前语料（50.8%）, 换语料要重定基线（A18: 基线可复现）。

## 六、未来方向（按研究排序）

   **已交付: `DM_SPO_LLM_JUDGE`**（隔离 SPO 谓词 LLM 判定, 修测量混淆）。
   这两个是净正的架构改进, 与 hyde 是否启用无关。
3. P2: Query2Doc 稀疏拼接对照; HyPE 假设 prompt 形式; SL-HyDE 自学习
