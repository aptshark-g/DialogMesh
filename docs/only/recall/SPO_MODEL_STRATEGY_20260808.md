## 〇、问题定义（用户拍板）

对语法拆解（SPO 提炼）做**专门的微调模型**, 替代/增强现在的"语法树算法",
把它作为召回底座（层1 结构增强）的引擎。问题: **微调模型会比语法树算法好吗？**

判别标准不是解析 F1, 而是: **SPO 结构对齐对召回的增益, 在微调模型下是否显著提升**
（A18: 数据可知、快速实验可判——这是它和二阶抽象的根本区别）。

---

## 一、现状核查（离线实测, 2026-08-08）

当前 SPO 提炼 = `core/agent/discourse_block_tree/syntactic_decomposer.py` 三层管线:

```
层1 Stanza 依存树 (grammar_tagger → subject/verb/object)   ← 通用预训练神经模型
层2 jieba POS 兜底 (v/vn→谓语, n→主/宾)                     ← numpy 坏环境降级
层3 正则兜底 (英文 camelCase / 代词)                          ← 结构性最后手段
```

**真正的瓶颈不在提取, 在对齐**（`recall_service._spo_anchors`）:
- 对齐 = **字面精确匹配**（谓词 0.5 / 主语 0.3 / 宾语 0.2, 字符串相等才得分）
- "怎么做" vs "如何实现" vs "steps" 永远对不上 → 语义归一为零
- 指代/省略补全只有轻量代词闭环（最近主语替换）, 无真正先行词解析

→ 微调模型的最大价值 = **语义归一 + 鲁棒提取**, 不是"解析更准"本身。

## 二、文献证据（2026-08-08 联网查证, clash 代理）

| 论文 | 年份 | 核心结论 | 与本策略的关系 |
|---|---|---|---|
| APRCOIE "Rules still work for OpenIE" (arxiv 2403.10758) | 2024 | 中文 OIE 规则路线仍有效, 但已进化到**自动模式生成**（非手工词典）+ tensor 过滤加速 | 规则没死, 但"自动生成规则"才是出路; 支持混合路线 |
| OpenIE6 (arxiv 2010.03147) | 2020 | 神经 OpenIE SOTA: 迭代网格标注, 10x 快于序列生成 | 神经抽取基线: 结构化输出可行且快 |
| milIE (arxiv 2110.08144) | 2021 | **规则系统与神经端到端可无缝集成**, 迭代先易后难抽取 | 直接支持"规则+微调模型"混合, 不二选一 |
| MetaIE (arxiv 2404.00457) | 2024 | LLM prompting 打不过**小 LM 在小数据集微调**; label-to-span 元理解可适配所有 IE | 蒸馏小模型路线可行, 且数据需求小 |
| UniversalNER (arxiv 2308.03279) | 2023 | ChatGPT → 小模型 targeted distillation, open NER 接近原 LLM | 蒸馏成本收益实证 |
| GLiNER multi-task (arxiv 2406.12925) | 2024 | 小 encoder 多任务 IE 达 SoTA, 结构化输出稳定（LLM 反而常 fail 结构化） | **首选架构候选**: 小、稳、结构化 |
| DeepStruct (arxiv 2205.10475) | 2022 | 结构预训练（任务无关语料→生成结构）, 28 数据集 10 结构任务零样本迁移 | "结构理解可预训练" = A12 约束空间的模型侧实证 |
| 临床 IE 蒸馏 (arxiv 2501.00031) | 2024 | BERT 蒸馏比 LLM 小 ~1000x, 临床 NER 效果可比 | 蒸馏成本下界实证 |
| RUIE (arxiv 2409.11673) | 2024 | Retrieval-based Unified IE using LLM | 检索+抽取一体化的最新形态 |

**结论性信号**:
1. 规则路线在中文上仍有竞争力, 但必须是"自动生成模式"而非手工词典（APRCOIE）
2. 小模型微调（尤其蒸馏）在 IE 上**系统性赢过 LLM prompting**（MetaIE）
3. 规则与神经**可无缝混合**（milIE）——不是非此即彼
4. 小 encoder（GLiNER 式）在结构化输出上比 LLM 更稳、更快、更便宜
5. 结构理解可以预训练（DeepStruct）——与我们的 A12 约束空间哲学同构

## 三、初步判别（基于文献, 待实验确认）

**微调模型会比语法树算法好——但要选对架构和用法:**

```
赢的维度（文献支撑）:
  语义归一   同义谓词/宾语合并（"怎么做"≈"如何实现"）→ 对齐从字面升语义
  鲁棒提取   口语/省略/跨语言 → Stanza/jieba 的短板正是微调模型的长板
  结构化稳定 小 encoder 结构化输出稳定, 不漂移（GLiNER 实证）

输的维度（成本）:
  冷启动     需要标注/蒸馏数据（→ LLM 蒸馏缓解: UniversalNER/MetaIE）
  可解释性   微调模型内部是黑盒（→ 白盒靠输出层 SPO + 溯源置信度兜住, A19）
  延迟       CPU 推理新增几 ms ~ 几十 ms（→ 小 encoder 可接受）
```

**关键取舍**: SPO 是 0.85 置信度的一路信号。微调的价值上限 =
这路信号从"字面匹配"升到"语义匹配"带来的**召回增益**, 必须用黄金集量化。

## 四、候选路线（三条, 成本递增）

| 路线 | 做法 | 成本 | 风险 |
|---|---|---|---|
| A. 规则增强 | 自动模式生成（APRCOIE 式）+ 同义词典归一（谓词/宾语合并表） | 低（纯代码+词典） | 词典覆盖有限, 口语仍弱 |
| B. 小模型微调 | GLiNER 式 encoder, 用现有块/EDU 数据标注 SPO, 本地微调 | 中（需标注 ~500-2000 条） | 标注质量决定上限; 需 GPU/训练管线 |
| C. LLM 蒸馏 | 网关 LLM 标注 SPO 训练集 → 蒸馏成小模型（UniversalNER 路线） | 中高（LLM token + 训练） | 蒸馏漂移; 但与 A6 反馈闭环天然契合 |

## 四续、2026-08-08 用户拍板 — A+C 混合, 职责分离三引擎架构

> 用户: "ac混合吧" + "语法抓重要性做锚点, 无 LLM 也有 RAG 基本盘;
> LLM 做锚点外图搜索后的选择 + 初始召回的选择混合; 多锚点; 小模型筛选核心给子图"

**架构（职责分离）**:

```
语法引擎(传统算法, 无 LLM)  → 重要性信号 → 多锚点(SPO 三元组)
      ↓
RAG 底座(向量+BM25) + 锚点图扩散(k-hop, 多锚点合并) → 候选集
      ↓
小模型筛选核心(蒸馏 0.5-1.5B) → 给子图
      ↓
LLM 挑选(初始召回 + 图搜索后两处选择混合) → 最终
```

**重要性信号量化**（语法引擎产出, 不依赖 LLM）:
- SPO 三元组完整性（有主谓宾 > 碎片）
- 谓语 = 意图核心（A12 状态转化动作）
- 实体密度（专有名词/术语）
- 否定/疑问标记（反模式高价值, A14）

**关键决策**:
- 微调模型的目的 = 语义归一 + 鲁棒（Stanza 已支持中文,
  `grammar_tagger.py:83-84` 即 zh pipeline; 微调不为语言支持, 为对齐升级）
- 无 LLM 基本盘 = 词法(BM25) + 结构(SPO 锚点); LLM 只介入选择/精筛（A16 快反馈）
- 硬件: RTX 3080 16GB 移动端, 7B QLoRA 可调但重; 蒸馏产物选 0.5-1.5B
  （Qwen2.5-1.5B / GLiNER 式小 encoder）常驻推理; 7B 留给 LLM 挑选器(R7)或教师精调
- 多锚点 = 多个 SPO 三元组各自扩散后合并（GraphRAG local→global 同构）

**推荐路线定案**: A（规则增强, 立即做）→ C（LLM 蒸馏 → 小模型筛选核心, 主路线）
→ B 作为 C 的落地形态; 7B 微调仅当 R7 LLM 挑选器需要精调时启用。

- SPO 对齐对召回增益从 X% → Y%（黄金集对比, 数字说话）

## 八、方案先进性核查（2026-08-08 联网, 2024-2026 文献对照）

> 结论: **方案不过时** — 混合锚点 + 图扩散 + 蒸馏小模型都是 2024-2025 主流,
> 但找到 4 个可优化升级点 + 1 个融合实验项。

### 已确认不过时（我们的设计与前沿同向）

| 我们的设计 | 前沿对照 | 结论 |
|---|---|---|
| 混合锚点（向量+BM25+SPO+HyDE） | DAT 动态混合 / KG²RAG 语义+KGR 扩散 | 同向, 但权重机制可升级（见下） |
| 锚点→k-hop 图扩散 | LightRAG 双层检索 / QCG-RAG query-centric 图 | 同向, 缺 high-level 主题层（见升级2） |
| 蒸馏小模型做抽取/筛选 | MetaIE / UniversalNER / GLiNER-multitask | 同向且是主流路线 |
| 溯源置信度 + A18 ε 自适应 | Self-MedRAG 自反思检索 / DAT 动态 α | 同向, A18 是加分项 |
| SPO 结构对齐（Gentner） | DeepStruct 结构预训练 / milIE 迭代抽取 | 独特且有理论锚点 |

### 升级点（按性价比排序）

**升级1 — 权重动态化（高性价比, 对应 DAT 2025）**
- 现状: 固定置信度 + ε 微调（全局一套）
- 文献: DAT 按 query 动态调 dense/BM25 权重（LLM 评 top-1 效果→校准 α）
- 落地: query 类型检测（事实型/语义型/操作型）→ 权重偏置叠加 A18 ε 学习
- 成本: 低（分类器或规则）; 收益: 每 query 自适应

**升级2 — 补 high-level 主题层（低成本, 已有资产）**
- 现状: 只有 low-level 锚点扩散（实体/SPO 级）
- 文献: LightRAG 双层（实体+主题）/ E²GraphRAG 摘要树
- 落地: 主题树模块（T1-T7 已施工）即现成 high-level 索引 → 主题召回与锚点扩散合并
- 成本: 低（接线）; 收益: 宏观话题召回, 补锚点盲区

**升级3 — k-hop 扩散 → PPR（中成本, 对应 SPRIG 2025）**
- 现状: 简单 hop 衰减（0.8/hop）
- 文献: SPRIG 用 NER 共现图 + Personalized PageRank, CPU-only 线性时间,
  比朴素图检索 +28% 且 Recall@10 不掉
- 落地: 对话树边权重化 → PPR 替代 hop 衰减
- 成本: 中（图算法实现）; 收益: 多跳召回提升, 且纯 CPU（契合 3080 移动端）

**升级4 — BM25 → 学习式稀疏（可选, 有蒸馏模型后）**
- 文献: Mistral-SPLADE 证明 LSR 比 BM25 语义更强（LLM 关键词扩展）
- 落地: 阶段3 用蒸馏小模型产 SPLADE 式权重, 替代/并列 BM25
- 成本: 高（需模型）; 收益: 词法路升级为语义词法

**实验项 — RRF vs 线性融合（黄金集 A/B）**
- 文献: RRF（Reciprocal Rank Fusion）是混合检索标配, rank-based 对尺度不敏感
- 现状: score × confidence 线性融合
- 落地: 黄金集对照 RRF 与线性融合, 数字选型

### 硬件结论（3080 16GB 移动端）
- SPRIG CPU-only 路线契合: PPR + NER 共现图不需 GPU → "无 LLM 基本盘"完全可行
- 7B QLoRA 可调但重; 蒸馏产物 0.5-1.5B 常驻; 7B 仅用于 R7 LLM 挑选器精调
