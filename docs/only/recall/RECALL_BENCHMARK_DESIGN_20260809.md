# 召回量化评测设计（2026-08-09 讨论定案）

> 状态: 设计定案（待施工）| 触发: 用户"我们最缺的是量化测试数据"
> 参考: notTish 项目设计（docs/notTish/design/, 学习借鉴）

---

## 一、背景与判断

1. **最缺量化测试**: 1892 单元测试全绿但系统级断线照漏（recall→执行层
   断了几个月, 2026-08-09 才接上）——单元测试证明"模块内部对",
   证明不了"系统连通、行为达标"
2. **文档库 = 天然语料**: 625 份真实文档（docs 450 + docs/only 175,
   7.6MB）——真实、领域相关、结构化; "没同步"的文档是资产不是阻碍
   （真实知识库本来就新旧混杂, 且测出漂移 = 文档审计工具）
3. **已有专门内容**: data/recall_goldset.json（40 query/218 块, 真实对话）
   ——但只有对话场景

## 二、粗糙点自省（初稿被否）

"章节标题自生成 query + self-retrieval" 粗糙:
- query 是文档内部语言（标题）, 不是真实用户查询 → 测"标题匹配"非语义召回
- self-retrieval 命中率虚高（标题与正文同块）或虚低（标题词面共享）
- 测不出"换说法能不能找到"（同义/英文/口语化/反义）

## 四、评测设计（三层内容 + 统一报告）

### 内容层
1. **层1 真实对话黄金集**: 已有（40 query/218 块）——真实用户查询
2. **层2 人工代表性查询集**（新写, 待施工）: 从设计文档提炼 50-80 个
   "开发者真会问的问题", 标准答案标注到源文档块
3. **层3 变体鲁棒性**（LLM 批量生成）: 每 query 生成同义改写/英文/
   口语化/反义变体 → 测召回对换说法的稳定性（对齐结构语义思路）

### 报告（统一 BenchmarkReport）
- 主指标: top1/top3/top5 命中率 + MRR + 随机基线
- 维度分: 相关度（命中） + 漂移度（命中旧文档扣分） + 鲁棒性（变体一致率）
- 分级: 简单/复杂/跨域 分别统计
- 漂移检测: 命中旧文档 vs 新文档单独计（来源可信度 = 文档-代码同步度）

### 脚本
- scripts/doc_recall_bench.py 改造: 接受外部 query 集 JSON
  （query/expected/variants/level）, 语料仍是 docs 全量切块（块带 path 索引）
- 自生成标题 query 降级为辅助参考（不进主指标）

### 最终版 4 组件（含补读）
1. 内容: 真实对话黄金集 + 人工查询集（层2）+ 变体鲁棒性（层3）
2. 报告: 统一 BenchmarkReport（top1/3/5 + MRR + 维度分 + 分级）
3. 对比: 四路 Baseline（bm25 / vector / mixed / llm-retrieval）
4. 审计: 文档-代码同步度（每块标注对应实现路径, 漂移单独计）

## 七、施工记录（2026-08-09 晚, 首轮基线完成）

### 已完成
1. **语料/查询集**: docs/test/recall_queries.json（50 条人工查询,
   8 功能域, 16 目标文档零缺失）; 语料 = docs/only 全量 2444 块
   （章节切块, 块带 path 索引 + created_at）
2. **跑分脚本**: scripts/doc_recall_bench.py（外部查询集 / 分级统计 /
   漂移候选 / 四路 single / 粗筛 top-c / 时序参数）
3. **性能优化**: 磁盘向量缓存（重跑秒级）+ 批量 encode(batch 32) +
   GPU torch（2.6.0+cu124, RTX 3080）——2444 块编码 8.3s（CPU 10 分钟超时）
   + 词项预索引粗筛（消灭重复分词）
4. **时序约束**（评测驱动发现）: RecallService.time_half_life_days
   （默认 0 关, >0 半衰期）; 块 created_at（文件名日期或 mtime）;
   排序分 = fused × 2^(-age/half_life), 下限 0.3——5 项单测

### 首轮基线（50 query × 2444 块, 粗筛 top-300）
| 模式 | top1 | top3 | top5 | MRR | 说明 |
|---|---|---|---|---|---|
| bm25 单源 | 28% | 46% | 56% | 0.384 | 词法基线 |
| linear 混合 | 38% | 62% | 74% | 0.515 | 混合 > 单源 (+10pp) |
| rrf 混合 | 36% | 60% | 76% | 0.503 | |
| **linear + 时序** | **44%** | 60% | 74% | **0.534** | 时序 +6pp |
| **rrf + 时序** | **42%** | 62% | 72% | **0.528** | |

分级（linear+时序）: simple 41% / complex 48% / cross 25%（跨域是短板,
  时序从 0% 救到 25%）

### 发现（量化测试价值实锤）
- 混合 > 单源词法（+10pp）——混合召回的价值有数字了
- 时序约束有效（+6pp）——"本轮/最新"时间语义此前完全缺失
- 跨域 query 仍弱（25%）——跨文档知识聚合是下一块
- 剩余漂移案例根因 = 粗筛词项交集漏语义相关块（如 09 版交接文档词面
  不匹配"恢复入口"）——后续: 粗筛混合向量 或 top-c 扩大

## 八、对外评测口径（2026-08-09 定案）

**对内 vs 对外是两个评测**:
- 对内（看护）: 内部文档语料 + 内部查询, 数字只进 docs/test/,
  价值 = 每次改动后重跑看涨跌（本次抓到时序缺失 +6pp 即实例）
- 对外（GitHub/读者）: 内部数字不可直接贴（无上下文, 术语外部不懂）

**对外三件套**:
1. 通俗翻译: 给参照系——"随机基线 0.2% → 44%（提升 220 倍）;
   每 100 个问题 44 个第一候选就是正确文档"
2. 样例演示: 抽 3-5 条"查询 → 命中"对照（外部读者秒懂召回在干嘛）
3. 公开基准适配（后续）: BEIR 子集（nq/trec-covid）/ C-MTEB 中文检索
   ——"在标准基准上 X 分"才是外部可信口径

**结论**: 对内看护继续用现有体系; 对外报告走"通俗翻译 + 样例演示"
先行, 公开基准适配列入后续（与层3变体、文档-代码同步审计同批）。
