## 〇、问题

1. TREE_TIERING_DECISION 只有**静态** page-in/page-out（按会话整体落盘/加载）,
   没有动态晋升/降级 → 高价值历史块无法"热起来", 低价值当前块长期占热层
2. 召回是**被动**的: query 来了才找 → 没有利用预判（预意图/蓝图下一步/行为链模式）
3. recall 的 `sid` 参数只用于缓存文件名, **未按会话过滤块** → 对话树热路径没真实现

---

## 一、三件套模型（用户拍板）

```
┌─ 热层（寄存器/工作集）──────────────────────────────┐
│  ① 当前会话树块（对话推理结构）                        │
│  ② 全局热索引（跨会话高价值 + 预放锚点, LRU）          │
└─────────────────────────────────────────────────────┘
         │ 并行召回（同时跑, 谁先到先给子图）
         ▼
┌─ 冷层（持久化）──────────────────────────────────────┐
│  全局块池（跨会话原文, 永不删 A17）                    │
└─────────────────────────────────────────────────────┘

晋升: 冷命中且综合分高 → 复制进热索引（语义唤醒 A15）
降级: 热索引超限 → 综合分最低 → 确保持久化有份 → 删热（降温不删除）
预放: 预判下一步 → 预提取锚点 → 预放热索引（TTL 兜底, 失败无害）
```

## 二、热索引（HotIndex）

**结构**（内存 LRU + 磁盘缓存 `data/recall_index/hot_{sid}.json`）:
```
{bid, text, spo, vector, 综合分, 来源(hot|promoted|prefetch), 最近访问, ttl_rounds}
```

**容量**: 初始 512 块（env `DM_HOT_INDEX_CAP` 可调）
**淘汰**: 综合分 = 温度 × 访问频率 × 语义价值 × 来源权重（A18 权重可学习）
  超限 → 综合分最低者 → 先持久化确认 → 删热

## 三、并行召回（热 ∥ 冷）

```
热路径: 会话树块（sid 过滤）+ 热索引 → 各锚点函数 → 快
冷路径: 全局块池 → 各锚点函数 → 覆盖广
   ↓
融合: 去重（热冷同块）→ RRF/线性 → 输出
```

- `_ensure_blocks(sid)` 修复: 按 `_session_id` 过滤（热路径真实现）
- 热冷同块去重: 保留热路径（来源标记 hot, 更快）
- 质量比较: 冷命中块若融合分高 → 触发晋升候选

## 四、晋升 / 降级

**晋升触发**: 冷路径命中且融合分 > 阈值（初始 0.6）或用户 feedback(useful)
  → 复制进热索引（source="promoted"）, 后续热路径直命中

**降级触发**: 热索引超限 → 综合分最低块
  → ① 若仅内存（未落盘）: 先写 Warm 文件（A17 不丢）
  → ② 从热索引删除 → 回冷层

## 五、锚点预放（Anchor Prefetch）

**信号源**（可插拔, 低开销优先）:
```
① 状态信号: 当前话题/意图/阶段（规则, 零成本）
② 蓝图信号: 执行中已知下一步节点 → 预取该步上下文（A16）
③ 行为链信号: 用户历史模式（"上次 X 后总问 Y"）
④ LLM 轻量预判（可选）: 复用意图管线, 1 次调用
```

**流程**:
```
预判 query（多信号合成） → 对全局池 recall → top-k 块
  → 预放热索引（source="prefetch", 融合权重 ×0.5, ttl_rounds=3）
  → 命中: 强化预判信号（行为链养料）
  → 未中: TTL 到期自动淘汰, 无害
```

**反馈闭环**（关键增值）: 预判命中率 = 学习数据
- 命中 → 强化该信号源的权重（A18 ε）
- 未中 → 弱化; 失败多了预判策略自动调整（A6 对内学习）
