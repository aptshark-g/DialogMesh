## 一、GAP-3 工具批次级介入（OpenClaw beforeToolBatch 对齐）

### 问题
原有介入是**节点级**（PlanGate 单节点暂停 + 三层介入逐事件）——一批工具调用
（同节点 batch / parallel）没有一个"批维度批准"层。OpenClaw 的
`beforeToolBatch` 允许一批工具合并 approve（中风险批量场景）。

### 实现

**intervention.py**
- `RiskClassifier.classify_tool(tool, args)` — 工具调用风险分级:
  高危关键词（写/删/花钱, 含工具名与参数）→ HIGH;
  只读类工具（search/read/get/list/find/query/fetch/check...）→ LOW;
  其余 → MEDIUM
- `InterventionRouter.route_batch(tools, dimension)` — 批次级介入:
  含高危 → HIGH + sync_required=True（批次拦截待确认）;
  含中危且无高危 → MEDIUM + proposed（不阻塞, PR review 语义）;
  全只读 → LOW + applied（直接执行 + 留痕）
  → 单一 `tool_batch` 决策事件（after=工具摘要列表）

**executor.py**
- `_handle_tool` 入口加 `batch` 分支（node.params.batch）
- `_handle_tool_batch(node, batch, text)`:
  1. 逐工具调用前校验（T2 必填参数, 不盲执行）
  2. 风险分级 → `route_batch` 介入
  3. sync_required → 整批拦截 `{"status": "blocked", "reason": "tool_batch_approval_required"}`
     否则 → 并发执行
- 抽公共 `_execute_tool_specs(specs)`（parallel/batch 共用执行 + 聚合, 消除重复）

### 验证
- 新测试 `test_tool_batch.py` **8/8 全绿**（分级/汇总/只读执行/写工具拦截/缺字段/空批次）
- 回归: test_intervention 12 + test_tool_node 6 + context_window 30 = 43/43 全绿

## 二、GAP-4 压缩反馈闭环（Hermes manual_compression_feedback 对齐）

### 问题
G2 事件生命周期（热/温/冷）已落地, 但压缩质量无反馈通道 — 无法评测/调优
压缩阈值与 importance 权重。

### 实现

**context_window/compression_feedback.py**（新）
- `CompressionFeedbackStore` — 反馈持久化（data/compression_feedback.json,
  原子写 + 线程锁）+ 统计（total/good/bad/good_rate）+ recent

**context_window/window_manager.py**
- `compression_log`（deque 10）+ `_log_compression(level, before, after)` —
  每次压缩记录 `{id, level, before_tokens, after_tokens, saved_tokens, ts}`
- 压缩点接入: `_promote_warm_to_cold` + `_compress_warm`
- `get_window_summary` 暴露 `recent_compressions` + `last_compression_id`

**kernel dispatch + API**
- `kernel_compression_feedback` / `kernel_compression_feedback_stats`
- `POST /v6/context/compression-feedback`（quality/comment/compression_id/source）
- `GET /v6/context/compression-feedback/stats`（stats + recent）

**前端（ContextDockContent）**
- 上下文 Dock 底部"压缩质量反馈"区: 👍不错 / 👎有问题 + 补充说明 + 提交
- 提交成功提示"已记录（压缩阈值调优输入）"

### 验证
- 新测试 `test_compression_feedback.py` **5/5 全绿**（记录/非法质量拒绝/持久化重载/
  window 压缩日志/API 端点）
- tsc 归零 + vite build 成功（2.54s）

## 三、对齐哲学

- GAP-3: 三层介入扩展为**批维度**（低 applied / 中 proposed / 高 sync_required）;
  高危批次拦截 = A21 安全底线; 只读批次直接执行 = A16 快反馈
- GAP-4: 压缩质量可反馈 → 元认知可复盘（决策事件维度）; 未来可调压缩阈值
  （importance 三信号权重）— 与 G2 生命周期同闭环
