# 蓝图分层决策 — 不是所有硬编码都变模板（2026-08-13）

> 触发: 用户问"这样的话后面硬编码都变成蓝图模板？你怎么看？是好是坏？"
> 结论（用户拍板）: **可记录 = 当前情况的判断** — 模板化的是"会演化的
> 流程", 不是"所有的代码"; 分层对了是资产, 分层错了就是负债。

## 一、三层分类（按颗粒度, 呼应 PARADIGM A2 颗粒度哲学）

```
平台层（硬编码, 永不模板化）
  引擎初始化、状态机注册、事件总线、权限引擎、蓝图引擎本身、
  ToolRegistry/SkillRegistry 本身
  —— 模板的模板; 模板不能自我注册（鸡生蛋）, 必须硬编码。

能力层（注册为工具/技能, 但不模板化）
  recall / run_shell / dir_list / grep / file_read / recall_decompose
  —— 原子动词。能力变强（重排/HyDE/意图感知/多路召回都在这一层）,
     而不是能力变成模板。工具 = 动词, 模板 = 句式。

流程层（模板化）
  意图→召回→图扩展→回复、代码分析→工具循环、任务规划→执行
  —— 多步编排、常变、可学习、需审计 → 模板化收益最大。
```

## 二、判断标准（什么时候提模板）

| 信号 | 决策 |
|---|---|
| 有第二个调用方 / 明显会复用 | 模板 |
| 一次性、诊断脚本、探索期路径 | 硬编码 |
| 能从执行结果学习改进（G2 learn_blueprint / MetaFeedback 权重） | 模板 |
| 纯机械固定步骤 | 不用模板 |
| 需要审计 / 回滚 / 人工干预（PlanGate / tracer） | 模板 |
| 原子操作 | 工具注册（不进模板） |
| 多步编排 | 模板 |

## 三、坏处与边界（诚实）

- **过度模板化 = 抽象爆炸**: 每个模板都有节点语义匹配（CHAIN_TO_PHASE）、
  param 传递契约、错误处理成本。蓝图薄的病根 = 抽象层先于实现层
  （模板写了一堆, handler 没接全, 看着在蓝图里、跑起来是空的）。
- **模板是慢变量**: 适合稳定、可学习的流程; 探索期一次性路径硬编码更快。
- **分发开销虽小但真实**: 事件 + tracer + 权限检查, 高频微调用会放大。

## 四、本轮施工的应用（2026-08-13）

- 能力层增强（5 链接线、segments 多路召回、A18 持久化）= 能力, 硬编码/工具注册;
- 入口消费 = 注册 `intent_multi_recall` 模板（复用 recall_decompose 工具节点 +
  multi 参数）——"多意图召回好不好用"变成可学习的模板选择, 而非改代码;
- 平台层（引擎接线）保持硬编码。

## 五、对应公理

- A2 颗粒度哲学: 不同层级不同抽象颗粒度, 不是"一个抽象套所有";
- P2 算法与 LLM 分工: 平台 = 确定性基础设施（硬编码）, 流程 = 可学习编排
  （模板）, 能力 = 可组合工具（注册）;
- A19 白盒化 / G2 自增长: 模板化的动机 = 可审计 + 可学习;
- A14 约束在事实中浮现: 分层不是声明出来的, 是调用事实（第二个调用方出现）
  自然归纳的——先有事实, 后有模板。
