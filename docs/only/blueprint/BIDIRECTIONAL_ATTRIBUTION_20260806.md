# 双向归因闭环 — 微观探索 × 宏观约束 × 元认知仲裁（2026-08-06）

> 触发讨论：T4 ReAct 子循环应升级为完整认知闭环——偏差不只重试，
> 每个偏差带归因，归因回流对应层（计划/约束/数据/工具），双向学习。
> 状态：设计定案，待施工。前置：META_ARBITER P0 + FLOW_SELF_GROWTH G1-T3
> （决策事件 / RECOVERY / tool 节点 / LLM schema 决策 / 校验 / 回灌）。

---

## 一、核心论断：偏差 = 养分，不是要消除的错误

```
工具失败 / 计划遗漏 / 约束跑偏 / 数据不足 — 每个偏差都是系统经验:
  不是"重试到成功"就完事
  而是"归因 → 学习 → 改进对应层" — 偏差本身让系统变强

对齐元认知设计: self_audit / verify_past_decision（实现但无触发源）
本设计给它们真实的触发源 + 真实数据。
```

---

## 二、双向归因闭环（架构图）

```
┌─────────────────────────────────────────────────┐
│ 宏观层（计划/约束）                                │
│   蓝图模板 / SkillRegistry / ConstraintChecker    │
│   工程链约束 / 参数注册表                          │
└──────────────┬──────────────────▲────────────────┘
               │ 约束（计划限制探索）  │ 归因回流（探索暴露遗漏）
┌──────────────▼──────────────────┐────────────────┐
│ 微观层（工具探索）                │                │
│   tool 节点 ReAct 子循环          │                │
│   探索 → 结果 → LLM 再决策        │                │
└──────────────┬──────────────────┘                │
               │ 偏差信号（失败/跑偏/遗漏/幻觉）       │
┌──────────────▼──────────────────────────────────┐
│ 元认知树图（仲裁/复盘/归因）                       │
│   产出: 归因事件 → 前端可见 → 用户可介入            │
└─────────────────────────────────────────────────┘
```

## 三、双向但方向不同（关键）

| 方向 | 信号 | 归因问题 | 学习落点 |
|------|------|---------|---------|
| 微观→宏观 | 探索发现**计划遗漏**（工具没有/路径不够） | "为什么没计划好？" | 模板进化（G2）/ SkillRegistry 权重 |
| 宏观→微观 | 计划约束发现工具**跑偏/幻觉** | "为什么没约束好？" | ConstraintChecker / 工程链约束（G3） |
| 双向 | 数据不足导致两者都失效 | "为什么数据不全面？" | 数据源 / ingestion / 工程链 |
| 工具层 | 工具调用本身失败 | "为什么调用错？" | tool-call-repair（T4 ReAct 重试） |

---

## 四、与 OpenClaw 的差异（为什么更完整）

OpenClaw tool-call-repair 只修**工具调用本身**（参数错重发）。
本设计修**整个认知链**:

```
同一个偏差, 四条归因路径:
  工具失败 → 归因"参数"     → 修工具调用（= OpenClaw 有）
  工具失败 → 归因"工具不存在" → 沉淀新工具/模板（G2）
  工具失败 → 归因"约束太松/紧" → 调 ConstraintChecker（G3）
  工具失败 → 归因"数据源缺"   → 补 ingestion（工程链）
```

## 五、施工分层（T4 → T5 → T6）

### T4. tool 节点 ReAct 子循环（机制底座）

```
tool 节点 params 支持 max_steps（默认 3）:
  执行 → 结果不足/失败 → LLM 看结果再决策:
    改参数 / 换工具 / 宣布完成
  每步写 decision_bus 事件（可回看/介入/否决）
  子循环超限 → 返回 error → 外层 RECOVERY 接管（P0-2 已做）

对齐 OpenClaw agent-loop ReAct + toolLoopRecovery
```

### T5. 归因字段（每个偏差带 attribution）

```
偏差事件 payload 加:
  attribution: plan | constraint | data | tool
  evidence: 失败详情 / 上下文摘要
  suggested_fix: 初步归因建议

一次失败可多方归因（主因 + 次因）
```

### T6. 归因回流（按归因类型接到各层）

```
plan       → G2 模板进化 / SkillRegistry 权重（MetaFeedback P0-3 已副作用化）
constraint → G3 ConstraintChecker 动态调参 / 工程链约束
data       → ingestion 数据源反馈 / 关联链
tool       → tool-call-repair（参数自修复）/ ToolRegistry 学习
```

---

## 六、验收门槛

1. tool 节点 ReAct: 首次失败 → LLM 改参数重试 → 成功或 ≤3 步终止
2. 每步写 decision_bus 事件（kind=tool_retry / strategy_switch）
3. 偏差带 attribution 字段（plan/constraint/data/tool）
4. 归因回流: plan 归因 → 模板/权重变化; constraint → 约束变化
5. 前端可见: 双向事件流（探索/约束/归因）可回看
6. 用户可介入: 可否决重试/加约束/终止子循环
