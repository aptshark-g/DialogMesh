## T1 构建层修复（无外部依赖，先做）

| 子项 | 改动 | 验收 |
------|------|------|
| 单例隔离 | `engine.py` `build()` 对 BUILTIN_TEMPLATES 深拷贝后再用；LLM override 只作用于副本 | HYBRID 后 BUILTIN_TEMPLATES 不变（对抗测试） |
| strategy 不覆盖 | fallback RECOVERY 后不执行 `dag.strategy = strategy` | RECOVERY DAG strategy=RECOVERY |
| converge 防崩 | `llm_dag_builder.py` L301 `float()` 加 try → None 回退；`required` 用严格布尔解析 | 坏 LLM 输出不崩溃、`"false"`→False |
| 缓存修复 | cache key 去 hash 碰撞（用 text 截断或 uuid）+ 缓存副本 | 不同文本不同对象 |
| match 空串守卫 | `skill_registry.match("")` → general_chat | 空 intent 不再命中 code_analysis |

## T2 执行层混合式改造（核心）

| 子项 | 改动 | 验收 |
------|------|------|
| 统一执行器 | 保留 Decider 入口，executor 逻辑内联（删双实现重复）；`decider._chain_handlers` 不再抓私有方法 | 单一执行路径 |
| 同步段直调 | `_handle_pcr` → `PCRRouterV2.route(text)`; `_handle_subgraph` → `SubgraphCompiler().compile_dialogue()`; `_handle_intent` → DualTrack 或读 PCRResult | 节点输出真实结构（PCRResult/SubgraphContext），非关键词 fallback |
| 删伪造 fallback | `_handle_profile` API 失败 → 空 + 显式标记；pcr/intent 无组件 → `{"status":"unavailable"}` | 无假画像/假 PCR/假 Intent 进 prompt |
| 同 Tick 拓扑 | 同 Tick 内按依赖迭代（多轮收敛），乱序不丢节点 | 对抗测试 |
| 事件记录 | 每节点产出写 EventLog（subject=node_id, payload=摘要, 含边引用） | 执行后 EventLog 可回溯（§7.5 快照地基） |
