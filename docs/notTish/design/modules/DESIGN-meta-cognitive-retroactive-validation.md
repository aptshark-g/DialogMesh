# META-COGNITIVE RETROACTIVE VALIDATION ENGINE (元认知回溯验证引擎)
## Design v1.0 — 主动质疑·溯源锚定·约束推导·置信评估

---

## 1. 核心哲学

> **不是"内容是否正确"，而是"为什么认为它正确/不正确"，以及"这个判断本身是否可靠"。**

传统验证：内容 → 爬取 → 对比 → 结论（单层）
元认知验证：内容 → 质疑 → 溯源 → 质疑溯源 → 推导 → 质疑推导 → 置信评估（多层循环）

## 3. 核心组件定义

### 3.1 质疑生成器 (Skeptic)

**功能**：对任何输入内容（LLM 输出、爬取结果、推导结论）生成质疑点。

**质疑维度**（6D）：

| 维度 | 质疑问题 | 触发条件 |
|------|----------|----------|
| **D1-来源** | "这个断言的原始来源是什么？" | 任何未标注来源的事实性断言 |
| **D2-时效** | "这个信息的时间戳是什么？是否过时？" | 涉及技术参数、版本号、标准 |
| **D3-范围** | "这个结论的适用范围是否被过度泛化？" | 含有"所有""必然""一定"等词 |
| **D4-因果** | "这个因果关系是否有反例？" | A→B 形式的断言 |
| **D5-量化** | "这个数值是否可验证？误差范围？" | 含有具体数字、百分比 |
| **D6-一致性** | "这个结论与已知的 L0-L4 知识是否矛盾？" | 与持久化层语义图冲突 |

**输出**：质疑列表 `[{dimension, question, severity, context}]`

---

### 3.2 溯源爬取器 (Retro-Crawler)

**功能**：不是按关键词爬取，而是**按质疑点逆向爬取**。

**传统 vs 逆向**：

```
传统：keyword="FxLMS convergence" → 爬取论文 → 人工阅读 → 提取结论
逆向：质疑="S_est 可以在线辨识？" → 追溯：谁在论文中提出？→ 找到原始文献 → 提取原始约束条件
```

**溯源策略**：

```python
class RetroCrawler:
    def trace(self, assertion: str, skeptic_point: SkepticPoint) -> SourceTrace:
        """
        1. 分解断言为原子命题（最小可验证单元）
        2. 对每个原子命题：
           a. 在持久化层搜索已有溯源记录（Source-DB）
           b. 若无，启动外部爬取：
              - 不是搜索关键词，而是搜索"谁首次提出 X"
              - 使用引文网络（citation graph）向上追溯
              - 优先追溯：原始实验论文 > 综述 > 教材 > 博客
        3. 返回溯源链：assertion → 原始论文 → 实验条件 → 数据
        """
```

**输出**：`SourceTrace {chain: [SourceNode], confidence: float, gaps: [Gap]}`

### 3.3 来源锚定器 (Source-Anchor)

**功能**：对溯源结果进行可信度评估和标注。

**来源可信度分级**（5 级）：

| 等级 | 类型 | 示例 | 可信度 |
|------|------|------|--------|
| S0 | 原始实验/数据 | 论文原始实验数据、官方 datasheet | 0.90-1.00 |
| S1 | 同行评审论文 | IEEE/ASME 期刊、会议论文 | 0.70-0.90 |
| S2 | 技术文档/手册 | 厂商手册、标准文档 | 0.50-0.70 |
| S3 | 综述/教材 | 二手总结、教科书 | 0.30-0.50 |
| S4 | 网络/博客/论坛 | 博客、知乎、StackOverflow | 0.10-0.30 |
| S5 | 无来源/推测 | 纯推测、幻觉 | 0.00-0.10 |

**锚定操作**：

```python
class SourceAnchor:
    def anchor(self, trace: SourceTrace) -> AnchoredAssertion:
        """
        1. 评估溯源链中每个节点的可信度
        2. 计算链式可信度（ weakest link 原则）
        3. 标注锚点：
           - 强锚定（S0-S1）：可信任，但需验证适用条件
           - 弱锚定（S2-S3）：需额外验证
           - 无锚定（S4-S5）：标记为待验证
        4. 记录到 Source-DB，供后续查询
        """
```

### 3.4 约束推导引擎 (Constraint Derivation Engine)

**功能**：当溯源失败（找不到来源）时，启动**逻辑推导**验证。

**推导策略**（3 层）：

```
Layer 1: 形式化推导（L0-L2）
  输入：断言 + 已知公理/定理
  方法：逻辑推理、数学证明、算法复杂度分析
  输出：{valid: bool, proof_chain: [...], assumptions: [...]}

Layer 2: 物理约束推导（L3）
  输入：断言 + 物理定律
  方法：量纲分析、因果律检查、边界条件验证
  输出：{physically_possible: bool, violation: [...]}

Layer 3: 工程可行性推导（L4）
  输入：断言 + 工程参数
  方法：成本估算、时间估算、资源约束检查
  输出：{feasible: bool, cost_estimate: {...}}
```

**示例**：

```
LLM 断言："S_est 可以在线实时辨识"
溯源失败：找不到支持此断言的原始文献

启动约束推导：
  L1（数学）：辨识需要 N 个采样点 → 最小延迟 = N·Ts
  L3（物理）：若 Ts = 25μs，N = 100 → 延迟 = 2.5ms
  L3（物理）：FxLMS 要求因果性，2.5ms 延迟 > 控制周期 → 不可行
  L4（工程）：实际 FPGA 实现中，辨识模块需额外 DSP 资源 → 成本增加

结论：逻辑不自洽（延迟违反因果律）
置信度：0.95（推导基于量纲分析和物理定律，不依赖外部来源）
```

---

### 3.5 置信度评估器 (Confidence Assessor)

**功能**：综合来源锚定 + 约束推导，给出**置信范围**（不是单点值）。

**评估公式**：

```
Confidence = [lower, upper]

其中：
  upper = min(1.0, source_confidence + derivation_boost)
  lower = max(0.0, source_confidence - derivation_penalty)

source_confidence: 来源锚定可信度（0-1）
derivation_boost: 推导支持加分（0-0.3）
derivation_penalty: 推导反对减分（0-0.5）

特殊情况：
  - 无来源但推导支持：upper = 0.7, lower = 0.5（"逻辑合理但无实证"）
  - 有来源但推导反对：upper = 0.3, lower = 0.0（"来源可能错误"）
  - 来源和推导矛盾：触发元认知循环（质疑来源本身）
```

---

### 3.6 多层元认知循环 (Meta-Cognitive Loop)

**核心机制**：不是一次性质询，而是**递归质疑**。

```
Loop 0: 对原始内容质疑 → 溯源/推导 → 评估
Loop 1: 对 Loop 0 的溯源结果质疑 → "这个来源本身可靠吗？" → 二次溯源
Loop 2: 对 Loop 1 的推导过程质疑 → "推导的假设条件是否成立？" → 假设验证
Loop N: 直到收敛（置信度稳定）或资源耗尽（最大循环次数）
```

**终止条件**（3 种）：

1. **置信收敛**：连续两次循环置信度变化 < 0.05
2. **矛盾消解**：来源和推导从矛盾变为一致
3. **资源耗尽**：达到最大循环次数（默认 3 层）或时间预算用尽

## 4. 数据流与协作流程

### 4.1 标准质疑流程（LLM 输出校验）

```
[LLM 输出] → "S_est 可以在线实时辨识，延迟 < 40μs"
    ↓
[Skeptic] → 质疑：D1（来源？）、D5（量化？40μs 来源？）、D6（与 L3 矛盾？）
    ↓
[Retro-Crawler] → 追溯 "S_est 在线辨识" 的原始文献
                → 找到：某论文声称 "实时辨识" 但未给延迟数据
                → 溯源链断裂：延迟 < 40μs 无来源
    ↓
[Source-Anchor] → 标注：延迟 < 40μs 为 S5（无来源/推测）
    ↓
[Constraint Deriver] → L1 推导：辨识需要 N 个采样点
                     → L3 推导：N·Ts > 40μs（假设 Ts=25μs, N=100）
                     → 结论：与断言矛盾
    ↓
[Confidence Assessor] → 来源可信度：0.0（无来源）
                      → 推导可信度：0.95（物理定律支持）
                      → 置信范围：[0.0, 0.05]
    ↓
[Meta-Loop] → Loop 1: 质疑推导假设 "N=100" 是否必要？
            → 二次推导：若 N=1（单点估计），辨识精度不足
            → 置信度不变，收敛
    ↓
[输出] → 标记：断言被证伪，置信度 < 0.05，建议修正
```

### 4.2 协调层 × 收敛层协作

**协调层职责**：
- 接收 LLM 输出或外部输入
- 调度 Skeptic 生成质疑点
- 分配资源（爬取预算、推导时间、循环次数）
- 决定终止条件

**收敛层职责**：
- 执行形式化校验（与 L0-L4 持久化层比对）
- 执行约束推导（数学/物理/工程）
- 返回一致性报告和推导结果

**协作点**：

```python
# 协调层触发质疑
skeptic_points = coordinator.skeptic.analyze(llm_output)

for point in skeptic_points:
    # 分配资源
    budget = coordinator.allocator.allocate(point.severity)
    
    # 先尝试溯源（收敛层提供持久化层数据支持）
    trace = retro_crawler.trace(point, timeout=budget.timeout)
    
    if trace.is_complete():
        # 来源完整，锚定
        anchor = source_anchor.anchor(trace)
        confidence = confidence_assessor.assess(anchor=anchor)
    else:
        # 溯源失败，启动推导（收敛层）
        derivation = convergence_layer.constraint_derive(point, l0_l4_context)
        confidence = confidence_assessor.assess(derivation=derivation)
    
    # 检查是否需要元认知循环
    if confidence.needs_meta_loop():
        coordinator.meta_loop.schedule(point, confidence)
```

## 6. 关键设计决策

### 6.1 质疑 vs 否定的区别

- **质疑** = "我需要验证这个"（中性，触发溯源）
- **否定** = "这个已被证伪"（主动，需推导支持）
- 系统只质疑，不否定，直到溯源或推导完成

### 6.2 无来源但逻辑合理 = 置信范围，不是绝对拒绝

```
推导支持 + 无来源 → 置信范围 [0.5, 0.7]
  ↓
  "逻辑合理，但缺乏实证，建议标记为假设"
  ↓
  后续若有新来源验证 → 更新为 [0.8, 1.0]
  后续若有反例 → 更新为 [0.0, 0.2]
```

### 6.3 元认知不是无限循环

- 最大循环数：3（默认）
- 每次循环资源减半（质疑质疑本身需要更少资源）
- 置信度变化 < 0.05 时提前终止

## 8. 与 Nemotron 的关系

当前设计**不依赖 Nemotron**，所有组件均可由规则+逻辑实现：
- Skeptic：6D 质疑模板（规则）
- Retro-Crawler：引文网络 API（如 Semantic Scholar、CrossRef）
- Constraint Deriver：L0-L4 形式化推理（规则）
- Confidence Assessor：区间计算（数学）

**Nemotron 的增强场景**（可选）：
- 复杂断言的自动分解（"S_est 可以在线辨识" → 拆成 3 个原子命题）
- 非结构化文本的溯源（从博客/论坛中提取事实）
- 推导假设的自动生成（"假设 N=100 是否合理？"）
