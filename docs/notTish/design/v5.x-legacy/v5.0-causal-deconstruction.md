## 1. 问题陈述

### 1.1 当前系统的问题

Literature Cortex v4.1-REV2 已具备双核架构（收敛/发散）、规则引擎、Bi-BFS 搜索。但用户反馈：

> "过于论文化了。每个内容都是一句话和一些量化数据，没有感觉到那种联系和解构的感觉。"
> "FxLMS 改了什么？次级路径。为什么有这个？因为信号传递要时间。怎么计算的？有物理公式。这才是完整闭环。"

**具体症状：**

| 症状 | 根因 | 举例 |
|------|------|------|
| 节点像论文条目 | 数据模型是 `(id, title, type, content)` | `paper_fxlms` 的内容是 "Filtered-x LMS algorithm..." |
| 边像引用关系 | `base_type` 只有 correlation/causation/depends_on | `paper_fxlms → paper_bw` 标记为 "causes"，但没说为什么 |
| 没有层级穿透 | 没有 L1-L6 知识层级编码 | 无法问"FxLMS 的物理根源是什么？" |
| 没有因果语义 | 边没有说明"为什么依赖" | 不知道 LMS 为什么不够、为什么需要 FxLMS |
| 没有自动解构 | 从论文到六层解构需要人工 | 系统只会存储论文，不会拆解知识 |

### 1.2 核心目标

将系统从**论文存储引擎**升级为**因果解构引擎**：

1. **六层知识模型**：每个概念必须定位在 L1-L6 的某一层，并说明上下层依赖
2. **因果语义边**：边不是"引用"，而是"物理基础支撑"、"数学推导来源"、"工程实现路径"、"退化因素"
3. **自动解构**：从论文/文献自动提取六层解构内容（或至少强制要求人工填写）
4. **层级穿透查询**：`explain_why(fxlms)` → 物理根源；`explain_how(fxlms)` → 工程实现

## 2. 核心架构：六层知识模型 + 因果语义边

### 2.1 六层知识模型

```
L1 物理公理 (Axioms)
├── 因果律 (Causality Principle)
├── 信号传播延迟 (Signal Propagation Delay)
├── 机械波传播 (Mechanical Wave Transmission)
├── 热力学定律 (Thermodynamics Laws)
└── ...不可违背的自然规律

L2 数学抽象 (Mathematics)
├── Wiener-Hopf 方程
├── 梯度下降
├── 系统辨识理论
├── Kramers-Kronig 关系
└── ...形式化表达

L3 算法实现 (Algorithms)
├── LMS (假设零延迟，物理不成立)
├── FxLMS (补偿次级路径延迟)
├── RLS (快速收敛)
├── Kalman Filter (状态估计)
└── ...可执行的步骤

L4 系统架构 (Systems)
├── 单通道 ANC
├── MIMO FxLMS
├── 热-振耦合系统
├── 分层温控策略
└── ...组件组合

L5 工程实现 (Implementation)
├── FPGA 实时控制
├── EtherCAT 通信
├── 定点数运算
├── PT100 温度采集
└── ...物理映射

L6 验证失效 (Validation)
├── 收敛性证明
├── Nyquist 稳定性判据
├── 失效模式分析
├── 残余噪声评估
└── ...边界与退化
```

**关键约束：**
- L1 节点没有 `parents`（物理公理是根）
- L3 算法必须有 `physical_basis` 字段（指向 L1/L2）
- L5 实现必须有 `algorithm_source` 字段（指向 L3）
- L6 验证必须覆盖所有父节点的失效模式

### 2.2 因果语义边

替换现有的 `base_type` 枚举：

| 新语义 | 含义 | 示例 |
|--------|------|------|
| `physical_basis_for` | A 是 B 的物理基础 | `causality_principle` → `signal_propagation_delay` |
| `derived_from` | A 是 B 的数学推导来源 | `wiener-hopf` → `lms` |
| `improved_by` | A 的缺陷被 B 改进 | `lms` → `fxlms` |
| `implemented_by` | A 的工程实现是 B | `fxlms` → `fpga_realtime` |
| `degraded_by` | A 的性能退化因素是 B | `fxlms` → `thermal_drift` |
| `validated_by` | A 的正确性由 B 验证 | `fxlms` → `convergence_proof` |
| `causes` | A 的存在导致 B | `thermal_gradient` → `thermal_deformation` |
| `depends_on` | B 依赖 A 才能成立 | `fxlms` → `secondary_path_identification` |

**边的必填字段：**
- `causal_mechanism`：为什么这条边成立？（文字解释）
- `physical_formula`：支撑这条边的物理公式（可选）
- `derivation_chain`：数学推导步骤（可选，JSON 数组）

### 2.3 节点结构（强制解构模板）

每个节点必须包含以下字段：

```yaml
id: fxlms
level: L3
type: algorithm
domain: signal-processing

# 强制解构字段
what: "Filtered-x LMS，通过预滤波参考信号补偿次级路径延迟"
why_exists: "因为 LMS 假设零延迟反馈，但物理系统中信号必有延迟（见 L1 因果律）"
physical_basis: "信号传播延迟（L1）+ 因果律（L1）+ 群延迟（L1）"
  - ref: signal-propagation-delay
  - ref: causality-principle
  - ref: group-delay
mathematical_form: "Wiener-Hopf 最优解（L2）+ 梯度下降迭代（L2）"
  - ref: wiener-hopf
  - ref: gradient-descent
engineering_mapping: "FPGA 实时实现（L5）+ 定点数运算（L5）"
  - ref: fpga-realtime
  - ref: fixed-point
failure_modes: "相位误差>90°导致发散（L6）+ 温度漂移改变 S(z)（L6）"
  - ref: phase-error-instability
  - ref: thermal-drift

# 内容（强制包含六节）
content: |
  ## 这是什么？
  ...
  ## 为什么存在？
  ...
  ## 物理基础
  ...
  ## 数学推导
  ...
  ## 工程实现
  ...
  ## 如果错了？
  ...
```

## 3. 数据模型重构

### 3.1 Schema 扩展

```sql
-- 节点表：增加六层解构字段
ALTER TABLE nodes ADD COLUMN knowledge_level TEXT 
    CHECK(knowledge_level IN ('L1', 'L2', 'L3', 'L4', 'L5', 'L6'));
ALTER TABLE nodes ADD COLUMN what TEXT;           -- 这是什么
ALTER TABLE nodes ADD COLUMN why_exists TEXT;     -- 为什么存在
ALTER TABLE nodes ADD COLUMN physical_basis TEXT; -- 物理基础（JSON 引用列表）
ALTER TABLE nodes ADD COLUMN mathematical_form TEXT; -- 数学形式
ALTER TABLE nodes ADD COLUMN engineering_mapping TEXT; -- 工程映射
ALTER TABLE nodes ADD COLUMN failure_modes TEXT;  -- 失效模式

-- 边表：增加因果语义
ALTER TABLE edges ADD COLUMN causal_semantics TEXT
    CHECK(causal_semantics IN (
        'physical_basis_for', 'derived_from', 'improved_by',
        'implemented_by', 'degraded_by', 'validated_by',
        'causes', 'depends_on', 'correlation'
    ));
ALTER TABLE edges ADD COLUMN causal_mechanism TEXT; -- 为什么这条边成立
ALTER TABLE edges ADD COLUMN physical_formula TEXT; -- 支撑公式
ALTER TABLE edges ADD COLUMN derivation_chain TEXT; -- 推导步骤（JSON）
```

### 3.2 现有数据迁移

- 旧节点 `type='paper'` → 新 `level` 需要人工/LLM 判定
- 旧节点 `type='seed'` → 新 `level=L1`（种子是物理公理）
- 旧边 `base_type='causes'` → 新 `causal_semantics='causes'`（语义最接近）
- 旧边 `base_type='correlation'` → 需要人工判断实际语义

**迁移策略：**
1. 保留旧表，新建 `nodes_v2` 和 `edges_v2`
2. 写迁移脚本：从旧节点提取标题+摘要，调用 LLM 自动填充六层解构
3. LLM 无法判定的 → 标记为 `level=unknown`，待人工审核

## 4. 推理层：层级穿透引擎

### 4.1 Why-chain（向下钻取）

```python
def explain_why(node_id: str, depth: int = 3) -> list[ChainLink]:
    """回答：为什么这个节点存在？追溯到物理根源。"""
    
    node = store.get_node(node_id)
    chain = []
    
    # 第 1 层：直接原因
    for edge in store.get_incoming_edges(node_id, semantics=['improved_by', 'depends_on']):
        parent = store.get_node(edge.source_id)
        chain.append(ChainLink(
            reason=edge.causal_mechanism,
            parent=parent,
            level=parent.knowledge_level,
            depth=1
        ))
    
    # 第 2-n 层：递归追溯
    for link in chain:
        if link.level == 'L1':
            continue  # 已到物理公理
        sub_chain = explain_why(link.parent.id, depth=depth-1)
        link.sub_chain = sub_chain
    
    return chain
```

**示例：** `explain_why('fxlms')`

```
FxLMS 为什么存在？
→ 因为 LMS 不够（improved_by: lms）
  → LMS 为什么不够？（explain_why('lms')）
    → 因为 LMS 假设零延迟反馈（physical_basis_for: signal-propagation-delay）
      → 信号延迟为什么存在？（explain_why('signal-propagation-delay')）
        → 因为因果律（physical_basis_for: causality-principle）
          → 因果律是 L1 公理，停止
```

### 4.2 How-chain（向上追踪）

```python
def explain_how(node_id: str, depth: int = 3) -> list[ChainLink]:
    """回答：这个节点怎么实现？追踪到工程落地。"""
    
    node = store.get_node(node_id)
    chain = []
    
    # 第 1 层：直接实现
    for edge in store.get_outgoing_edges(node_id, semantics=['implemented_by']):
        child = store.get_node(edge.target_id)
        chain.append(ChainLink(
            method=edge.causal_mechanism,
            child=child,
            level=child.knowledge_level,
            depth=1
        ))
    
    # 第 2-n 层：递归追踪
    for link in chain:
        if link.level == 'L5':
            continue  # 已到工程实现
        sub_chain = explain_how(link.child.id, depth=depth-1)
        link.sub_chain = sub_chain
    
    return chain
```

**示例：** `explain_how('fxlms')`

```
FxLMS 怎么实现？
→ FPGA 实时实现（implemented_by: fpga_realtime）
  → FPGA 怎么通信？（explain_how('fpga_realtime')）
    → EtherCAT 协议（implemented_by: ethercat）
      → EtherCAT 怎么保证实时？（explain_how('ethercat')）
        → 硬件时间戳 + 分布式时钟（L5 细节）
```

### 4.3 自动解构（LLM 解析）

```python
def deconstruct_paper(paper_metadata: dict, abstract: str) -> DeconstructedNode:
    """从论文自动提取六层解构。"""
    
    prompt = f"""
    论文标题：{paper_metadata['title']}
    摘要：{abstract}
    
    请按以下六层解构这个论文的核心贡献：
    
    1. 这是什么？（What）
    2. 为什么存在？（Why）—— 解决了什么物理/工程问题？
    3. 物理基础（Physical Basis）—— 依赖哪些物理定律？
    4. 数学推导（Mathematical Form）—— 核心公式和推导？
    5. 工程实现（Engineering Mapping）—— 如何落地？
    6. 失效模式（Failure Modes）—— 什么情况下会失败？
    
    同时标注这个贡献属于 L1-L6 的哪一层。
    """
    
    result = llm.parse(prompt)
    return DeconstructedNode(
        level=result.level,
        what=result.what,
        why_exists=result.why,
        physical_basis=result.physical,
        mathematical_form=result.math,
        engineering_mapping=result.engineering,
        failure_modes=result.failure
    )
```

## 6. 关键设计决策

### 6.1 为什么必须六层？

| 层级 | 回答的问题 | 不可省略的原因 |
|------|-----------|---------------|
| L1 | 为什么这个现象必然存在？ | 物理公理是知识的根。没有 L1，L2-L5 都是空中楼阁 |
| L2 | 怎么形式化表达？ | 数学是精确的。没有 L2，无法量化、无法证明 |
| L3 | 具体怎么做？ | 算法是可执行的。没有 L3，无法落地 |
| L4 | 怎么组合？ | 系统是现实的。没有 L4，不知道边界和耦合 |
| L5 | 怎么物理实现？ | 工程是约束的。没有 L5，不知道成本和限制 |
| L6 | 什么情况下会失败？ | 失效是边界。没有 L6，不知道适用范围 |

### 6.2 人工 vs 自动解构

| 场景 | 策略 | 原因 |
|------|------|------|
| 核心节点（如 FxLMS） | 人工填写 | 准确性要求高，作为模板 |
| 批量论文导入 | LLM 自动 + 人工审核 | 效率优先，质量可控 |
| 用户查询时生成 | 实时 LLM 解构 | 动态知识，无需预存 |
| 已有旧数据 | 迁移脚本 + LLM 补全 | 兼容旧数据，逐步升级 |

### 6.3 因果语义 vs 传统关系

| 传统关系 | 问题 | 因果语义改进 |
|----------|------|-------------|
| `causes` | 太泛，不知道"为什么导致" | `physical_basis_for` + `causal_mechanism` 字段 |
| `depends_on` | 不知道"依赖什么" | `derived_from` / `implemented_by` 细分 |
| `correlation` | 无方向，无解释 | 废弃。所有边必须有方向+解释 |

## 8. 风险与边界

| 风险 | 描述 | 缓解措施 |
|------|------|----------|
| LLM 解构幻觉 | 自动填充的六层内容可能不准确 | 人工审核队列 + 约束校验（物理公式必须可验证） |
| 六层归类争议 | 同一概念可能跨多层 | 允许跨层引用（如 FxLMS 是 L3，但可引用 L1 物理基础） |
| 因果链过长 | Why-chain 可能追溯到很远 | 限制 depth≤3，默认展示三层 |
| 数据量爆炸 | 每个节点六层字段 + 边因果解释 | 文本存储，不建索引；按需加载 |
| 旧数据迁移成本 | 大量论文需要重新解构 | 批量 LLM 处理 + 渐进迁移 |
