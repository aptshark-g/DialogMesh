## 1. 问题陈述

### 1.1 当前架构的局限性

Literature Cortex v4.0 的持久化层本质是**断言式存储 + 语义匹配**：

- 存储的是已确认的节点和关系
- 能力上限是"找已有的关联"
- 没有的知识就找不到
- 属于**被动仓库**，而非**主动加工厂**

**具体瓶颈：**

| 问题 | 表现 | 根因 |
|------|------|------|
| 知识断裂 | 两个相关概念在图谱中没有边 | 依赖文献显式提及，忽略隐含关系 |
| 伪命题丢弃 | 判定不成立的命题直接删除 | 无"有条件成立"机制（修正：改为矛盾归档） |
| 静态匹配 | 只能找到已有文献覆盖的关联 | 无逻辑演绎能力（修正：正向演绎补足） |
| 假设不可追溯 | 无独立假设存储，与事实混存 | 单层持久化（修正：双层持久化 + 来源标记） |

### 1.2 核心目标

将持久化层从**仓库**升级为**加工厂**，具备三个能力：

1. **正向演绎**：基于已有事实和规则，自动推导隐含结论
2. **逆向假设**：基于目标节点反向推导前置条件，通过双向搜索补全缺失链路（**仅用于知识断裂，不用于逻辑错误修正**）
3. **矛盾归档**：废弃命题标记矛盾后归档，不污染假设层（**修正：替代原"伪命题复活"**）

## 2. 核心架构：双层持久化 + 规则引擎 + 冲突仲裁

### 2.1 双层持久化架构（修正版）

```
┌─────────────────────────────────────────────────────────────────┐
│                    应用层 (API / UI / Pipeline)                  │
├─────────────────────────────────────────────────────────────────┤
│                    推理层 (Inference Engine)                     │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐     │
│  │ 正向演绎内核 │    │ 逆向假设内核 │    │ 冲突仲裁器  │     │
│  │ (规则引擎)   │    │ (Bi-BFS)     │    │ 矛盾路径标记│     │
│  └──────────────┘    └──────────────┘    └──────────────┘     │
├─────────────────────────────────────────────────────────────────┤
│                    持久化层 (Persistence Layer)                  │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐     │
│  │ 事实断言层    │    │ 假设推演层    │    │ 矛盾归档库  │     │
│  │ (Asserted)   │    │ (Hypotheses) │    │ (Contradict)│     │
│  │ 置信度 ≥0.85 │    │ 条件化+置信度 │    │ 置信度 0.0  │     │
│  └──────────────┘    └──────────────┘    └──────────────┘     │
│              ↑                    ↑                    ↑      │
│         验证升级              TTL清理               永久归档   │
└─────────────────────────────────────────────────────────────────┘
```

#### 事实断言层 (Asserted Layer) — 修正

| 属性 | 原方案 | 修正后 |
|------|--------|--------|
| 准入标准 | 必须有明确来源；通过约束校验；已有验证 | 同原方案 |
| 可信度 | **100% / 高置信**（**问题：过度绝对化**） | **置信度 ≥0.85**，保留不确定性。来源标注：`import` / `human` / `rule` / `llm` |
| 写入权限 | 仅通过外部输入 + 验证后升级写入；不可被推演直接修改 | 同原方案。升级需满足：文献支撑 0.4 + 约束校验 0.3 + 多验证 0.2 + 时间检验 0.1，**总分 ≥0.8** |
| 内容 | 原始文献提取的节点、已验证的关系、本体种子框架 | 同原方案 |

**修正理由：** 文献提取本身存在 OCR 错误、作者表述歧义、翻译偏差。"100%可信"是分类错误，应量化为置信度。

#### 假设推演层 (Hypotheses Layer) — 修正

| 属性 | 原方案 | 修正后 |
|------|--------|--------|
| 准入标准 | 符合本体规则 / 逻辑推演即可 | **仅限"知识断裂补全"**（A→B 已知概念间无通路）。**排除：逻辑错误修正** |
| 可信度 | 标注置信度 + 约束条件 | 同原方案，但增加 `source` 字段区分：`auto_gen`（算法）/ `llm_sug`（大模型）/ `human`（人工） |
| 写入权限 | 推理引擎可自由读写；定期清理无效假设 | 推理引擎可自由读写；**每层最大 100 个假设**；**同类型相似度>0.9 合并** |
| 内容 | 推理生成的间接关系、假设节点、带约束的命题、待验证链路 | 同原方案。新增：假设节点必须标注生成来源（`generator_id`） |

#### 矛盾归档库 (Contradict Archive) — 新增（替代原"伪命题复活"）

| 属性 | 说明 |
|------|------|
| 准入标准 | 被硬约束（能量守恒、因果性、可测性、稳定性）直接否定的命题 |
| 处理方式 | **不复活**。标记为 `confidence=0.0`，存入归档库，永久保留但不可查询 |
| 作用 | 避免重复生成相同错误假设；作为反例训练数据 |
| 示例 | "被动阻尼可实现无限精度振动抑制" → 违反能量守恒 → 归档 |

**为什么砍掉伪命题复活？** 原流程："被动阻尼 + 外部能量补偿" ≠ "被动阻尼"，这是**构造了一个新命题**，不是复活旧命题。复活后的命题标注 0.4 置信度，会被误当文献线索，污染工作流。

### 2.2 正向演绎内核 (Deterministic Deduction Engine) — 修正

#### 2.2.1 规则集独立化（修正：从隐式代码提取为独立目录）

规则集不再隐含在代码中，独立为 `rules/` 目录，版本化，与本体演化同步：

```
rules/
├── v1.0.0/
│   ├── transitive.json      # 传递性规则
│   ├── inheritance.json     # 继承性规则
│   ├── inverse.json         # 逆关系规则
│   └── constraints.json     # 约束校验规则
├── v1.1.0/                  # 本体 Double-Loop 演化后更新
│   └── ...
└── README.md               # 版本化说明，关联 ontology_evolution 表
```

**规则引擎加载时：** 读取当前版本规则，同时检查 `ontology_evolution` 表是否有新版本，自动切换。

#### 2.2.2 四类规则（保留原方案，增加约束校验）

**传递性规则：**
```
A →depends→ B →depends→ C  ⇒  A →indirect_depends→ C
A →instance_of→ B →subclass_of→ C  ⇒  A →instance_of→ C
```

**继承性规则：**
```
B →subclass_of→ A  and  A →has_property→ X  ⇒  B →has_property→ X
```

**逆关系规则：**
```
A →is_prerequisite_for→ B  ⇒  B →depends_on→ A
```

**约束校验规则（新增硬约束表）：**

| 约束类型 | 规则 | 违反标记 |
|----------|------|----------|
| 能量守恒 | 被动系统 → 必须满足 → 能量耗散 | 若声称"无限精度" → **矛盾归档** |
| 因果性 | 前馈控制 → 必须先有 → 扰动预测 | 若无预测 → **矛盾归档** |
| 可测性 | 状态反馈 → 必须满足 → 状态可观测 | 若不可观 → **矛盾归档** |
| 稳定性 | 闭环系统 → 必须满足 → 特征值在单位圆内 | 若有极点外 → **矛盾归档** |

**违反约束的命题 → 标记为"矛盾" → 存入归档库（confidence=0.0）→ 不进入假设层 → 不复活。**

#### 2.2.5 实现效果与验证先行的策略（修正）

- **自动补全间接关系**：预期图谱有效关联量提升 3-5 倍
- **自动校验自洽性**：找出矛盾节点、错误映射
- **但：必须先验证收益**

**新增验证步骤：** 在 1000 节点图上跑传递性规则，量化"关联量提升"。
- 若提升 **≥20%**：继续 Phase 2（Bi-BFS）
- 若提升 **<20%**：停止。规则集覆盖不足，优先扩展规则集而非叠加复杂推理

### 2.3 逆向假设内核 (Hypothesis Generation Engine) — 修正

#### 2.3.1 核心机制：双向约束搜索 + 假设节点生成（限制用途）

**修正：仅用于知识断裂补全，不用于逻辑错误修正。**

```
Phase 1: 正向扩散 (Forward BFS)
  从起点A出发，基于规则向外推演所有可达节点
  记录路径：A → X → Y → ...
  **边界：depth ≤ 3，每层最多 100 个假设**

Phase 2: 逆向回溯 (Reverse BFS)
  从终点B出发，反向推演所有前置依赖节点
  记录路径：... → U → V → B
  **边界：depth ≤ 3，超时 30 秒自动返回部分结果**

Phase 3: 交汇匹配 (Intersection)
  当正向集合和逆向集合出现同类型节点（或公共节点）时
  自动拼接：A → X → C → V → B

Phase 4: 约束校验 (Validation)
  对生成的链路做全路径约束检查
  **若违反硬约束 → 不生成假设，直接跳过**
```

#### 2.3.2 假设节点生成策略（修正）

当正向和逆向集合无交集时，系统生成符合本体类型的假设中间节点：

**但新增限制：**
- 假设节点类型必须与已有本体分类一致（不能生成全新类型）
- 假设节点必须标注 `source='auto_gen'` 和 `generator_id`（规则 ID）
- 假设节点存入假设层前，**先检查矛盾归档库** → 若与已归档矛盾命题重复 → 不生成

#### 2.3.3 伪命题复活机制 → 改为矛盾归档（砍掉）

**原方案（已删除）：**
```
原始命题：「被动阻尼可实现无限精度的振动抑制」
约束校验：被能量守恒约束判定为伪命题
系统逆向推导：若要该命题成立，需补充「外部能量注入」的约束
最终存入假设层：在引入主动能量补偿的前提下，被动阻尼架构可实现高精度振动抑制
```

**修正方案：**
```
原始命题：「被动阻尼可实现无限精度的振动抑制」
约束校验：违反能量守恒
处理：标记矛盾 → 存入归档库（confidence=0.0）→ 不复活
原因：「被动阻尼 + 主动能量补偿」是一个新命题，不是旧命题的复活。复活会污染假设层。
```

## 4. 关键设计决策（修正版）

### 4.1 为什么先纯规则，后AI？（保留原方案，增加验证先行）

| 维度 | 纯规则 | AI增强 |
|------|--------|--------|
| 可解释性 | 100%可追溯 | 部分不可解释 |
| 确定性 | 100%确定 | 概率性 |
| 速度 | 毫秒级 | 秒级到分钟级 |
| 覆盖范围 | 本体框架内 | 可跨框架 |
| 维护成本 | 规则需维护 | 模型需训练 |

**策略：先搭骨架，后填血肉。但骨架必须验证稳固。**

**新增：骨架验证标准。** 纯规则推演的结果必须是 100% 可解释、可追溯的。但规则本身的覆盖度和推导收益必须被量化验证，否则骨架是空的。

### 4.2 假设层清理策略（修正：增加归档机制）

| 机制 | 说明 | 参数 | 修正 |
|------|------|------|------|
| TTL (存活时间) | 假设默认存活 90 天 | `HYP_DEFAULT_TTL = 90` | 到期后**归档到 `hypothesis_archive`**，不是删除 |
| 置信度阈值 | 低于 0.15 的假设删除 | `HYP_MIN_CONFIDENCE = 0.15` | 低于 0.15 **物理删除**（不再保留） |
| 每层最大假设 | 每层最多 100 个 | `HYP_MAX_PER_LAYER = 100` | **新增**：超限停止生成 |
| 同类型合并 | 相似度>0.9 合并 | `HYP_MERGE_SIMILARITY = 0.9` | **新增**：合并后 confidence 取 max |
| 内存预算 | 100MB 上限 | `HYP_MEMORY_BUDGET_MB = 100` | **新增**：超限时触发清理 cron |
| 验证失败 | 3 次失败则删除 | `HYP_MAX_FAILED_VALIDATIONS = 3` | 同原方案 |
| 人工标记 | 人工标记"不相关"则立即清理 | `HYP_MANUAL_FLAG = true` | 同原方案 |

**修正：清理时序定义。** 每天 03:00 跑 cron 清理。清理流程：
1. 检查 TTL 到期 → 归档到 `hypothesis_archive`
2. 检查 confidence < 0.15 → 物理删除（级联删除关联 edges）
3. 检查内存预算 → 若超出，按 confidence 升序清理直到低于预算

### 4.3 验证升级标准（保留原方案）

| 升级条件 | 权重 |
|----------|------|
| 有文献直接支撑 | 0.4 |
| 约束校验全部通过 | 0.3 |
| 多人/多系统独立验证 | 0.2 |
| 时间检验（存活超过180天） | 0.1 |
| **总分 ≥ 0.8** | **可升级** |

**新增：人工审核触发。** 若 confidence < 0.95，即使总分 ≥0.8，也需人工审核后方可升级。

## 6. 风险与边界（修正版）

### 6.1 已知风险

| 风险 | 描述 | 修正缓解措施 |
|------|------|-------------|
| 假设膨胀 | 无限生成假设导致图谱爆炸 | 每层 max 100 个 + 同类型合并 + 100MB 内存预算 |
| 规则维护 | 规则集需人工维护，覆盖不全 | 规则集独立版本化，与本体演化同步；优先扩展规则集而非叠加复杂推理 |
| 框架局限 | 纯规则跳不出已有认知框架 | 框架更新需外部输入或 AI 突破（Phase 3 解决） |
| 误判升级 | 假设过早升级为事实 | 严格验证标准（≥0.8）+ 人工审核（confidence<0.95 时） |
| 计算开销 | 双向搜索在大图上慢 | 限制 depth≤3；预计算索引；30 秒超时；SQLite 热点缓存 |
| **矛盾污染** | **新增：假设与已验证路径冲突** | **冲突仲裁显式标记，用户可见；已验证路径优先** |

### 6.2 纯逻辑推演的上限（保留原方案）

- **只能生成框架内的假设**：若本体没有"铁电材料"分类，纯规则永远推演不出相关假设
- **人类同样受此限制**：科学家的逻辑推演也跳不出已有认知框架
- **AI 用于突破边界**：大模型用于生成框架外的创新假设，规则用于验证和补全
